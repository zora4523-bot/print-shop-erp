# UI 审查：方法与全库审查结果（2026-09-29）

基线 `c3908b1c`。回答两个问题：怎样让 AI 稳定地做 UI 审查；按这套方法审一遍本仓库的结果。规范依据 [`docs/ui-规范.md`](../ui-规范.md)，条款号沿用。

## 一、怎样让 AI 做 UI 审查：六层流水线

核心判断：**纯靠 AI 读代码找不全 UI 问题**。「选择框偏了」「勾选框不对齐」是渲染后的几何事实，
代码里只看得到 `h-8` 和 `min-h-11`，看不到它们被放进了同一行；「标签切换卡顿」是时序事实，
代码只能给出风险。所以按「问题在哪一层能被确定地观察到」分层，每层用最便宜的手段：

| 层 | 手段 | 能确定抓到的 | 本仓库现状 |
|---|---|---|---|
| L0 规范可执行 | `docs/ui-规范.md` 条款号 | 给每条发现一个裁决依据；没有条款的记「规范缺口」 | 已有，缺对齐 / 页面外壳 / 命名条款 |
| L1 静态门禁 | eslint / `ui-tokens` / `ui-copy` | 调色板字面量、裸色、私有金额格式、deep import、禁词 | 已有，零命中 |
| L2 AI 代码审查 | 按维度并行子代理 + 统一输出格式（`文件:行号`、条款、证据、严重度、可否门禁化） | 组件多实现、按钮层级、语义色误用、外壳偏离、切换机制风险 | **本次新增** |
| L3 运行时 DOM 探针 | Playwright 逐路由 × 视口 × 明暗，页内脚本量几何与计算样式 | 同行控件高度/底边差、勾选框与文字偏移、样式指纹普查（找稀有样式）、多主按钮、标题层级、axe、溢出、CLS | 已有 `ui-gates.ts`（溢出/触控/axe），**本次新增几何与普查** |
| L4 AI 视觉审查 | 同族页面截图并排，多模态比对 | 页面级布局不一致、信息架构、视觉层级 | **本次新增** |
| L5 交互时序 | 生产构建上逐个切换点点击，量「点击→选中态」「点击→内容稳定」、长任务、CLS、滚动跳动、标签条是否重挂载 | 标签切换卡顿、点了没反应、闪烁 | **本次新增** |
| L6 裁决与回流 | 逐条核实 → 去重 → 定级；已确认的**类别**转成门禁 | 防止同类问题复发 | 每轮审查的最后一步 |

关键纪律（来自本仓库既往教训）：
- 每条发现必须复核到 `文件:行号` 或截图坐标；探针结果先人工看一眼再定性（本次首轮探针就有两类误报：`sr-only` 文字被当成勾选框标签、隐藏的 `input[type=file]` 被当成控件，已修正）。
- 时序只在生产构建上测；开发模式的 React 与按需编译会把数字放大数倍。
- 不在开发库改账号：本次把开发库复制到一次性隔离库 `erp_e2e_uireview_20260929`，只在副本里写入 E2E 夹具账号，全程只读浏览。
- 审查结论只写「风险」或「实测值」，不编毫秒数。

## 六、根因（修这些比逐页修更值）

1. **表单原子件规格不统一**：圆角/内距/焦点圈/错误态/只读态各一套 → 17 份 selectClass、手写 textarea、只读底色各写各的。
2. **缺原子件**：分段导航（链接版）、RadioGroup/ToggleGroup、Field（标签+必填+帮助+错误）、筛选栏、`LinkPendingHint`。
3. **缺页面壳**：PageHeader 没有 `back / status / scope` 槽，于是长出 RuleCenterPageHeader 和 11 个手写 h1；DetailPageShell / FormPageShell（UI-L02/L03）仍未落地。
4. **Button 没有「选中」变体、危险性不是一等参数** → 各处用 className 覆写颜色。
5. **Dialog 原语在 44px 兜底之外**。
6. **规范缺条款**：控件对齐、勾选框写法、按钮顺序、内容宽度、命名同源、选中态、z-index/浮层阴影刻度。

## 七、把结论变成门禁（下一轮就不用再靠人眼）

| 优先 | 门禁 | 判据 |
|---|---|---|
| 1 | ConfirmActionDialog 契约测试 | `confirmText` 以「取消/删除/放弃/移除」开头 → 必须 `danger` 且 `cancelLabel` ≠「取消」 |
| 1 | 面包屑路由单测 | 遍历 `app/**/page.tsx`，不得出现「页面」；可点击祖先必须有 page 或 redirect |
