- 任务：取消独立「下发生产」，把系统校验并入提交、修改与实际履约事务。实施范围和不变量见 [实施计划](./2026-10-03-production-entry-plan.md)。

- 普通厂内任务直接安排生产师傅；寄样自动待发货，不创建厂内任务；外协创建外协工单，无厂内任务的单自动准备。纯包装继续原报工计件，不更改历史工资。

- 无 schema、已应用迁移、依赖或构建配置变更。旧公开下发 action 和批量枚举保留明确拒绝旧请求；内部工序激活、重做调用、历史回执消费方继续保留。

## Design QA（代理自查，非真实用户测试）

按 UI 规范顺序检查；受影响布局沿用项目 Design System，不做额外视觉重设计。

1. 视觉层级：实屏核对排单页的工单/工序、师傅、核对/发布主动作；寄样显示发货，无生产安排；主动作发货优先。最终生产构建的 320 暗色核对页、1920 明色结果页截图已复核：主动作明确，无重叠。
2. 排版留白：九视口生产页面与列表/工具栏组件；长中文和长英文工单名称、批量、错误原因无 body 横向溢出。状态文案缩短后 1024px 看板九项可容纳，测试不再强制制造横滚。
3. 色彩对比：明暗主题的 axe、语义 token 门禁；错误/成功/禁用原因含文字，保留共享 Button/Input/Notice 焦点样式。
4. 组件一致性：安排入口使用 Link 与共享 buttonVariants，复用现有确认、反馈、列表和卡片；未新增共享设计组件。检查详情、列表、批量、工作台、销售状态消费方。
5. 交互反馈：实际覆盖选择、核对、发布、pending 防重复、成功链接、失败保留选中值及请求键、草稿恢复、改版整批拒绝、无可用师傅原因、暂停/恢复相关事务。键盘实屏发现核对后失焦，已修复并补回归；在最终生产构建的 IAB 实际执行 Enter→核对标题→Tab 发布→Tab 返回修改→Space，焦点回到 SELECT，console error 为空。
6. 动效：组件测试在 normal 与 reduced motion 下切换核对/返回并失败恢复；九视口截图门禁在 reduced motion 下等待真实动画稳定；不新增装饰动效。
7. 响应式：实际九视口为 320×568、375×667、390×844、393×852、430×932、768×1024、1024×768、1280×800、1920×1080；明暗全检。触控目标、局部滚动、长内容和确认层按现有门禁验证。
8. 功能质量：真实登录/建单/核价/安排/师傅报工/金额调整/发货/外协以及失败恢复；浏览器记录 pageerror/console error，不吞异常。Next 服务端在部分主动导航时仍记录既有 destination-stream 提前关闭，浏览器业务断言无对应运行时错误；不宣称服务器日志完全无警告。
9. 可访问性：axe；键盘选择进入排单、Tab/Shift+Tab/Enter/Space、Escape 关闭对话框与焦点返回；新增核对标题/结果区域及返回选择框的焦点回归；视觉用例包含 200% CSS zoom 和 320px 重排。焦点修复的最终真实框架九视口 45 项复验通过。
10. 原创性：无新增外部资产、模板或参考页面；本次只调整已确认业务入口和反馈，沿用现有 ERP 组件。

## 交付边界

本任务为开发修复与本地提交，不代表已推送、合并或生产部署。未来部署须执行 [部署指南](../部署指南.md) 的存量 dry-run 与明确 ID 修复，保留异常单并在修复事实的业务写入中自动准备；不得通过恢复下发按钮绕过校验。生产目标环境 smoke、真实通知/durable worker、生产旧单修复尚未在本任务执行。

## 已知低风险项（Claude 第四轮，无阻塞项）

- 极少数旧 CONFIRMED 工单的当前工序与保存方案冲突时，附带自动准备会使销售修改、变更关闭整体回滚，并显示领域提示。保留拒绝不一致写入，先核对原生产记录；没有自动猜测或覆盖工序。
- 部分旧待处理单的联系方式/报价缺失在发布事务才整批拦截；详情页已有完整就绪原因。列表与排单页的提示可进一步提前，但不会放行错误数据。
- 资料齐全、需派工的旧待处理单仍按存储状态计入“待完善”，主操作可以是“安排生产”。只影响存量信号标签。

- 最终复核补充观察项：上线后检查 `/orders` 的 EXPLAIN 与延迟、统计信息维护，不增加事务超时；保留原打样分支“不再是 DRAFT”的较宽断言（寄样另有 PACKING 精确断言）。
