# 功能模块交互可发现性审查

审查日期：2026-09-27。代码基线：`349d754e`，分支 `codex/design-removal`。本轮为测试与审查，业务实现未修改；下述建议均待实现。审查前工作区只有两份既有、未跟踪的 09-21 首次使用审查文档，本任务不纳入它们。

确认 7 项交互问题：4 项 P2、3 项 P3。既有报工冲正缺口、已保存分货的移除限制单独记录，不计入这 7 项。P2 表示会阻断纠正、丢失录入或妨碍常规业务操作；P3 表示文案与入口引导问题。

## 方法与边界

- 从 93 个 `app/**/page.tsx` 建立路由清单，按管理员、外部销售、工人角色检查菜单、页面入口及对应 Server Action / 领域消费方。
- 使用 Playwright CLI 独立浏览器会话访问页面，记录可访问性树、真实表单操作与截图。用户在 `localhost:3000/orders/new` 的浏览器页没有被导航或操作。
- 所有写入均在本机可丢弃数据库 `erp_e2e_discoverability_1790512246530`，测试服务为 `127.0.0.1:3100`。通知/CDR 使用 mock，后台任务 inline；不能据此声称真实企业微信、OSS 或生产 worker 已验收。
- 核对“创建—修改—撤回/停用”路径，不要求对历史账单、已结算工资、发货事实提供物理删除。直接输入 URL 只用于验证功能存在，不能证明普通用户能从菜单找到它。
- 路由遍历、具体操作验证、既有 E2E 分开记录；页面能打开不等于所有业务状态均通过。

## 确认的问题

### UI-01 · P2 · 仓库与库位只有创建，无法纠正名称或停用

管理员打开“仓库/库位”，展开“仓库与库位设置”。实测创建“交互审查仓库-误录”及“交互审查库位-误录”成功后，卡片只有名称、编码、“启用”标记，没有修改、停用或移除入口。新库位立即进入调拨下拉选项，即使未产生库存也无法从业务界面纠正或停止使用。

这属于**操作能力缺失**，不只是按钮不明显。[列表渲染](../../app/(admin)/owner/warehouses/page.tsx) 第 298–338 行仅渲染状态；[表单](../../components/business/warehouse/WarehouseForms.tsx) 只绑定两种创建动作；[服务端动作](../../actions/owner-warehouses.ts) 与 [仓库领域服务](../../lib/warehouse.ts) 也只提供创建路径。`listActiveWarehouseLocationOptions` 被库存、采购等页面消费，持续展示误建且启用的库位。

建议：补齐改名与停用/恢复，保留历史引用；默认库位、现有库存和未完成单据的约束由服务端检查。不要以直接删除库存历史解决。验收应从新建错名开始，完成纠正、停用后选择器移除、恢复后可选的闭环。

证据：本地 `output/playwright/discoverability/warehouse-created.txt`、`warehouse-created.png`。

### UI-02 · P2 · BOM 维护缺少常规入口，供应商维护在小屏入口断开

管理员主导航的字典区域只有“物料”“仓库/库位”。“产品结构 / BOM 分类”提供分类和产品资料入口，但没有 BOM 用料维护链接；工单“物料用量估算”未配置时也没有前往维护的入口。直接访问 `/owner/boms` 可以打开列表、新建和停用页面，且工单详情实际调用 `estimateMaterialUsageForOrderItems`，因此不是已经废弃的空路由。

供应商的情形较轻但同源：采购页只有“新建供应商”；按此入口进入的新建页，页头和表单底部都返回采购，不提供管理已有供应商的链接。375px 的父级面包屑隐藏，主菜单也没有“客户/供应商”，普通用户难以找到改名、停用已有供应商的位置。宽屏父级面包屑可能提供绕行，不能表述为所有尺寸绝对不可达。

代码证据：[模块注册表](../../lib/navigation/admin-modules.ts) 第 239–262 行、[规则中心入口](../../lib/navigation/rule-center.ts)、[工单用料估算](../../components/business/bom/OrderMaterialUsageEstimate.tsx)、[供应商新建返回逻辑](../../app/(admin)/owner/parties/new/page.tsx) 第 33–58 行。

建议：给有权限的管理员提供明确的“用料清单”和“供应商管理”入口，并从未配置用料、采购选择供应商处给上下文链接。验收须从工作台点击到达，不以直接访问 URL 代替。

证据：`admin-routes-*.txt` 的完整链接清单、`navigation-mobile.txt`、`supplier-mobile.png`、`_owner_boms.yml`。

### UI-03 · P2 · 采购与 BOM 内的新建资料跳转会丢失当前录入

已复现三条路径：

1. 采购填数量 `123`、单位成本 `2.5`、备注 → “新建物料” → 浏览器返回：三个字段全部为空。
2. 同样填写采购 → “新建供应商” → 创建成功并自动返回：新供应商已选中，但数量、成本和备注全部为空。
3. BOM 填名称及两行用量 `11`、`22` → 删除第一行，剩余用量正确保留 `22` → “新建物料” → 浏览器返回：BOM 名称及剩余用量为空。

这是**流程中断及输入恢复缺失**。内嵌入口鼓励用户在录入中补基础资料，却没有保留调用页面草稿；物料创建页的“返回列表”还指向物料列表，丢失来源上下文。

代码证据：[采购表单](../../components/business/purchase/PurchaseOrderForm.tsx) 第 33、56–64、93–102 行，[BOM 表单](../../components/business/bom/BomForm.tsx) 第 239–247 行，[供应商创建返回](../../actions/owner-parties.ts) 第 54–57 行仅传回供应商 ID。`PendingLink` 仅在提交中阻止导航，不提供未保存输入保护。

建议：在当前流程内补资料，或为来源表单保存按用户隔离的草稿并传回新建对象；回填后仍保留全部已填项。采购、BOM、供应商、物料创建的跳转链需一起验收。

证据：`purchase-material-return.txt`、`purchase-supplier-return.txt`、`bom-remove-and-return.txt`、`purchase-filled.png`、`purchase-supplier-return.png`。

### UI-07 · P2 · 未来工价发布后缺少撤销计划，立即纠正也被阻断

在独立测试师傅账号中真实复现：新建个人工价草稿，将局部工价设为 `0.1234`、指定 `2030-01-01 08:00` 生效，保存、复核、发布成功。展开“待生效”版本只有费率和说明，没有取消计划入口。再新建一版，选择“使用统一工价”“立即生效”，完成保存和发布复核后被拒绝：“生效时间须晚于该账号上一版工价”。未来错误计划仍保留，不能通过业务 UI 取消，也不能立即发布新价绕过。

这属于**计划操作恢复能力缺失**。不是要求覆盖历史工资；被测试的版本尚未生效，测试师傅没有任何报工。草稿编辑区同样没有“放弃草稿”，但主要影响是已发布未来计划阻断其前的纠正。

代码证据：[统一/个人共用工价表单](../../components/business/salary/PieceworkPriceBookForm.tsx) 第 50–62 行只给已发布版本只读展示；[个人发布服务](../../lib/salary/personal-piecework-admin.ts) 第 92–95 行要求晚于上一版；[统一发布服务](../../lib/salary/piecework-price-book-admin.ts) 第 548–555 行有同样时间守卫；两个 action 只分派 create/save/publish。个人价已浏览器复现，统一价的相同缺口为代码核对，未在统一账本重复发布未来版本。

建议：补齐未生效计划的取消或替换流程，保留版本和审计记录，恢复正确的生效区间；不要简单移除时间守卫或修改已结算工资。验收覆盖立即纠正、撤销未来计划、已有报工不回算、重复请求和并发发布。

证据：`personal-future.txt`、`personal-recovery-blocked.txt`、`personal-future.png`、`personal-recovery-blocked.png`。

### UI-04 · P3 · 多个新建页面面包屑误显示“创建工单”

在新建采购、账号、物料、BOM、供应商、纸张、工艺、分类和产品资料页复现。页面标题正确，但面包屑当前页显示“创建工单”；小屏只露出末级时尤其误导。

[AdminBreadcrumb](../../components/business/admin/AdminBreadcrumb.tsx) 第 89–105 行按最后一个路径段从模块表取标签，`new` 命中 `/orders/new` 后优先于通用“新建”及页面标题，导致不同模块互相串名。

建议：按完整路径解析上下文；没有专用标签时使用当前模块的新建名称。验收至少覆盖采购、账号、BOM 与工单的新建页，确认工单原标签保持正确。

证据：`_owner_accounts_new.yml`、`_owner_purchases_new.yml` 等，以及 `supplier-mobile.png`。

### UI-05 · P3 · 外协列表空状态没有说明从哪里发起外协

从侧栏“外协”进入空列表，只看到“暂无外协单”，没有新建入口或“到工单选择外协”的引导。创建功能存在于符合条件的工单详情，需先知道另一条操作路径。

代码证据：[外协列表](../../app/(admin)/foreman/outsource/page.tsx) 第 23–36 行；[工单详情](../../app/(admin)/orders/[id]/page.tsx) 内的 `canCreateOutsource` 及 `/foreman/outsource/new?orderId=...` 链接证明创建消费者仍存在。不能把此问题描述成“系统不能创建外协”。

建议：列表空态和页头提供“从工单创建外协”入口，仍由工单状态及权限守卫决定是否允许创建。

证据：`_foreman_outsource.yml`；外协全链现有 E2E 单独记录于测试结果。

### UI-06 · P3 · 工资规则入口说明与实际页面矛盾

规则中心“员工薪酬规则”卡片写“工序计件工价不在这里配置”，但其链接进入 `/owner/rules/employee-pay`，首个区域正是“计件工价”，支持新建调价草稿。下方又有一个“维护计件工价”指向同一个 URL。功能可以到达，但说明误导用户绕行。

代码证据：[规则中心](../../app/(admin)/owner/rules/page.tsx) 第 37–40 行及末尾独立计件入口；[实际页面](../../components/business/rules/salary/EmployeePayRulesPage.tsx) 第 22 行渲染 `PieceworkPriceBookForm`。

建议：统一入口说明，明确此页包含计件工价与其他薪酬规则，保持金额、版本、发布复核不变。

证据：`_owner_rules.yml`、`_owner_rules_employee-pay.yml`。

## 已知能力缺口与有意限制

- **报工数量纠错缺口**：工人可以“提交问题”，管理员可以回复“已解决”或驳回；回复明确不会改报工数量和工资。375px 实际进入有数据的“我的报工明细”，页面同样提示“提交后由管理员核对，不直接更改报工或工资”（`worker-report-detail.txt`）。[现行决策](../../DECISIONS.md) 的 2026-09-19“冲正 = 作废原报工”已明确应用层没有冲正入口，只能由技术人员处理。这是已有缺口，不能把“有异议表单”当作业务纠错闭环。后续应设计受授权的追加冲正，保留原报工及结算约束，不给历史记录加直接删除。
- **已保存分货地址不能移除/合并**：建单草稿可以移除地址，保存后的增加地址是单向拆分；编辑仅更改收件字段。2026-09-12 的现行决策明确“不删除地址、历史收费或价格修订”。本轮不判作回归；若要支持未发货分货反悔，需要独立设计分货守恒、逐票收费、包装与版本重算，不能只加关闭图标。
- **历史档案只读**、物料单位创建后不可变、已发货不能整单取消、已发布价格不可直接覆盖，均有现行业务约束。未列为交互缺陷。
