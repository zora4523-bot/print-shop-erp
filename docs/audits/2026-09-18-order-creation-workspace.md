# 新建工单分层与批量工作区验收

日期：2026-09-18。任务起点：`c8bfc5cb`，开始时工作区干净。本次为本地开发修改，未推送或部署生产。

## 交付范围

- 顶部“增加工单”：每张独立地址、工单号、费用及状态，最多十张，逐张核对和创建。
- 文件区“增加设计款”：继承当前材料、工艺及规格，文件独立选择。
- 材料区“增加规格”：共享所属设计的文件、材料和工艺，数量、包装和费用按规格明细独立处理。
- 管理员和外部销售共用分组交互，继续使用各自的服务端权限与收费入口；保留寄样、打样、管理员人工收费和多地址发货。
- 修复管理员切换材料/规格后旧产品事实与新选择混用导致的报价失败。
- 批量切换保留编辑内容和已选择文件；创建结果立即记录，失败继续已有工单，刷新后不重复创建。已保存工单可进入详情继续处理。

## 数据与计价边界

新增 `OrderItem.designGroupKey` 可空字段；历史明细保持空值并逐条独立处理。完整迁移链在独立 fresh 数据库通过，共 157 个迁移；本地开发库和隔离测试库已应用前向迁移，无 reset、无历史回填。生产未修改。

设计分组不合并报价阶梯、不减免版费；每个规格保留独立明细、生产与结算关系。同一设计的材料、工艺和稿件版本由创建 schema 再校验。批量复用原创建、报价、上传、提交 Action 和每单幂等标识，没有新增批量授权旁路。

## 使用限制

- 批量为逐张核对后创建，不是一次提交所有工单。
- 浏览器刷新不能恢复尚未上传的 File 对象，需要重新选择文件；批量页内切换可保留。
- 文件通过既有上传接口关联到各规格明细，本轮验证覆盖文件选择、共享、隔离和重试状态；未执行生产 OSS 上传或真实企业微信通知。
- 生产发布时先应用新增迁移并生成 Prisma Client，再切换应用版本；本地验证不能替代生产发布前的完整门禁与 smoke。
