## 四、视觉回归应该怎么做

现状：`tests/visual/ui-gates.ts` 在真实页面上断言溢出、触控、axe 与控件几何（PR 两视口、main 六视口），组件交互契约在 Vitest Browser Mode；像素基线只有打印视图（darwin）。这套门禁擅长「坏了」（溢出、遮挡、对比度），不擅长「难看、难读」——本次 L-1 / L-2 / L-3 / U-1 全部是后者，所以都漏了。建议按成本从低到高分四层，**先把问题类别变成确定性几何规则，像素基线只留给少数「外观就是契约」的地方**：

1. **几何规则（零基线、零维护，优先）**。规则跑在已有的 `expectViewportGate` 里，所有已覆盖路由自动受益。
   - 本次已加 `number-split`：带千分位 / 小数点或 ≤8 位的独立数字不得跨行；工单号、电话、长地址、代码块不算。探针在全部管理端侧栏路由 × 6 视口上修后零命中。
   - 下一批候选（都能写成 20–40 行的页内函数，并按 `ui-gates-geometry.browser.spec.tsx` 的方式配正反例）：
     - `label-wrap`：卡片 / 徽章 / 按钮里 ≤8 字的短标签折行（L-2）。
     - `orphan-wrap`：`flex-wrap` 控件行最后一行只剩 1 个控件、上一行 ≥3 个（L-3）。
     - `empty-heading`：标题后紧跟同级或更高级标题、中间无内容（D-12 的「生产记录」）。
     - `disclosure-state`：`<summary>` 内既无 `data-slot=disclosure-indicator` 也无展开 / 收起文字（D-1）。
2. **组件级像素基线（Vitest Browser Mode）**：只给外观即契约的复合组件——工单列表行（7 种行动作 × 375 / 1280 × 明暗）、决定看板、详情「当前待办」卡。直接用现有夹具（`AdminOrderListLayout.browser.spec.tsx` 的 `row()` / `referenceRows()`），不依赖数据库；图片数量控制在 30 张以内。
3. **页面级像素基线：最多 2–3 张**（列表首屏、详情首屏 @1280），用固定夹具库 + 冻结时间，遮罩日期 / 编号 / 缩略图，沿用 `print-darwin.yml` 的「按路径触发」模式，不进 PR 必跑门禁，避免噪音。
4. **发布前 AI 视觉巡检**（本次做法）：隔离库副本 + 脚本化整页分段截图 + 可见文本导出 + 探针 JSON，人工 / AI 对照上一轮复核层级、冗长、重复。它用来发现门禁表达不了的问题，发现后回到第 1 层补规则。

纪律（沿用仓库既有规则）：新增或更新任何像素基线，先把渲染图给业主看、得到明确同意再提交，commit message 写 `[visual-regression]`（CLAUDE.md §8.4）；只在隔离库上跑，不碰开发库；时序只在生产构建上量。第 2、3 层是否纳入 CI 需业主拍板（CLAUDE.md §8.2 的「PR 两视口、main 六视口」口径）。
