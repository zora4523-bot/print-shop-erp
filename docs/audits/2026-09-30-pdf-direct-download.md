# 单张 PDF 简化与稳定性验收

日期：2026-09-30；基线 `80cc7086`，分支 `codex/order-leave-recovery`。任务开始时工作树干净。本轮为用户要求的 PDF 使用体验与稳定性优化，不包含生产部署或数据库迁移。

## 实现

- 单张下载默认直接在 Web 的 Chromium 子进程生成，不创建队列任务、不依赖 HEAVY 心跳或产物存储。相同账号、角色、完整内容和 base URL 合并请求，最多缓存五分钟。
- 每 Web 进程最多四个不同请求在途、一个串行渲染池、45 秒生成等待预算，完成缓存限制为 32 MiB/16 份；大于缓存容量的 PDF 仅返回。每任务独立 BrowserContext，浏览器按次数、寿命、空闲及失败回收。取消后的浏览器关闭完成前不启动下一浏览器。
- 请求断开只退出自己的等待，不取消其他订阅者；失败或超时结果不缓存。所有下载保留最终身份、资源和内容复核。未升版的内容变更同样拒绝返回旧内容。
- `PDF_ORDER_MODE=queued` 保留原队列回退；带 jobId 的旧链接继续按原授权查询，内容标识过时或缺失则要求重新生成。批量 PDF、CDR 和其他任务保持现有队列行为，不删除历史记录或迁移。
- 详情页、详情组件默认操作和批量操作结果中的打印链接改用已有 `/print/orders/:id?autoprint=1`。准备完成后才调用打印；PDF 下载及 `view=inline` API 保留。不会自动登记“已打印”。

## 实测与发布边界

最终 direct E2E 的同一四页文件：首次 HTTP 响应约 3.4 秒（包含开发编译），复用下载约 47 ms；字节完全相同。这是本地开发环境的一次测量，不是生产性能承诺。原始日志和测试渲染图位于仓库外 `/tmp/erp-pdf-direct/`。

生产需在发布前评估 Web 和 Chromium 子进程的总内存/CPU，以及多个 Web 副本的总并发；进程内缓存不是全局缓存，也不与历史队列任务做跨进程去重。保留 `PDF_ORDER_MODE=queued` 回退开关。未执行生产构建、生产容量测试或发布，不将当前开发验收表述为生产已验收。

内嵌浏览器的原生 PDF 插件没有被修改；普通打印入口通过 HTML 打印避免依赖该插件。若手动访问 `view=inline`，仍由浏览器自身 PDF 查看能力决定展示效果。
