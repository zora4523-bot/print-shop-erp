## 已确认问题

### P2：搜索索引预检仍要求已退役的唯一索引

- 触发：管理员打开 `/owner/pigsty`，工单搜索预检显示缺少 `ProductionTask_orderItemId_craftId_key`。
- 证据：完整 188 条迁移后的隔离库实际复现；`to_regclass` 查询确认旧索引不存在、替代索引 `ProductionTask_orderItemId_craftId_idx` 存在。
- 原因：`20260807170000_order_list_filters_and_exports` 将旧索引登记为必需；`20260826180000_split_production_tasks` 删除该唯一索引并建立普通组合索引，未同步 `app_ops.search_surface_candidate`。`lib/search-readiness.ts` 直接读取数据库视图，所以提示会持续存在。
- 影响：管理员可能将正常的索引替换误判为部署故障，甚至尝试恢复不再适用的唯一约束。当前页面只展示预检，不会自行修改索引。
- 修复方案：新增前向迁移，同步预检登记与当前实际查询；不得修改旧迁移或重建旧唯一索引。增加 fresh database 与升级数据库的预检回归，验证实际搜索查询使用的结构。
- 状态：新增 `20261008190000_search_task_index_readiness`，只替换工单搜索登记中的旧索引项。原查询仍通过 `OrderItem.tasks` 过滤生产任务，替代索引保留此访问路径；未更改查询、索引约束或历史迁移。

### P2：采购收货确认没有显示实际物料名称

- 触发：创建采购单，填写本次收货数量，点击「核对并确认收货过账」。
- 实际结果：页面物料为「120g珠光艳闪」，确认层却显示「物料：当前采购明细物料」。数量、库位和单位成本有具体值，物料核对项没有提供识别信息。
- 证据：`purchase-confirm.log`、`output/playwright/purchase-confirm.png`；`components/business/purchase/PurchaseReceiptForm.tsx` 的 `purchaseReceiptImpactItems` 固定返回该占位词，现有单测也固定断言它。
- 影响：入库前无法通过确认层核对目标物料，不符合 UI 规范 §7 要求确认层展示本次实际变更。
- 修复方案：从采购详情传入实际物料名称及必要规格，让确认预览显示同一采购明细的身份；保留服务端授权、剩余数量、单位成本、版本和幂等校验。更新确认层单测和真实采购页面回归，检查取消后输入保留及实际入库数量。
- 本次操作结果：取消确认后数量 40 保留；再次确认实际形成 40 张收货记录，采购状态变为部分收货，剩余 60 张。问题属于确认信息不足，未观察到错误库存写入。
- 状态：采购详情将经过同一显示格式化的物料名称传入确认组件，预览展示实际名称。服务端写入逻辑未改；单测与现有浏览器组件测试覆盖传值及确认显示。

### P2：采购确认按钮在文字放大时超出手机视口

- 触发：采购详情设为 320×568，将根字号放大至 200%。
- 证据：实际 `innerWidth=320`、根 `scrollWidth=400`；确认按钮 294px 宽、父容器 108px 宽，默认不换行。采购表格在独立滚动区域中，未造成根元素溢出。
- 修复：仅给采购确认按钮设置最大宽度、文字换行、自适应高度及垂直内边距，保留最小触控高度。真实页面复验根宽度为 320px，确认操作和文本均保留。
- 热更新编译期间的一次刷新出现新旧按钮 class 不一致的 hydration 提示；待编译完成、重新加载并确认最终 class 后复验。不将该次采集当作最终验收。

### 环境限制：历史财务资料缺失

- 实际点击「打开历史财务看板」后，新窗口返回 HTTP 500，服务端明确报 `Historical finance directory unavailable`。
- 本任务环境未配置 `HISTORICAL_FINANCE_DIR`，未挂载历史资料。授权检查后文件读取失败；没有伪造财务数据或把该页面记为通过。配置真实资料后仍需重验。
