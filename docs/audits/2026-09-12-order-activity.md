# 工单动态布局与历史分页

## 先行规则

在 UI 规范记录工单动态的信息层级、分页和权限要求后实施。参考 Apple HIG 的布局层级、对齐、分组与渐进展开原则，沿用本项目颜色与控件。只改管理员详情日志展示与只读查询，原始日志、制版写入、金额计算与历史快照不变。

## 实现

- 管理员详情不再同时展示模型内的“动态/变更历史”摘要和完整区块；使用单一“工单动态”区块，保留完整修改申请记录、审核备注及处理入口。其他未提供完整日志区块的调用方继续保留原有摘要。
- 日期分组，标题、时间/人员、关键变化、操作说明分层，详情按需展开。时间使用上海时区；同名角色不重复。不使用删除线或整块白底。
- 独立展示适配器精确比较原始金额，补齐提交报价、结算金额名称，过滤内部报价修订标识。未变化标量不展示；未知历史值明确提示，不泄漏原始对象，不按格式化文本判等。制版事件保留写入时的操作说明，未记录的完整制版快照不反推。
- 独立管理员读取按时间和 ID 倒序，每页 20 条，使用第 21 条作为下一页标记；每次加载重新授权。客户端保留已加载记录、防重入、去重、失败重试和最终页焦点恢复。
- 查询权限和响应契约同步于 API.md。

## 验证范围

覆盖展示适配器、权限拒绝、不可访问工单、同时间游标边界、页面单一日志入口与审批记录保留；浏览器覆盖七视口、明暗主题、触控、溢出、axe、展开、加载、去重、失败重试和焦点。测试不写入用户工单。

## 验证结果

- 目标单测/集成测试 62 项通过；最终全量 Vitest 5,908 项通过、55 项跳过。
- 浏览器测试 52 项通过（详情、待办和动态），包含七视口 × 明暗、触控、axe 与分页交互。首次检查发现按钮高度和最终页焦点问题，修复后全部通过；未修改截图基线。
- TypeScript、UI 文案/令牌门禁通过；ESLint 无错误，保留两条既有导航警告。检查排除既存构建和测试输出目录。
- 开发实页读取验证：该工单显示七条事件，管理员姓名不重复，未变化金额已过滤，变更详情可展开，旧日志与摘要不再重复。未执行工单写操作，未发布到生产。
