# 工单详情信息层级与功能保留审查

日期：2026-09-28。基线：`81a682dc`，分支 `codex/design-removal`。本轮是审查与优化方案，不实施页面改版。已跟踪文件开始时干净；两份 09-21 first-use 未跟踪文档不属于本轮。

依据：[UI 规范](../ui-规范.md) §1.2、§2.2、§3、§4.3、§7，以及“管理员工单详情布局”“工单详情操作集中”“工单动态”；结合 [09-12 布局](2026-09-12-order-detail-layout.md)、[操作集中](2026-09-12-order-detail-actions.md)、[背景修复](2026-09-12-order-detail-background.md) 和 [DECISIONS](../../DECISIONS.md)。

## 结论与证据范围

页面主要问题是识别信息隐藏、查看与修改职责混杂、操作优先级不清、同一资料重复铺陈；不是把字号和间距统一就能解决。另确认一处状态分支下的错误定位，以及价格来源/事件文案映射遗漏。建议保留现有权限、组件行为与业务契约，先修明确缺陷，再按职责重组展示。

- 对用户标记的“已下发、单款、单地址”工单只读检查；独立临时页实测“查看设计文件”“更正物流费用”“生产记录”定位，均正确打开/聚焦对应目标。后两者滚动完成后距视口顶部 160px，没有被后台标题遮挡。
- 独立页 1280×720，默认文档高度约 6840px；费用标题约 y=838、配送约 y=3079、生产约 y=3562、成本补录约 y=5091。即使只有一款，也要跨多屏才能浏览生产与记录。数值仅是本样本测量，不代表所有工单。
- 对本单最新价格修订做限定字段的本地只读查询：`revision=2 / source=ORDER_READY_FOR_PRODUCTION / status=AUTO_CONFIRMED`，用于确认“未识别来源”不是数据源为空。未读取或记录连接凭据，未修改工单。
- 不同状态、销售隔离与已移除入口以代码、项目决策和目标测试核对；未拿用户工单实际下发、改价、发货、结算或取消。

## 审查发现

| ID / 优先级 | 问题、影响及证据 | 建议 |
|---|---|---|
| OD-01 / P2 | **“前往结算”定位错误。** `SHIPPED` 且价格不待核对时，链接指向 `#detail-delivery-records`；该区只有地址登记和阻塞提示，真正 `settleFactoryOrderAction` 的确认按钮在右侧决策组件。用户点击后被带离实际结算入口。代码链确认，当前样本尚未发货，未实页触发此状态。 | 保留一个真实结算入口；如仍需定位，指向结算决策块并聚焦。已发货分支与逐地址发货后自动结算分支分别验收。 |
| OD-02 / P2 | **折叠操作不可发现，工单号也被隐藏。** 页头“工单信息”默认收起，里面仅放工单号/复制/版本。共享 summary 隐藏原生 marker，本页多数栏目既无箭头也无“展开/收起”文字，看起来像普通标题。真实 DOM 已确认，内层款式资料自己补了展开文字，外层却没有。 | 工单号及复制直接放页头次行；其余折叠标题提供方向图标与状态文案，原生键盘语义保留。优先做详情页局部补充，不贸然修改全站共享组件默认行为。 |
| OD-03 / P2 | **已知事实被展示为未知。** 价格来源缺少 `ORDER_READY_FOR_PRODUCTION` 映射，真实页面显示“未识别来源”。动态使用 `actionLabel`，缺少下发、创建打印任务等现行工作流事件映射；另一个详情模型却已有这些标签，当前动态没有使用它。 | 将已知来源和事件映射补入实际消费的共享注册位置，核对写入方清单并测试。未知历史值继续使用安全兜底，不能一律猜成“自动报价”。 |
| OD-04 / P2 | **同一当前金额的状态表达不一致。** 样本主合计显示“199.80 估”，下面“确认金额·当前”却直接 `formatMoney`，没有估价状态；“对客收费明细”又把创建时估算的行称为“实际收费”。这不是已证实的金额计算错误，但会使用户误认为物流已最终确认。 | 当前金额统一消费金额展示事实；历史报价/确认/结算按各阶段事实显示，不能把当前估价标志套给全部历史阶段。物流行按事实称“估算收费/已确认收费”，不更改价格、终价或流水。 |
| OD-05 / P3 | **右侧操作同权重、阻塞信息重复。** “当前待办 → 工单处理 → 工单操作”层级偏多，暂停、确认打印与六七个通用入口争抢注意力；发货禁用原因同时进入按钮文字和下方说明。已打印状态与打印相关动作也分开。 | 当前要做的动作置顶，暂停等异常操作次要；打印/下载/预览归一组，维护和外协归一组，发货禁用原因在该操作旁只解释一次。打印任务状态与操作就近，但仍区分打开打印内容、加入待打印和确认已打印。 |
| OD-06 / P3 | **同一款式在摘要卡和“设计文件与完整工艺资料”重复展示。** 用户需要在两份同名款式中来回找数量、工艺、设计文件与费用；规格名称与实尺等识别信息也占用重复层级。 | 每款一个容器：设计图、款名、数量、关键工艺常显；完整工艺和文件作为该款展开区，沿用现有文件组件与目标 ID。不能把展开区整体删除，它还承载稿件版本、特殊工艺、历史计价与设计文件权限。 |
| OD-07 / P3 | **主内容默认铺开多组维护表单，记录阅读被操作区打断。** 物流确认、附加费用/制版新增、计薪次数、成本新增与查看资料在一条长流中；成本和售后又放在“基本信息、成本与重做”的混合分类，页内导航未覆盖。 | 管理栏目与已有记录仍默认可读；进入“调整费用/新增成本”等明确入口后展开对应编辑器，必须保持未提交状态及深链可达。成本归费用，售后独立可定位，基础资料归页头/概要。此项需同步细化现有“管理栏目默认展开”规范，不能擅自把整页改成隐藏模块的 Tab。 |
| OD-08 / P3 | **标题语义和空态过多。** 当前待办为普通 div，随后直接 h3/h4；生产 h2、生产折叠标题、计件/异议多个 h2 并列。样本无报工时连续显示无工资、无报工问题、无异议、无流水，加上底部重复基础/费用/收货信息，视觉层级趋平。 | 固定页面 h1 → 业务区 h2 → 子块 h3。重复摘要引用同一展示来源；无业务记录时按 UI §7 合并空态或省略可选区，有异常、历史事实或实际入口时保留。不能隐藏缺 BOM 等需要处理的真实阻塞。 |

补充：页内导航是锚点导航，**本来就不应伪装成只渲染一个面板的 Tab**。目前定位工作正常；长页可增加当前位置标识，但它属于优化建议，并非“导航失效”。

工单号 / 复制 · 生产版本 · 外部销售 · 交期 · 款数/数量
页内定位：款式资料 / 费用 / 配送 / 生产 / 售后（有内容或可操作时）/ 操作记录

## 功能保留与移除审查

| 功能 | 当前事实 | 改版边界 |
|---|---|---|
| 草稿提交、编辑、急单、取消 | 按状态及待审申请控制，真实 action 再授权 | 保留原组件/参数与服务端闸口，不因按钮挪动扩大适用状态 |
| 下发、暂停、恢复、审批变更/取消 | 右侧决策组件；单张下发与打印已分离 | 保留确认内容、旧版本阻断、并发/未知结果反馈及纸单回收要求 |
| 打印、PDF、网页预览、打印任务/确认打印 | 行为并不相同 | 可以分组，不可当作重复功能删掉；批量下发+打印不受影响 |
| 工单号复制、版本、旧纸单失效提示 | 仍存在，部分藏于折叠区 | 移到可见概要，不删版本或复制能力 |
| 设计图大图、文件列表、草稿上传/删除 | 完整资料里的 DesignUploadPanel；只有草稿可编辑 | 每款只挂一次；CDR 受控下载继续走权限入口，不将私有 URL 暴露给销售 |
| 全部收费编辑、历史材料核价、物流确认、附加费用/制版明细增改移除 | 相关组件仍挂载，并非已删除 | 按职责调整入口，保留原复核、原因、金额精度、价格修订和审计；历史已移除制版行仍能查看 |
| 到付调整、分货与包装、逐地址运单/面单、发货、结算 | 现行页面有对应表单/动作；前往结算链接存在 OD-01 | 修定位，不删写入动作；已发货地址、最后一票自动结算及财务状态均复测 |
| 生产进度、计薪次数、用料估算、工资与两类异议 | 生产区及概要；待报工时部分进度摘要不显示 | 不把“暂无”全部删除后连异常入口一起丢弃；有记录与无记录分别覆盖 |
| 工厂成本新增/调整、重做关联/发起 | 下方业务区；重做仅原单非重做且 SHIPPED/SETTLED/FINISHED | 给明确区名和定位，不认为当前已下发样本没有重做按钮就是缺功能 |
| 事件时间线、修改申请、分页 | 新 OrderActivity 默认展示；旧修改日志不再重复挂载 | 保留原日志与详细审批、加载更早/失败重试/分页权限；只删除重复视图不删数据 |
| 销售详情 | 路由先分流到 SalesOrderDetailView，独立安全 DTO | 管理员改版不能将成本、工资、内部审计和权限带到销售端；共享组件变更要跑销售回归 |

**已按项目决策移除、不得借本轮恢复的功能：**

- 客户名称/简称录入、展示、筛选与相应详情字段：2026-09-27 决策要求统一按归属外部销售识别；底层历史兼容和审计不跟随展示删除。
- 独立工序流转单打印及逐工序二维码：2026-09-08 决策已移除；普通工单 PDF、主码及工序表保留。
- 详情版组/模具组 ID、专版计价组及废弃制版占位：09-12 UI 规范明确移除展示，底层仍有计价/历史消费，不能删 schema 或迁移。
- 客服角色、清废/厨师工种及相关新业务入口：按 09-24 决策移除；不把退休功能当详情遗漏补回。
- 任一地址已发货后的取消：现行规则明确禁止。已下发后没有“直接取消”同样由取消申请/裁决流程约束，不是随意隐藏。

**本次拟去掉的仅是重复呈现和多余容器。** 每处删/合并必须记录旧位置、唯一新入口、渲染条件、调用 action 和回归项。搬移表单不得重复挂载或因切换而重置未保存内容。当前没有依据删除任何领域服务、公开 API、schema、已应用迁移或历史记录。

## 实施顺序与验收

1. **修明确缺陷**：OD-01 定位；OD-03 映射；OD-04 金额状态。先补旧行为会失败的断言，再修复。价格来源仅改展示，不回填本单价格数据。
2. **整理识别与操作区**：页头工单号/复制、折叠提示、待办主次、打印分组；六标准视口及 2205px、明暗、长工单名与按钮文案验证。
3. **整理内容归属**：每款资料合并，费用/成本分层，配送、生产、售后与审计归位。先列完整组件清单，迁移前后逐一核对；修订 UI 规范对应段落，再实施，避免与“默认展开/锚点导航”约束冲突。
4. **回归清单**：草稿、待核价、待下发、已下发、暂停、待审批、多地址部分发货、已发货、已结算、已取消、寄样/打样/免费重做；有无文件、多规格/多款式、估价/确认价/缺价、打印旧版本、有无报工及异议、历史已移除收费明细。
5. **技术边界**：保持 `#pricing-review`、`#fulfillment-pricing`、`#shipment-registration`、`#detail-design-item-*` 等深链可达，能展开祖先并聚焦；键盘/触控/axe、44px、overflow、滚动遮挡与表单唯一挂载均要测。共享组件若修改，补全部消费方回归。
6. **真实写入验收**：只在独立可丢弃库跑管理端动作与销售越权失败；布局变更不修改真实工单。普通 UI 按 CONTRIBUTING 做目标测试、lint/typecheck、视觉门禁；如触及金额/状态机，升级为全量领域、数据库和相关 E2E 验证，不用本轮只读结果替代。
