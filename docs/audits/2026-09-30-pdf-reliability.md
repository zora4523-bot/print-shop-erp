# PDF 生成与恢复补强验收

日期：2026-09-30。任务基线：`c5ba0823ec2e2c2770ee2a21668e5b0567fb3d50`，分支 `codex/order-leave-recovery`。修改前工作树干净；本次不发布、不迁移数据库、不修改打印模板或视觉基线。

## 原因与修改边界

本地 Web 使用 durable 模式，但没有近期 HEAVY worker 心跳，PDF 在渲染前返回 503。该现象不能证明生产 Chromium 或图稿有故障；生产部署配置仍沿用 PostgreSQL 队列、HEAVY worker、Puppeteer/Chromium 的服务端 HTML 转 PDF。

- `pnpm dev` 统一管理 Web、LIGHT、HEAVY，检查端口、真实 PDF 运行时和本次启动心跳；开发通知固定模拟。保留 `dev:web` 给外部进程管理场景。
- HEAVY 在心跳和消费任务之前检查内嵌中文字体、实际 PDF 生成和私有产物存储往返。`check:pdf`、部署 smoke 使用同一探针。
- PDF 等待页就地查询已授权任务；失败提供重试、网页打印、返回工单和按权限显示的运维入口。保留任务绑定、最终会话/资源/版本复核和私有缓存规则。
- HEAVY 内串行复用 Chromium，每任务独立 BrowserContext，限制次数、寿命、空闲、排队及超时，失败和停机回收；`PDF_BROWSER_REUSE=0` 可回退。

## 性能证据与限制

本地简单 HTML 基线：逐次启动三次总耗时 2,625/1,228/1,153 ms，复用后 696/654/656 ms。真实 HEAVY 测试两次 browserMs 为 1,158/5 ms，renderMs 为 2,355/2,267 ms；第二次日志确认 reused=true。两个测试工单内容不同，不能据此推断整体吞吐提升百分比。日志中的 workerRssBytes 只统计 Node，不代表 Chromium 子进程峰值。

原故障页面在 Codex 内嵌浏览器收到 PDF 后，其内置查看器仍显示灰色异常图标；因此仅确认该入口生成成功，未把内嵌 PDF 预览记录为通过。独立浏览器测试的文件下载、PDF 解析及 Poppler 渲染已通过。

本轮没有执行生产 build、生产部署或真实 OSS 存储验收，也不宣称完成发布门禁。生产升级仍需按部署指南验证共享存储（OSS 探针需要其私有前缀的读写删除权限）、实际图稿、多页工单及目标环境 smoke。

本次本机原始日志及测试产物位于仓库外 `/tmp/erp-pdf-reliability/`，不作为永久仓库附件。测试使用隔离数据库 `erp_e2e_pdf_reliability_20260930`；没有覆盖生产数据。
