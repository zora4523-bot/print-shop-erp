# 工单生产空记录提示审查

## 规则先行

在 UI 规范“文案与确认”加入“无记录提示准入”：提示必须有明确读者、决策用途和唯一归属；设计标题只承担识别与折叠导航，不展示生产后台记录是否生成；可选字段无记录时不渲染，不以同义占位填充网格。实际阻塞及恢复入口必须保留。

## Review 与处理

| 位置 | 判断 | 处理 |
|---|---|---|
| 设计资料标题的生产完成数、历史任务完成数 | 与标题职责不符 | 移除，保留名称、数量和工艺数量 |
| 标题“尚未生成生产工序” | 缺少任务记录不等于异常 | 移除 |
| 款式的生产/历史记录及无计件步骤空占位 | 重复、无操作价值 | 仅实际有记录时渲染，真实记录保留 |
| 基本信息“生产工序：尚未生成” | 再次重复空记录 | 无记录时省略 |
| 发货前置条件、待核价金额、重复成本防范 | 影响操作或财务判断 | 保留 |
| 完整列表无计件工资/包装组空态 | 说明该列表确实为空 | 保留一处，不扩散到标题 |

仅移除 JSX 展示与其唯一使用的 TaskStatus 导入；生产查询、状态、快照、原始数据和权限均不改动。折叠控件不在本次明确指定的文案清理范围。

## 防回归

在 `scripts/ui-copy/policy.json` 对工单页面禁止三条已拒绝的“未生成/无独立工序/无步骤”文案；以有记录、无记录两类页面用例验证标题始终不含生产进度、真实历史仍展示、空历史不再渲染。门禁不是全部语义判断，新增文案评审仍须回答读者、用途与重复性三项问题。

验证：页面及文案检查器 73 项测试通过，详情/待办浏览器 35 项通过（包含七视口与明暗主题）；TypeScript、UI 文案与令牌门禁通过。ESLint 无错误、两条既有导航警告。本次没有业务状态或数据库修改，未执行生产下发、打印或发货。原测试进程启动停滞后仅重启该进程，重跑通过。
