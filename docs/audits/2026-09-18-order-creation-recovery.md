# 批量建单失败恢复修复

日期：2026-09-18。基线 `64c9a350`，开始时工作区干净；本报告随修复提交保存。范围为此前 Grok 对抗审查确认的 1 项 P1 和 2 项 P2，不包含发布或生产数据操作。

## 已修复

1. **P1，响应丢失后修改内容重试**：同一个提交标识原来可返回旧工单成功结果，让新地址或数量被误认为已保存。现在创建事务保存首次请求指纹，普通命中与唯一键冲突恢复均比较原始内容；不一致明确报出原工单号，要求到详情核对。相同内容重试仍只生成一张工单。
2. **P2，批量列表满额后无法继续**：恢复出来的已保存、未完成上传或提交工单，原来无法满足“全部完成”的下一批条件。现在全部已有工单号即可开始下一批，后续在原工单详情继续；有未保存工单时不能清空批次。保留上限 10 张，满额禁用新增并提示，标签自适应换行。
3. **P2，样品表单依赖 sessionStorage**：寄样、打样的表单、材料工艺、归属信息及已保存状态纳入批量内存快照。浏览器存储报错时，页内切换仍保留内容。

没有调整费用算法、放宽服务端权限或回填历史价格。复用现有 CREATE 审计 JSON，无新迁移。旧工单无首次指纹时要求人工核对，不静默放行。
