# 管理员与外部销售建单输入稳定性复审

基线：`0aec3ab4`，分支 `codex/gongdanceshi`。开始时跟踪文件与暂存区干净；既有未跟踪截图保留，不纳入本次提交。

## 发现与修复

- 管理员与外部销售的 `/orders/new` 共用 `OrderForm` / `OrderFormB`。上次将异步报价错误汇总移到字段之后的修复覆盖两种角色，本次保留显式提交失败和错误链接的定位能力。
- 外部销售 393px 真实页面复现：清空数量时，字段错误插入文档流，下方每包数量输入框从 546px 移到 568px，偏移 22px。先保留失败日志，再用相同位置断言验证修复。
- 常用文本输入下方预留反馈空间，覆盖工单名称、数量、每包数量、设计文件、主地址和联系人，以及管理端归属/交期、包装补充说明、备注、追加地址与分配数量。包数与包装错误共用反馈位置，优先显示错误。
- 反馈使用最小高度，不截断长错误；没有错误时不产生空的警报或无障碍朗读。联系人组件的预留空间为可选参数，其他编辑页面保持原有默认表现。
- 只替换错误反馈的呈现，未移除校验或改变提交、授权、计价、历史价格和数据库规则。每包上限 12、错误阻断及报价刷新仍由原调用链处理。

## 审查结果

- 两端均检查数量清空/恢复、包装超限/恢复、复制当前款、切换款式、删除款式、地址解析、手动修改收货人和电话、追加地址、报价返回期间输入焦点及位置。
- 手动修改主地址联系人后，继续编辑地址不会丢失已修改的姓名和电话，未改动联系人状态和地址解析契约。
- 销售工作台复用 `OrderItemQuantityField`，同步获得数量反馈预留区域；补跑该消费方的完整浏览器组件检查，未发现布局或交互回归。
- 开启反面烫金、切换工艺、增加款式或地址引起的主动展开属于用户触发的布局变化，保留现有行为。
- 扩展测试一度使用 `End` 键，触发 macOS 浏览器滚动；几何记录显示文档中的字段位置不变，变化来自 `scrollY`。改为点击输入和逐字追加，并针对实际数量 1260 的报价响应等待，不用旧响应或未分配数量的地址证明报价完成。
