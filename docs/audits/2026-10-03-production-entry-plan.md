# 生产入口简化实施计划

## 用户确认的范围

用户要求规划并修复重复的“下发生产”操作。系统校验在提交、修改、排单及发货事务中自动执行；管理员只处理实际缺失的信息。厂内生产通过安排师傅发布任务；寄样直接处理发货；外协继续通过外协工单管理。

开始基线为 `1fce730d`，工作区与暂存区均干净。本任务包含领域服务、管理端入口、必要测试、现行业务说明及验收记录，不修改已应用迁移，不写生产数据。生产发布不属于本次实施步骤。

## 功能不变量

- 金额与已保存报价、权限、版本、待审批变更、历史生产事实与工资约束继续生效。
- 厂内任务仅由排单建立指定负责人；已有报工的旧单保留原流程，不自动猜测负责人或改写工资。
- 寄样不生成厂内工序、不选择师傅；合格提交自动进入待发货。
- 无可排厂内任务的工单自动启用外协或原包装处理流程，保留现有打包报工工资行为，不因本任务强制转为单人生产。
- 单人生产的打包规则继续沿用已确认设计；不改变工价、历史账本、结算与实体打印行为。
- 只读页面不推动状态；旧工单兼容在明确的业务写事务中处理。

## 实施批次

1. 提取生产入口判定与无需派工的自动准备逻辑，复用实际工序计划，区分寄样、厂内任务、无厂内任务及资料缺失。
2. 建单、核价、修改完成后自动准备无需派工的工单；排单接纳可自动校验的待确认工单，并保持原请求版本与整批事务保护。旧寄样发货及旧外协写入补充自动准备兼容。
3. 普通单使用安排生产入口；取消公开单张及批量下发操作的入口，服务端拒绝通过旧下发操作绕过排单。内部重做、排单仍复用激活工序的领域方法。
4. 列表、详情、工作台、销售状态及文档使用一致文案；零目标与资料错误给出准确提示，批量入口不隐式漏掉选中的工单。
5. 验证后运行真实 Claude Code 对抗复审，修复范围内问题，最终评分须大于 9 分。通过必要验证后创建本地提交。

## 验收

真实数据库覆盖：普通提交与排单、待确认准备、寄样提交到发货、无厂内任务/外协、历史无报工与有报工、免费重做、版本冲突、待审批、打印幂等、批量回滚及工资不变。执行全量 Vitest、覆盖率、类型、lint、架构及相关浏览器/E2E；按 UI 规范依序完成十项 Design QA，九视口与明暗主题记录实际结果。未执行检查不计为通过。
