# 包装类型实施记录

## 业务范围

管理员、客服及外部销售共享建单包装控件，默认入袋，可切换不包装、红卡盒子 230g、触感盒子 250g。价格、数量和边界的现行规则见 [加工费计费规则](./加工费计费规则.md#4-包装包装组级)。新规则不改写已保存工单或已发布历史价目；复制、恢复草稿保留包装选择，后续实际报价读取当前版本。

## 实现依据

包装组是原系统保存组成、数量、收费和打包生产来源的事实源。本次扩展包装模式和按盒计费单位，沿用报价、创建、提交、修改申请、履约重计价、生产准备和打印链路。前端不自行写金额，也不以每包数量为空代表不包装。

`actualBagCount` / `unitsPerBag` 是兼容列名，装盒时分别为盒数/每盒数量；不包装保留正值组成作款式归属，但数量及收费为零。红卡最多 10 个、触感最多 8 个，混装按组成合计检查。装盒按配送地址分别进位；改单与生产计划使用同一计算器。

空盒价与装盒加工费独立存为已发布加工费规则，运行时不读取初始化常量。现有价格中心“包装与快递”分区新增三行，可通过草稿保存、审阅和发布修改。缺任一规则阻止自动装盒报价。所有金额为 Decimal；合并单价乘盒数后按包装组四舍五入，保留四位单价和两位小计。

不包装不生成打包生产工序；装盒使用原打包工序及新 `PER_BOX` 工资单位，不套用 `PER_BAG`。客户 0.50 元装盒加工费不等于员工工资；没有正式按盒工价时，报工返回未发布工价，不能生成错误工资。现有 v1 工价初始化命令只负责原三个工序费率，本任务没有擅自设置装盒工资。

盒子克重不等于实物重量。装盒运费在管理员确认实际包裹重量或人工核价前保持待核；顺丰到付保持既有规则。此限制不会把红包加工费或装盒已知金额变成 0。

## 配置应用

先正常备份数据库，应用三个增量迁移并生成客户端：

```bash
pnpm exec prisma migrate deploy
pnpm exec prisma generate
```

然后使用目标环境启用的管理员 **账号 ID** 安装本次确认的三项价格：

```bash
# 默认只读预览
node --conditions=react-server --import tsx scripts/install-box-packaging-rules.ts --actor=<管理员账号ID>
# 校验草稿与已发布规则，发布新增包装价格
node --conditions=react-server --import tsx scripts/install-box-packaging-rules.ts --actor=<管理员账号ID> --apply
```

命令复用没有其他调价的加工费草稿，或从当前版复制草稿。事务内锁定价格写入、核对基版和更新时间、比较非装盒规则及计价常量，避免夹带其他调价；通过全表校验、建单投影和原发布流程后才生效。已安装则返回 `already-installed`。中途发布失败保留可审查草稿，不覆盖其他修改，不直接修改已生效版本。

发布后重启开发/应用与 worker，使其加载新 Prisma 枚举。新装环境也需要该配置步骤，迁移本身不自动改价格。生产上线仍按 [部署指南](./部署指南.md) 执行，不以本地验证替代生产发布。
