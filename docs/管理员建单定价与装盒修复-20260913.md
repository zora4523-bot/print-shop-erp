# 管理员建单定价与装盒修复

## 现行行为

管理员直接建单及代外部销售建单均可在款式中选择“人工定价”，填写本款加工费总额和定价原因；包装组可填写每袋/每盒单价，显式填 0 表示免收该项。不包装始终为 0，不接受包装改价。默认仍使用自动计价。加工费、包装费、版费和运费分别核算，整单合计由服务端生成。

款式价格按整款金额保存，采用固定费存储，避免将总价除以数量产生单价舍入差。包装单价最多四位小数，按包装组乘数量后取两位小数。保存和提交保留管理员确认快照、原因及原自动报价参考；异步报价不会覆盖人工金额。款式数量、工艺、纸张、尺寸、包装组成或分货条件变化后，需重新确认对应人工价格。恢复管理员本地草稿保留上述输入；销售草稿和销售提交载荷均剔除它们，服务端同时拒绝越权字段和停用管理员。

管理员可填写纸张克重和自定义尺寸；这些生产事实继续接受原有校验。人工定价不能替代缺失的烫金颜色、图稿、收货资料，也不能绕过包装容量、归属、版本和投产校验。未知版费及装盒运费继续按原核价流程确认。报价失败显示具体业务原因，并提供重新报价入口。

## 拆址修复

新增地址先依据完整分货矩阵，调用与建单和投产一致的包装数量计算器：每址分别向上取整，再汇总盒数。沿用已保存的包装单价；不读取最新价格本替换旧单约定价格。事务内同步包装组数量、小计、包装费、加工费及总额，追加价格修订并要求重新核价。管理员议定盒价的包装组分货改变盒数后保留原定价原因和确认记录，但因盒数已变而不再视为已确认：核价页按原单价列为待确认项，草稿或驳回单提交时也不按价目簿改价，整单进入待管理员确认。

例如触感盒 101 个、每盒 8 个：单址 13 盒，29.90 元；拆成 3 个和 98 个两址后为 1 + 13 = 14 盒，32.20 元，增加 2.30 元。预览明确显示盒数、包装费及总额差异。

已物化生产工序且拆址改变盒数时，本入口阻止保存并指向工单修改申请；不能直接改掉已经下发的包装工序或历史报工来源。不改变盒数的分货仍遵守原地址状态和价格规则。

装盒地址没有实物重量时，原地址和新地址的运费均保留 `PENDING_AMOUNT`、金额 `null`；界面显示“待核价”。已人工确认的原地址金额保留，管理员仍可显式核定新地址费用，顺丰到付规则保持。红包纸张克重不能代替含盒子和外包装的包裹重量。

## 员工按盒工价发布

客户装盒加工费 0.50 元/盒与员工工资独立，不能直接套用。发布器支持三个基础费率（局部烫金/下、专版/个、入袋/袋）及可选第四项 `PACKING/PER_BOX`。按“工序 + 单位”匹配规则，防止入袋和装盒互相覆盖。

新版本接续当前已发布版本；同一事务中关闭旧版本的开放有效期并发布新版本。新迁移 `20260914000000_piecework_successor_publication` 仅允许有对应后继版本的向前有效期衔接，保留发布证据、费率、既有报工和反冲记录的不可变约束。已用报工时间不能被排除；不能追溯发布。同一 manifest 可幂等重放，不同内容不能覆盖已发布版。

操作步骤：

1. 备份并执行正常增量迁移。已发布 v1 可从 [v2 模板](../config/piecework-price-books/v2-box.template.json) 复制正式配置；版本号设为当前版本 + 1。若只有未发布的 v1 草稿，也可在 v1 manifest 加入第四条规则后发布。保留原三个经确认费率，填入正式员工装盒费率、未来生效时间、来源和发布说明。模板中的 `null` 不可发布。
2. `pnpm piecework:publish --manifest=<正式配置文件>`：只读校验，取得 `draftUpdatedAt`。创建后继版本时该时间对应当前已发布版，作为并发条件。
3. `pnpm piecework:publish --manifest=<正式配置文件> --apply --actor=<活跃管理员用户名> --expected-draft-updated-at=<预览时间>`：执行发布，记录原文件、manifest、规则集摘要和审计。
4. 生效后按盒报工使用独立费率；未配置/未生效仍提示缺工价。旧 `piecework:publish-v1` 命令兼容保留，调用同一发布服务。

本次没有为日常开发库或生产库擅自确定员工装盒工资，也没有发布工资版本。隔离回归使用的 0.20 元/盒仅用于验证，并随数据库事务回滚。
