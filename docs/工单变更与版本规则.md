# 工单变更、取消与版本规则

计费规则见《加工费计费规则.md》。本文管**提交之后**的一切：改、取消、驳回、版本、销售端展示。

---

## 0. 一条总原则

**CONFIRMED 之后的修改不是编辑，是「变更申请」对象 + 工单版本递增。**

三个理由，缺一不可：
1. `confirmedFee` 已锁定，改数量必然改钱，要出新版本快照
2. 车间里有一张已打印的纸质工单在流转，数据库改了纸不会变
3. 客户扯皮时要有「谁在几点申请了什么、工厂怎么裁的」的留痕

---

## 1. 变更能力矩阵

| 状态 | 直接改 | 走变更申请 | 取消 |
|---|---|---|---|
| DRAFT | 全部字段 | — | 直接取消 |
| PENDING_FACTORY | 撤回 → 改 → 重新提交（全部字段） | — | 直接取消，零费用 |
| REJECTED | 同上（已退回销售，等同未确认） | — | 直接取消 |
| CONFIRMED | 仅收货信息、备注 | 数量 · 款式 · 工艺 · 纸张 · 规格 · 交期 | 申请取消，工厂裁决 |
| RELEASED / FOILING / PACKING | 收货信息（**贴唛前**） | 同上 | 申请取消，**已产部分照结** |
| SHIPPED | — | — | 不可，转售后流程 |
| SETTLED / CANCELLED | — | — | — |

轻变更（收货信息、备注）直改后**通知工厂**，不走审批；打包工序有「贴唛前核对收货信息」步骤兜底。

## 2. ChangeRequest 对象

```
ChangeRequest {
  id, woNo,
  type:        MODIFY | CANCEL,
  modifyKind:  QTY | DUE_DATE | ADDRESS | CRAFT_PAPER | OTHER,   // MODIFY 时必填
  detail:      string,          // 销售填写的具体说明
  status:      PENDING → APPROVED | DENIED | WITHDRAWN,
  denyReason:  string,          // DENIED 时工厂必填
  producedQty: int,             // 生产中取消时工厂回填
  settleFee:   decimal,         // 已产结算金额，系统按 producedQty 走计费引擎给参考值，工厂可改并留痕
  woVersionAfter: int,          // APPROVED 后的新版本号
  requestedBy, requestedAt, decidedBy, decidedAt
}
```

**硬规则：**
- 一张工单同一时间只允许一个 `PENDING` 申请；申请期间销售端隐藏「申请修改 / 申请取消」入口
- `PENDING` 申请可由销售 `WITHDRAWN` 撤回
- `DENIED` 必附 `denyReason`，该单回到销售端「需处理」桶
- 影响生产的申请（QTY / CRAFT_PAPER / CANCEL）提交即通知工厂端置顶；是否停线由工厂决定，系统不自动改工单状态

## 3. 版本机制 —— 纸质工单的作废闭环

**没有版本号机制，数据库改了、纸没换，师傅照旧纸做，改了等于没改。**

```
WorkOrder.version   从 1 起
变更申请 APPROVED  → version + 1
                   → confirmedFee 按新参数重算，写入新版本快照
                   → 旧快照保留（费用历史以版本为键，不覆盖）
                   → 工厂端生成「重新打印」任务
```

**二维码闭环（在原二维码规范上追加）：**
- 短链改为 `/wo/{woNo}?v={version}`，打印哪一版就带哪一版的号
- 扫码页比对链接里的 v 与当前 version：
  - 一致 → 正常显示工单
  - 不一致 → **整页红色告警：「此工单已作废，当前版本 v2，请找最新打印件」**，不显示旧版内容
- PDF 页眉印 `v{n}`，与二维码互为备份（扫不了码肉眼也能比对）
- 下载入口（销售端抽屉 / 工厂端）**永远只给当前版本**，旧版 PDF 不可再获取

## 4. 生产中取消的结算

取消不是删除。流程：

```
销售提交 CANCEL 申请
→ 工厂核已产数量 producedQty
→ 系统按 producedQty 走计费引擎算参考结算价
   款级费用按已产数量；纸箱耗材按已产总量；快递费 = 0（未发）
→ 工厂确认或调整 settleFee（调整必须留痕）
→ 状态转 CANCELLED，settledFee 写入
```

`CANCELLED` 的单在对账里仍然出现（有 settledFee 就要收钱），不许从列表里消失。

## 5. 驳回 / 暂停原因枚举

原因是**有限集合 + 工厂备注**，不是自由文本。枚举决定销售端的行动作与跳转位置。

| code | 展示 | 销售端动作 | 跳转 |
|---|---|---|---|
| `PAPER_OUT` | 纸张库存不足 | 换纸张 | 该款纸张选择区 |
| `DESIGN_ERROR` | 设计图有误 | 重传设计图 | 该款文件区 |
| `PRICE_PENDING` | 待工厂核价 | —（等工厂） | — |

驳回记录 = `reasonCode + reasonNote + 涉及的款 fig[]`。带 fig 是为了跳转能精确落到出问题的那一款。

**不存在「分辨率不足」**这类原因——设计图只是工单上的对版预览，生产走 CDR 矢量文件。

## 6. 销售端状态映射

内部状态机 11 态是真值；销售端展示映射成 8 个词。**这张表是销售端 API 的一部分。**

| 内部状态 | 销售端展示 | 备注 |
|---|---|---|
| DRAFT | 草稿 | 动作：继续填写 |
| PENDING_FACTORY | 待工厂确认 | 含待核价款时叠加朱红「待工厂核价」 |
| REJECTED | 已驳回 | 原因枚举 + 备注直接展示在行内 |
| CONFIRMED | 已确认 | |
| ON_HOLD | 已暂停 | 原因同驳回处理 |
| RELEASED / FOILING / PACKING | **生产中** | 三态合一。给销售的是能答客户的进度，不是车间工序 |
| SHIPPED | 已发货 | 运单号行内可复制 |
| SETTLED | 已完成 | |
| CANCELLED | 已取消 | 有 settledFee 的仍进对账 |

## 7. 销售端工单列表规范

**每行字段：** 缩略图（首款设计图，多款角标）· 工单名 + 客户 · 工单号（点击复制）· 状态药丸 · 交货日期（剩 ≤3 天朱红字，超期白字红底）· 款数·总数量 · 工艺摘要一行 · 金额 · 驳回/暂停原因行 · 运单号（已发货，可复制）· 变更申请中角标 · 相对更新时间

**金额三态**，只显示当前有效的一段：
`¥1,924.00`（confirmedFee）／ `¥404.30 估`（quotedFee，带「估」角标）／ 朱红「待工厂核价」

**「需处理」= 已驳回 + 已暂停 + 待核价 + 申请被拒**，聚合成独立筛选页，且在任何排序下置顶，行整体泛红。

**每行默认动作 = 「再来一单」**（复制此单，图稿清空、CDR 保留）。例外：草稿→继续填写；需处理→原因枚举对应的动作。

**明细 = 右侧抽屉，URL 可寻址**（`#wo={woNo}`）。抽屉只读；「换纸张」「重传设计图」「撤回修改」一律跳编辑页并定位到问题款。**编辑永远不在抽屉里发生。**

**不展示：** 工艺全参数、内部工序细节、师傅信息、audit 明细、内部成本。
