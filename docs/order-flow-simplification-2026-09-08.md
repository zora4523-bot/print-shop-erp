# 工单流转审查与实施方案

## 已确认的问题

- 列表“确认”仅打开抽屉，抽屉还有确认弹窗，用户重复操作但没有增加必要业务事实。
- 外部销售自动核价之后刻意停在 PENDING_FACTORY，旧内部路径却物化生产任务；核价与下发的职责不一致。
- 确认时重套当前发布价格，与编辑页沿用已审核报价、原报价保留的规则不一致。
- “锁定终价”误导用户：履约运费和独立制版明细原本就支持后续更正，结算才形成财务终态。

## 实施范围

提交、人工核价和管理员编辑/修改审批完成后，在原授权事务内检查已保存费用与合计、人工核价状态、待审批申请及收货信息，条件满足自动进入 CONFIRMED（待下发生产）。自动准备不物化工序、不创建打印、不授权师傅提前报工。

旧待确认工单无需批量回写；管理员下发时使用同一准备校验，在同一事务内完成准备、生产物化和首次打印。资料或费用不足返回具体问题；批量逐单隔离，成功项可安全重试。页面读取不写数据库。

列表按钮标识查看/处理，正常单取消人工“确认并锁定金额”。生产下发与结算保留明确后果提示。原报价不因价格表更新而变化；后续款式和费用调整继续走已有版本、权限、并发校验。版费默认零，管理员可添加。已结算工单不能直接改原费用；本次不新增财务调整产品。

## 不变量和失败方式

- ADMIN 才能下发、核价和费用维护；销售提交仍限本人。
- Decimal 汇总；空值、待定收费和金额不一致不能自动通过。
- 原报价、历史价格版本、生产和工资记录不覆盖。
- 待审批申请阻断；生产版本、幂等打印请求和事务锁保持生效。
- 价格表变化不触发接单重报价；显式改款/费用更正继续校验预览版本。
- 不自动确认存量数据，不通过访问 GET 触发业务写入。

## 验证计划

领域边界测试、动作授权与批量失败隔离、全量 Vitest、类型与 lint；隔离数据库 E2E 覆盖自动准备、未下发不能报工、一次下发、重试及价格历史；相关管理端响应式和可访问性检查。结果以任务验证记录为准，不将计划等同于完成。

## 验证结果

- 在 HEAD 加本任务增量的独立工作树运行全量 Vitest：551 个文件通过，5725 项通过、43 项按既有条件跳过；后续测试命名和文案整理的定向回归 103 项通过。
- 同一工作树类型检查通过；lint 无错误，保留两项既有未使用变量警告。
- 隔离数据库 Chromium E2E 的四个场景均通过：保存后自动准备、旧待处理工单直接下发及错误合计阻断、详情核价失败回滚、抽屉核价失败回滚。详情与抽屉的失败流程均核对数据库金额、版本、价格历史和生产记录未变化。
- 决策面板、抽屉布局和编辑辅助面板的浏览器测试共 38 项通过；另在本地实际订单抽屉核对正常单仅提供下发入口，无“确认并锁定金额”。
- 开发环境冷编译曾使一次登录超时；原详情回归用例还依赖旧核价区域的标题和位置，已改为当前“待你处理”内的入口与表单。修正后复跑通过，未放宽业务断言。
