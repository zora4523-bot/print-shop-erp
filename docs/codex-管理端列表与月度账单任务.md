# Codex 任务：管理端工单列表 + 月度账单

## 任务性质

两段式：先输出 `PLAN-管理端列表与账单.md`（差距分析 + PR 切分 + 迁移方案），一次确认后自主执行。UI 与交互的唯一参照是原型 `工单列表-管理端.html`——其内 JS 是可运行的行为参考。真值文档：《工单变更与版本规则.md》《加工费计费规则.md》。

## 一、管理端工单列表 —— 锁定决策

**结构**
- 队列制：待办（待确认+待核价+变更申请+已暂停）· 待打印 · 生产中 · 已发货 · 已结算/取消 · 全部，页签带计数，决定类非零泛红
- 看板条：待确认 / 待核价 / 变更申请 / 已暂停 / 已逾期 / 今日待发 六个数字，点击进入对应视图
- 队列内**严格新单优先**（既有决策），逾期靠颜色不跳序；服务端分页、按字段独立筛选（销售 / 工艺线 / 客户点击即筛）、异步导出，三条既有决策全部保留
- 合计条常驻：当前筛选 N 单 · 总数量 · 金额合计（口径 settled ?? confirmed ?? quoted，待核价单另计单独标注）
- 搜索覆盖：单号 / 客户 / 名称 / **运单号**
- 星标为个人标记 + 仅星标筛选，**不改排序**

**行**
- 勾选框 · 星标 · 缩略图 · 单号+版本徽标 · 名称 · 客户(可点筛)·销售·工艺线·提交时间 · 状态(11 态原生) · 行内摘要 · 交期着色 · 款量+烫金/打包双进度条 · 费用当前段 · 状态对应动作
- **行内摘要承载决定所需信息**：待确认单显示预检结果（✓ 可确认 / ⚠ 缺项列表）；变更单显示申请原文；异常与停滞朱红前置

**裁决（抽屉内，编辑另页）**
- 工厂确认：预检未过 → 确认按钮停用；驳回必选枚举原因（PAPER_OUT / DESIGN_ERROR）+ 备注
- 人工核价：录入金额后确认才解锁，锁定核价数为 confirmedFee
- **价表版本差**：quotedFee 的价表版本 < 当前版时，确认卡必须显示两版本两金额——"确认时按当前版重算锁定"（规则文档既定语义的 UI 落地）
- 变更裁决：批准 MODIFY = version+1 + confirmedFee 重算 + 生成重打印任务；批准 CANCEL = 按报工核已产、settledFee 写入后转 CANCELLED；拒绝必填原因退回销售
- 录运单发货（PACKING→SHIPPED）、结算（SHIPPED→SETTLED，按 confirmedFee）
- 抽屉含费用三段并列（当前段高亮）、报工进度、操作动态日志（操作人+时间+动作，含系统事件如"生成重打印任务"）

**待打印队列**
- 成员 = 生产状态（RELEASED/FOILING/PACKING）且（未打印 或 版本升级 reprint）；这是版本作废闭环的最后一环，没有它旧纸换不掉
- 行动作与批量动作均可"标记已打印"，清 reprint 标记

**批量操作**
- 白名单：批量下发+打印（仅 CONFIRMED 且无挂起申请）/ 标记已打印 / 批量结算（仅 SHIPPED）/ 导出所选；状态不符自动跳过并报数
- **确认与驳回禁止批量**——每张必须过预检

## 二、报工规则（扫码端，本任务实现约束校验）

- **硬拦**：每道工序（烫金 / 打包）累计报工 ≤ 工单数量，超出当场拒绝写入。上限是工单数量，不是上游工序完成数
- 打包 > 烫金（两者均未超单量）**不拦，仅列表提示**——多为师傅漏报，补报后异常自动消失；异常一律实时推导，不落库不需人工销
- 列表兜底：若数据中出现报工>单量（拦截失效），朱红标"查数据"
- 停滞检测：下发后无人扫码认领超过阈值标停滞；**阈值 2 天，存 SystemSetting**，不写死

## 三、通知（企业微信）

事件五类，每类可按接收角色开关（配置存 SystemSetting）：
1. 新单提交（→工厂确认者）
2. 变更 / 取消申请提交（→工厂确认者）
3. 报工异常（打包>烫金 出现时 →老板）
4. 停滞满阈值（→老板）
5. 待确认积压超阈值（→老板，阈值同入配置）

推送只带单号+摘要+深链（`#wo={woNo}`），不带金额。发送失败不阻塞业务流程，记日志。

## 四、月度账单（新模块）

**收款主体 = 代理商 × 月，不挂在工单上**（代理商月结，既定）。

- 账单 = 该代理商当月全部产生 settledFee 的单（含生产中取消的 CANCELLED）聚合，金额 = Σ settledFee
- 归属规则：按 `settledAt` 所在月；迟到的结算落入结算发生月的账单，**不回改历史账单**
- 账单状态机：`DRAFT（月初自动生成上月）→ CONFIRMED（对账确认，此后成员单与金额锁定）→ PAID`
- 已入 CONFIRMED 账单的单，settledFee 不可再改；发现错单走**下月账单负项调整**，历史账单不动（与工单版本快照同一哲学：改错靠新记录，不靠改旧记录）
- 账单页：列表（代理商 × 月 · 状态 · 单数 · 金额）→ 明细（单清单，可跳工单抽屉）→ 导出 → 标记已收
- 工单侧联动：SETTLED 单显示所属账单月；管理列表加"未出账"可筛
- 待收款看板数字进管理端看板条

## 五、待拍板（每条附默认取值）

1. 账单是否支持部分收款——默认**不支持**，月结整付，PAID 一次到位
2. 待确认积压阈值——默认 **5 单**
3. 其余同规矩：附默认取值，能查文档查代码的不许上榜

## 六、硬约束

- 严格新单优先、服务端分页、独立筛选、异步导出四条既有决策不许推翻
- 抽屉只做裁决，编辑工单内容另页
- 费用三段快照语义不变；账单只读 settledFee，不触发任何重算
- 不修改既有测试让它变绿；新模块 additive migration
- 通知与账单相关配置全部进 SystemSetting，不写死
