## 二、定价的核心命题（不要在 UI 里弄丢）

> 当前价、调价草稿、计划生效版本必须始终可分。不得把草稿包装成已生效价。调价直接影响开单金额。

销售报价查询（推断页）**不得**出现草稿或待生效版本。工作台可以编草稿；发布中心才让草稿变成当前价。

金额仍由服务端算。UI 的 Δ / 涨幅只是展示，不能变成第二个计算器，不能引入浮点。

## 三、现状对照（批次五「观察」在代码里是否还在）

### 3.1 收费项目工作台 · `/owner/prices/external-sales/items`

组件：`ExternalSalesChargeWorkspace`（约 1000+ 行）

| 设计稿指摘 | 现状 | 首批要不要改 |
|---|---|---|
| 草稿条在页顶，一滚就消失 | `DraftStatusBar` 不是 sticky；只有右侧选中栏 `xl:sticky`（约 862 行） | **要。** 草稿条吸顶 |
| 右栏顶部复制左侧 10 个价格胶囊 | 需实现时对照右栏 header；设计要求右栏只保留「当前选中项目身份 + 阶梯表」 | **要。** 删重复胶囊 |
| 每行重复「500 个草稿单价（元/个）」 | `ExternalSalesPriceTierGroupEditor.tsx:464-467` 的 `Label` 仍带数量 + `inputLabel` | **要。** 列头写一次；行内输入不再重复整句 |
| 「计价单位」十行完全相同 | header 已有「计价」`dl`（388–403 行）；行内 `supportingColumnLabel` 在按个/按张/每万/每款时是常量 | **要。** 常量单位只留表头。**例外**：整批固定总价时该列是折合单价，**不能**上移 |
| 行高约 80px 装一个输入框 | 行 `p-4` + Label + Input 堆叠（432–437 行） | **要。** 桌面行高目标约 44px，Label 仅小屏显示 |
| 数字左对齐无法比价 | 数量已 `tabular-nums`；金额列未统一右对齐 | **要。** 金额/Δ 右对齐 + `tabular-nums` |
| 「状态」把启用开关和「未修改」混在一起 | 同一列既有启用，又用 `bg-warning/5` 表示已改（436 行） | **要。** 启用是开关列；差异走独立 Δ 列 |
| 缺 Δ 列 | 只有行背景，没有 `+¥0.03 / +5.8%` | **要。** 展示用 Decimal 字符串格式化，不算钱 |
| 批量调价 + 撤销 | 无 | **要。** 只改当前打开的这一组草稿档，撤销回到进入编辑时的值。整组保存语义不变（任一行失败整组不保存） |

### 3.2 阶梯编辑器 · 同一右栏

`ExternalSalesPriceTierGroupEditor` 已有：

- `expectedUpdatedAt` 并发戳
- 整组 `useActionState` 提交
- 按 `CustomerPriceCalculationType` 切换文案（`PRICING_PRESENTATIONS`）

不要重写保存协议。只改 DOM / className / 列结构。`visual-fixture` 必须跟工作台用**同一套**组件，改阶梯表就要同步 fixture。

### 3.3 发布中心 · `/owner/prices/external-sales/versions`

设计：按用途两栏（加工费 | 快递与打包耗材）、草稿/当前生效分色、发布前影响汇总（项目数、档数、涨幅区间、有无下调、生效时间）、校验三级（通过 / 注意 / 待办）。

发布是 **L3**：确认层必须列出影响范围，不是「确定要继续吗」。理由与生效时间若表单里已有字段，只改确认层 UI；**不要**为了 L3 去加新的 Prisma 字段。现有 action 没有的能力写进「缺口」而不是偷偷补服务端。

## 四、五态（契约 09，定价首批要覆盖的）

| 态 | 工作台 |
|---|---|
| Loading | 左列表骨架约 6 行；右栏「选择一个收费项目」 |
| Empty | 分「无收费项目 / 筛选无结果 / 无权限」；后两个视觉一致、文案不同 |
| Disabled | 「无草稿时只读」与「该项目不在当前草稿内」文案必须不同 |
| Pending | 保存整组时锁定；明示「任一行失败整组不保存」 |
| 冲突 | 已有 `expectedUpdatedAt`；冲突给差异，禁止静默覆盖 |

无权限 Empty 与「记录不存在」在全站规范里要求渲染结构一致（`EmptyState` 的 `no-access`）。定价首批若尚未落地五态组件库，先在本页用现有 `Empty` / 语义 token 对齐结构，不要为这一页单独发明第三套空态。

## 五、和全站 12 项清单的关系

定价首批**不是**执行清单 01–12 的替代。清单里真正会碰到定价页的：

| 清单 | 与定价 |
|---|---|
| 01 五态组件 | 能复用则复用；不为定价阻塞开工 |
| 03 禁用态中性灰 + 常驻原因 | 无草稿 / 不在草稿内 的只读态 |
| 04 红色收紧 | 定价页红色只留给校验错误、下调警告、破坏性发布 |
| 05 L3 | 发布价目 |
| 08 环境提示分色 | 若页上有 DEVELOPMENT / mock，不要和「价格待办」同色 |

01、02、06、07、09、10、11、12 是工单/侧栏/师傅端的活，**不要**夹在定价 PR 里。
