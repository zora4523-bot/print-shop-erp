# 发布整改开发任务（2026-09-10）

依据：[发布审查](audits/2026-09-10-release-readiness.md)。本清单是任务规格，不代表问题已修复或发布已获批准。不自动触发其他任务、PR 或部署。

## 执行规则

1. 先完成安全依赖与稳定的业务缺陷，再修复测试契约并补齐生产流程验证，最后冻结发布候选。
2. 每个任务记录负责人、开始 SHA、涉及文件、业务不变量、复现、验收、验证命令与实际输出。实现和必要测试为一个可审查提交；无关重构单独提交。
3. 状态统一：`待开发 → 开发中 → 待验证 → 已验收`；依赖缺失用 `待前置条件`，不得写已完成。只有通过对应验收才能进入已验收。
4. 遵守 [CONTRIBUTING.md](../CONTRIBUTING.md) 的权限、所有权、金额精度、历史快照、幂等与迁移规则，以及 [UI 文案规范](ui-规范.md)。测试应追随已确认的规则，不反向修改规则来消除失败。
5. 修改完成按项目技能仅提交当前任务，不夹带打印等其他工作；不得降低覆盖率、删除断言、无依据更新截图基线或编辑已应用迁移。

本轮建议先做 REL-01 与 REL-08，再做 REL-02/03/05/06；REL-09 与打印改版一起验收，REL-04/10 补门禁，最后完成 REL-07 的发布前置。

## REL-01 安全依赖升级

- 优先级：P1；状态：待开发；角色：基础设施/应用开发；关联：R01、R02。
- 范围：`package.json`、锁文件、Next/Auth 相关兼容改动与必要回归。保留 Prisma adapter 补丁。
- 复现：`pnpm audit --prod --json`；Next 16.2.4 命中 App Router Server Function DoS 公告。
- 不变量：登录、角色和资源归属权限不退化，历史金额/快照不变，不借升级迁移业务数据。
- 验收：对每个适用 high/critical 告警修补，或给出调用链、部署条件和正式风险处理记录；不得仅因为 Linux 不受 Windows 漏洞影响就忽略其余告警。固定版本，核对新安装版 Next 文档。
- 验证：冻结安装、Prisma generate、typecheck、lint、全量含 PostgreSQL 单测与覆盖率、build、登录/建单/打印/E2E；保存升级前后审计差异。

## REL-02 认证异常必须拒绝通过代理

- 优先级：P2；状态：待开发；角色：应用开发；关联：R02；可与 REL-01 的认证升级形成一个独立边界明确的提交。
- 范围：`proxy.ts`、代理测试、必要认证库升级。
- 复现：将 wrapper 传入的 auth 设为 `{message:'配置错误'}`，现实现返回 `x-middleware-next=1`。
- 验收：配置错误/缺 user/缺 id 均拒绝；API 返回规定 JSON 401，页面转登录；合法登录仍放行；领域层数据库账号检查保留。
- 验证：代理目标测试、认证/权限测试、过期与停用账号 E2E、typecheck、lint。

## REL-03 修复失效浏览器 mock 与 E2E 契约

- 优先级：P1；状态：待开发；角色：应用开发/测试；关联：R03、R04。
- 范围：失败测试及它们的 fixture；除确认的实现缺陷外不改变产品行为。
- 复现：编辑辅助表单/工单变更整文件 mock 缺 `ConfirmActionController`；账单测试等待旧按钮；客服业绩测试要求已经废止的默认待核价。
- 验收：使用真实确认组件或保留真实导出的局部 mock，验证确认前不调用 action、确认后仅调用一次、pending 和失败反馈；账单从草稿到冻结到收款的断言真正执行；新版零版费和历史待定版费分别覆盖。
- 验证：全部 `.browser.spec.tsx`、全部关键 E2E、相关单测；报告通过/失败/跳过数量和跳过理由。导入失败不能计作 0 项通过。

## REL-04 把发布浏览器与安全门禁接入 CI

- 优先级：P1；状态：待开发；角色：测试/基础设施；依赖：REL-01、REL-03。
- 范围：`.github/workflows/quality.yml`、Playwright 发布配置、隔离测试库和工价 fixture、报告上传。
- 不变量：不访问生产数据库或真实通知，fixture 只写独立可丢弃库，追加式生产/财务记录不靠删除绕过约束。
- 验收：CI 实际执行浏览器组件、生产构建 E2E、打印门禁及六视口明暗/axe；不能只 `--list`。新库发布测试工价后报工场景不得因缺前置条件静默跳过；CI 保存失败截图、trace、JSON 和依赖审计。
- 验证：用已知失败用例证明 CI 会红，再修复至绿；从空库完整迁移开始，候选 SHA 与构建产物一致。

## REL-05 统一健康端点与部署 smoke 契约

- 优先级：P2；状态：待开发；角色：运维/应用开发；关联：R05。
- 范围：jobs 健康摘要、部署 gate、测试与部署 smoke 文档。
- 复现：inline、无 worker/机器人时 health 返回 `smartBot.status=null`，其余字段表示无机器人要求且正常，smoke 拒绝。
- 验收：明确定义该状态是合法的本地模式还是要求工具指定模式；文档里的本地 smoke 可执行。生产缺 worker、必需机器人未配置、身份不符、鉴权错误仍失败，不能放宽为“HTTP 200 就通过”。
- 验证：真实路由响应交给真实 gate 的集成测试；本地 inline 与 durable worker 两套 smoke；生产失败分支回归。

## REL-07 生产基础设施与业务前置验收

- 优先级：P1 发布前置；状态：待前置条件；角色：运维/业务负责人；不属于自动执行生产操作的授权。
- 范围：正式工价、worker、真实存储/通知、数据库存量检查、备份恢复、明确 release SHA。
- 验收：工价金额/单位/生效时间经业务确认；用测试账号走真实报工到结算；两个 durable 队列按候选版本运行；中文 PDF/OSS 文件可用；备份实际恢复并记录 RPO/RTO；生产存量检查有查询及结果；真实消息测试须明确授权。
- 验证：按审查报告链接的运维清单逐项留证，未满足项不能用“本机全绿”替代。

## REL-08 修复账单真实表单提交与完成反馈

- 优先级：P1；状态：待开发；角色：应用开发；关联：R07。
- 范围：月账单表单解析、生成/确认/收款/抵扣 action、结果文案和真实表单回归。
- 复现：生产构建点击“生成或更新草稿”，页面显示 `$ACTION_*` 的 Unrecognized keys。`formObject` 无差别收集所有字段，strict schema 拒绝框架元数据。
- 不变量：只排除框架协议元数据；未知业务键的拒绝、幂等键、整单锁定收款金额、冻结快照及服务端授权继续保持。
- 验收：真实 React FormData、正常 hydration、慢加载/原生提交都得到正确中文反馈；生成→冻结→收款完整成功，重复提交不重复收款；非法业务键/错误金额仍被拒绝。同类 CDR/账单 pending 观察须单独定位，不能用延长等待掩盖。
- 验证：包含 `$ACTION_REF_*`、`$ACTION_*:*`、`$ACTION_KEY` 的目标 action 测试；生产构建完整账单 E2E；全量单测/覆盖率、typecheck、lint。修复验证必须真正走 UI，不能只手工构造不含隐藏字段的 FormData。

## 完成定义

每项交付必须包含：问题与影响、修改范围、回归用例、实际测试结果、遗留限制、commit。发布负责人只能针对同一冻结候选，确认所有适用发布阻塞已验收、测试跳过均有合理解释、部署与恢复证据齐全后决定上线。
