# 生产事实恢复

先备份并核对目标库。部署时暂停排单、扫码、审批、工资和后台相关写入，在同一维护窗口应用全部前向迁移并切换所有应用/worker；恢复前确认新守卫已生效。不要在混合新旧版本仍写入时单独开放恢复入口。操作失败保留审计与工资流水，向前修复，不删除迁移或用换生产日期解锁。

默认命令只读扫描：

```sh
node --conditions=react-server --import tsx scripts/recover-production.ts
```

输出数据库名、工单/任务/修订、原师傅/工作日、数量申请、核对期间、后续版本生产依赖、原日/期间结算引用、工资及处理链接。没有事实证据的记录不会自动填零。先检查对应工单全部版本、生产及工资记录；OPEN/CONFLICT 属于未决事实，WAGES_DUE 属于已核清但仍未付工资，两者不能混为“已恢复”。普通开发库的空清单不代表生产环境没有异常。

管理员打开清单中的工单生产记录：

1. 有数量申请：核定正确数量及原日期。多款须逐款填写；已产但数量填错使用核定，只有确认未实际生产才驳回。
2. 旧版或已关闭工单：建立历史核对记录，再填原日期和真实数量。先核实新版尚未生产；存在后续实际生产、工资或无法证明未生产时保留 CONFLICT，不能自动覆盖。原单取消/已发货状态不重开。若后续已完成，凭证核定：① 同人、同日、相同实物且旧数量已含在后续完成中，关联该记录关闭旧义务，不新增产量或工资；② 确认旧任务另有实际生产且全部后续任务已处理完，勾选“额外生产”恢复原量原日，保留后续记录及工资。证据不匹配时保持核对，不自动猜测。
3. 日期不确定：保留原任务下发至今天的核对期间。区间内结算持续阻塞；核定真实日期后再解除。不得为通过日结任意缩短期间。
4. 原日已结算：明确确认后保存实际生产及待补工资；管理员待办、工资原日和师傅个人明细持续显示未付义务。补差支付方式待业务选择，当前不能通过该界面标记补发到账。确有凭据证明无需补发时，填写依据关闭义务，生产事实及原账仍保留。

仅以下确定的元数据错误可用批次命令处理：`RELEASE_REWORK` 修复停在 SCHEDULING 的单负责人关联重做；`FIX_FIRST_PRICING` 修复从未生产、没有任何工资的普通工单错误人工计价标记。每条清单格式：

```json
[{"orderId":"扫描所得 ID","revision":2,"version":1,"mode":"RELEASE_REWORK","requestKey":"每次修复唯一且可重放的键","reason":"已核对来源、任务、打印和历史工资"}]
```

```sh
node --conditions=react-server --import tsx scripts/recover-production.ts --manifest=/绝对路径/已核对清单.json
node --conditions=react-server --import tsx scripts/recover-production.ts --manifest=/绝对路径/已核对清单.json --apply --actor=管理员用户名 --confirm-database=已核对的数据库名
```

dry-run 显示候选清单和现状，不等于批准执行或承诺可恢复；apply 在每单锁内重读全部闸口并独立提交；重复使用完全相同键/输入返回原结果，键被复用或修订过期会拒绝。清单中某条失败后停止后续条目，已成功的条目保留；修正原因后重新 dry-run，不回滚已记录事实。命令不能自动恢复数量、付款或替换负责人。处理后对照原工资及结算快照、来源工单物流、任务数量和审计，再核查待办与师傅工资页。

生产尚未完工时，只改交期等资料可延续原任务：相同实物、负责人和各款待登记量在新版继续，保存原下发日期及 CONTINUED 审计，不虚构“未生产”或部分完工。改数量、设计或取消仍先核对实际生产。误标“未生产”的历史记录可重新建立核对。

历史包含按整条申请核对：有原申请量时必须全部匹配；同一后续登记可包含的旧数量合计不能超过其完成量。已包含或已承接的记录不能重新当作独立漏登记。跨日但实际属于同一批实物的记录，当前保持待核对；不要勾选“额外生产”或“未生产”解锁。工资日期的处置规则尚待业务确认。

新增前向迁移共四项：20260928130000、20260928131000、20260928132000、20260928133000；最后一项补齐包含数量累计上限及已承接/已包含证据保护。历史恢复只重核同工序且款式重叠的后续任务，无关工序已完成或沿用的数量与工资保持。完整核验记录见[执行记录](audits/2026-09-28-production-remediation-execution.md)。
