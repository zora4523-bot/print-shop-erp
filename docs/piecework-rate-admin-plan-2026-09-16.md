## 3. 页面与操作流程（P0）

管理员从“员工薪酬规则 → 计件工价”维护。展示当前工价、待发布草稿、已发布版本及生效时间。

| 项目 | 单位 | 填写要求 |
| --- | --- | --- |
| 局部烫金 | 元/下 | 发布必填 |
| 专版烫金 | 元/个 | 发布必填 |
| 包装入袋 | 元/袋 | 可选；2026-09-17 决定暂缓，缺价时暂停入袋报工 |
| 包装装盒 | 元/盒 | 选填；未发布时不能按盒报工 |

流程：查看当前工价 → 创建调价草稿（首次进入使用现有空草稿）→ 填写或修改 → 保存草稿 → 核对价格变化及生效时间 → 发布。

- 草稿允许暂缺金额；发布严格遵循现有金额范围及四位小数规则。金额用字符串传输、Decimal 运算；不得把空白转成零。
- 已发布版本只能查看；调整时建立后续版本，带入上一版金额供修改。首版不得预填猜测值或测试工价。
- 支持“立即生效”和指定生效时间，页面按上海时间展示，接口保存明确时间戳。
- 发布核对层展示旧价、新价、差额、生效时间和本次必要后果；不重复套确认弹窗。
- 发布失败保留输入；版本已被他人修改时提示重新加载并核对，禁止静默覆盖。
- 复用现有表单、金额输入、状态、错误与加载组件；遵守[文案与确认](./ui-规范.md#文案与确认)，不把数据库枚举、哈希或技术机制显示给用户。

## 4. 领域与接口任务（P0）

1. 补齐查询当前/草稿/历史版本、创建后续草稿、保存草稿的领域能力，保留现有发布入口。优先使用现有表结构，不预设新增迁移。
2. 保存草稿必须验证在职管理员、草稿状态和预期 `updatedAt`；与发布共用 advisory lock，锁定父版本及规则。修改规则时同时推进父版本更新时间并记录审计。
3. 现有发布器拒绝覆盖草稿中已经填写但与提交内容不同的金额。新增编辑能力先合法保存草稿，再对同一修订预览和发布；不得删除该保护来实现编辑。
4. 预览结果绑定草稿修订及规范化内容；发布在事务内重新校验，不能信任客户端预览结果。保留来源、修改说明、内容摘要和操作者记录。
5. 为“立即生效”补充事务内确定生效时间的明确契约；避免浏览器生成的时间在请求到达后变成过去时间。重复提交必须返回同一次发布结果，不能因重新生成时间导致第二次发布或冲突。
6. 指定时间不得倒填；未来版本、相邻版本的生效区间及连续编号沿用既有约束。存在待生效版本时，创建后续版本必须遵循当前版本链，不跳过、不原地修改已发布版本。
7. Server Actions 统一校验 `salary:rule:manage`，领域层再次验证管理员有效状态；外部销售、客服和师傅不得编辑或发布。仅页面隐藏按钮不算权限控制。
8. 输入采用项目既有 schema 校验；返回可序列化金额和业务错误。成功后只刷新相关页面。CLI 与后台使用相同规则，不另建可绕过保护的写入接口。
9. 可选按盒工价沿用现有支持；草稿规则增减同样受锁和修订保护。已发布且被报工引用的规则禁止修改或删除。

### 7.2 新版统一计薪口径

按用户移除旧版的方向，方案采用现有新版工序模型，不把旧公式再复制成另一套规则：

| 工序 | 计薪公式 |
| --- | --- |
| 局部烫金 | 合格完成数 × 过版次数 × 元/下工价 |
| 专版烫金 | 合格完成数 × 元/个工价 |
| 入袋 | 合格完成袋数 × 元/袋工价 |
| 装盒 | 合格完成盒数 × 元/盒工价 |

- 局部过版次数来自受控工序数据中的正反面颜色数，不允许师傅随意改倍率；多次报工、多人报工累计不得重复领取同一产量工资。
- 缺陷数、返工数保留质量记录，不自动增加本次计薪数量；纠错沿用现有报工冲销/更正能力并核查结算状态限制。
- 旧版小单一口价、装板费、日保底、个人机型覆盖和单双面/单双色倍率不再自动参与新报工计薪。局部过版次数已体现颜色与面数，禁止再乘旧倍率。
- 这会改变工资结果：实施时在现行业务规格中明确新旧适用边界，并追加决策记录，说明取代旧机型计薪的哪些条款，不改写过去的决策或工资记录。
- 本方案不赋予旧规则金额新的含义，也不以测试金额作为正式工价。正式价格在新后台由管理员发布，未配置时明确阻止对应报工。

### 7.4 编码约束与针对性验收

- UI 组件只负责展示和交互；服务端操作负责权限与输入；领域层负责金额、资源状态、锁和事务。依赖方向不得反转。
- 维护严格 TypeScript 类型和既有 schema；不使用 `any`、吞错、客户端授权或浮点金额捷径。读取接口返回最小投影，禁止将 Prisma 对象和内部审计信息直接发给客户端。
- 使用现有共享组件、语义样式和业务文案，不另造表单、弹窗或状态体系；遵循 [编码规范](./编码规范.md) 与 [UI-SYSTEM.md](../UI-SYSTEM.md)。涉及 Next.js 操作或路由时先读安装版文档。
- 保存与发布使用一致锁顺序；重试不重复记账。所有新报工保留价格版本、单价、计薪数量及金额依据，调价不重算已发生工资。
- 覆盖旧端点直调拒绝、旧后台任务重试拒绝、seed 不再新增旧计薪配置、历史详情/导出及工资总额不变；不能删除历史测试来掩盖破坏。
- 增加局部正反面多色、专版不乘旧倍率、小单不再套旧一口价、无保底自动补足、跨日调价、多人/重复报工、冲销与已结算限制的回归测试。
- 切换演练核对每笔在途业务的适用规则，避免一笔产量同时进入两个账本。新旧数据的数量、金额、关联和付款状态均须有前后对照。
- 不具备正式工价时可以验收后台编辑能力，但不能宣称生产扫码计薪已可用；部署切换须同时满足工价、数据演练和发布门禁。
