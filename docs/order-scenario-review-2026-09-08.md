# 工单场景数据与关联审查

## 可复现的本地数据

命令使用本机非生产数据库、已存在的 `e2e-sales` 与 `e2e-owner` 测试账号和当前有效产品/工艺目录。默认预览；写入必须明确指定 `--apply` 和仓库外报告路径：

```sh
NODE_OPTIONS=--conditions=react-server pnpm exec tsx scripts/seed-order-scenarios.ts
NODE_OPTIONS=--conditions=react-server pnpm exec tsx scripts/seed-order-scenarios.ts --apply --report=/tmp/order-scenarios-run.json
```

客户统一为“演示客户”；名称以“测试”开头。13 个固定场景的提交标识稳定，重跑不覆盖已完成或已编辑工单；仅可继续脚本创建但尚无报价、附图和后续日志的初始草稿。报告记录新建 ID，失败时保留可定位的草稿。交期按首次执行当天的上海日期生成，重跑不滚动修改已有交期。

| 场景 | 主要覆盖 |
| --- | --- |
| 局部烫金常规单 | 自动加工费、入袋费、运费、默认版费零 |
| 专版烫金明日交付 | 专版路线、明日提醒 |
| 彩印今日交付 | 纯彩印、今日提醒 |
| 彩印加烫金急单 | 彩印基础价与烫金附加工艺、急单 |
| 三种工艺多款单 | 局部/专版/彩印汇总、去重、各款独立计价 |
| 局部烫金逾期单 | 逾期提醒 |
| 专版混装两地址 | 两款混装、两票分货及各票费用 |
| 专版三色待核价 | 由实际三色事实触发人工核价，不伪造手工金额 |
| 彩印草稿 | 未填交期、未报价 |
| 彩印暂停 | 暂停原因及恢复依据 |
| 专版三色驳回 | 价格待补正及不可自动准备 |
| 局部烫金加量申请 | 原数量/报价保留，待审批标识与下发阻断 |
| 局部烫金取消 | 终止状态不显示倒计时 |

本批使用正式 `createOrder`、外部报价终结器和生产准备函数；场景状态经过状态机校验并记录测试日志，暂停/驳回另保留工作流决策记录。脚本不调用通知派发、生产下发、报工、发货或结算，不生成工资或虚构已付款凭证。生产中、已发货、已结算仍需使用相应业务流转 E2E 验证，不能把本批数据当作这些状态已验收。

## 关联核对及修复

- 列表/抽屉读取同一 `AdminOrderWorkspaceRow`；详情与编辑共用 `getOrderDetail`，保留款式 ID、真实数量、包装组及配送关联。
- 原详情页仍展示远期倒计时、隐藏交期年份，已与列表统一使用服务端临期信号及完整日期。
- 详情工艺摘要使用规范工艺类型；款式明细同时保留具体工艺字典名称，字典缺失时仍能识别彩印或烫金类别。
- 新增草稿场景暴露出未报价显示“历史金额 ¥0.00”的问题：管理端未报价草稿现在显示“未报价／提交后报价”，金额保持未知，真实零元报价仍保留。
- 每张新单回读列表与详情，核对工艺汇总、款数、总数、每款配送分配；报价单核对包装合计、加工合计、附加费用及报价快照。编辑页直接读取相同明细，不生成另一套测试费用。
- 计价仍取当前发布规则；自动计价不覆盖人工核价，版费默认零，人工录入版费入口不变。未假造 CDR，演示 SVG 明确不可生产。

- 草稿操作直接进入编辑页面，不再误导为人工录价；流转日志补齐当前状态机状态的中文标签，避免正常准备/下发状态显示为“未识别工单状态”。
- 编辑页标题与预览原来误用并发修订号 `revision` 作为工单版本；现统一显示 `workOrderVersion`，请求仍分别传入两个版本做并发校验。
