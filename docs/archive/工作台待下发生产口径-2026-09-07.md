# 工作台“待下发生产”口径

核对日期：2026-09-07。适用当前管理员工作台与工单队列。

## 结论

当前生产流程不做人工派工。工作台新增“待下发生产”，不沿用历史“待排产”名称。列表和首页计数共用 `adminSignalWhere('pending-release')`：工单为 `CONFIRMED`，且不存在 `PENDING` 修改或取消申请。该事项也归入管理员“待办”队列。

| 状态 | 当前解释 | 是否纳入待下发生产 |
| --- | --- | --- |
| `PENDING_FACTORY` | 待工厂确认 | 否，已有待确认入口 |
| `SUBMITTED` | 兼容的待工厂确认状态 | 否 |
| `CONFIRMED` | 已确认，尚未下发 | 无待审核变更时纳入 |
| `ON_HOLD` | 已暂停 | 否，先走恢复流程 |
| `RELEASED` | 已下发生产 | 否 |
| `SCHEDULING` | 历史生产准备状态 | 否，不代表等待人工派工 |
| `FOILING` / `PACKING` / `IN_PRODUCTION` | 当前或历史生产状态 | 否 |

首页链接为 `/orders?queue=all&signal=pending-release`。进入工单后仍通过原有“下发生产”操作执行；首页只读，不批量下发。

## 保持的业务边界

队列表示需要关注的阶段，不承诺所有记录都能立即下发。原有 `releaseFactoryOrder` 继续校验管理员权限、版本、幂等键、待审核变更及生产工序物化前置条件；下发仍在事务内创建当前版本的工序、进度步骤和首次打印请求。实际打印确认不是下发的前置动作。

不转换历史状态，不修改已应用迁移，不恢复旧派工流程，不改变金额、工资或历史生产快照。
