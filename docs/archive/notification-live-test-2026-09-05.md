## 测试隔离与证据边界

`scripts/notification-live-smoke.mjs` 创建一次性 PostgreSQL 数据库，执行全部迁移，仅复制现有群绑定和模板。在该临时库中启用全部 15 条规则和两个管理角色，并统一指向用户授权的现有群。

测试直接调用 `dispatchNotification`，实际经过生产任务入队、LIGHT worker、机器人发送、投递日志终态写入和任务完成。它不等于逐项真实操作下单、改单、报工、发货、盘点、结算和定时扫描。业务触发部分通过代码审查及自动化回归验证；未为测试修改真实订单、库存或薪资。

前两轮测试曾遇到真实 PostgreSQL 最终状态写入错误，随即停止，没有自动重放不确定投递。那些消息可能已经发出；本报告的 15/15 结论仅指上方独立编号的成功批次。

测试进程已结束，临时数据库及其中合成业务数据和投递记录已清理，剩余测试数据库数量为 0；这些临时记录未归档，群内真实测试消息保留。

## 本次修复

| 缺陷 | 修复和验证 |
| --- | --- |
| P1：发送完成后日志无法写入最终状态 | `delivery-ledger.ts` 的两个 CASE 参数被 PostgreSQL 推断为 text，与整数列不兼容，SQLSTATE 42804。增加 `::integer`，覆盖正常 finalization 和恢复 finalization。新增 10 项真实 PG 回归，覆盖四种终态、已提交成功的恢复和旧令牌拒绝。 |
| 通道测试人工重试后可能获得多次自动重试预算 | 通道测试创建、重新激活及人工重试均只允许一次执行；失败进入终态，避免不确定应答下自动重复推送。 |
| 五个历史默认模板显示字面量 `\n` | 新前向迁移仅修复精确匹配的历史模板，保留自定义模板、开关与路由。真实 PG 迁移回归通过，迁移已应用到本地业务库。 |
| 库存盘点跌破安全库存未触发预警 | 在锁定物料下汇总实际过账库位差额，按最终全局库存跨越安全线判定；每物料一次，与盘点同事务写入 outbox，幂等重放不重复。 |

另补充 `APP_PUBLIC_URL` 合法配置下的工单完整链接渲染，保持净化后的持久化 payload 契约不变；未配置时不猜测域名。
