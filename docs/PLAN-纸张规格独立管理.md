# 纸张、规格独立管理与产品组合自动维护方案

状态：待评审、待实现。日期：2026-09-20。

本方案基于 `318a6303e2cd06fb1de42dde392a0ebb31de9b01` 的代码与项目文档核对，仅交付设计方案。未修改页面、价格、数据库或生产配置，不能据此认定功能已上线。

## 1. 建议与目标

纸张、规格分别管理；管理员在纸张详情或价格表中维护适用关系，不再逐条创建“可建单产品组合”。系统自动维护订单、价格和 BOM 所需的内部产品关联。

最终日常菜单保留“纸张”“规格”以及各类计价页面，撤下“可建单产品组合”。撤下的前提是现有业务入口和消费方已完成替代，不能先隐藏菜单再补功能。

目标操作示例：为红卡 180g 增加方形封，只需选择该纸张、启用方形规格；需要自动报价时，再填写并发布方形单价。无需填写产品名称、产品编码或另建产品档案。

本方案不要求先删除 `Product` 表。拆分管理职责与替换全部底层模型是两件事，后者不作为本次验收条件。

## 2. 当前实现与问题

| 当前事实 | 代码或文档依据 | 改造影响 |
|---|---|---|
| 产品记录包含纸张、规格、分类及启停状态 | [Product 模型](../prisma/schema.prisma)、[产品查询](../lib/product.ts) | 不能把现有记录当作无用数据删除 |
| 建单规格从有效产品记录提取，尚无独立规格来源 | [建单选项](../lib/order/create-order-options.ts) | 仅增加一个“规格”页面仍不能完成解耦 |
| 选项覆盖空白封、专版烫金、彩印三条路线 | [建单目录](../lib/order/order-item-catalog.ts) | 只迁空白封时不能撤下全部旧管理能力 |
| 新增空白封纸张与价格会同时创建或复用产品 | [新增事务](../lib/price/customer-price-book-admin.ts)、[现行说明](./空白封纸张规格管理-20260913.md) | 可复用现有事务能力，但应拆分关系维护与价格草稿操作 |
| 工单、价格规则、BOM 引用产品身份 | [Schema](../prisma/schema.prisma)、[BOM 查询](../lib/bom.ts) | 必须保留原 ID 及历史关联 |
| 矩阵没有产品且没有价格时显示“不适用” | [价格矩阵](../components/business/rules/pricing/CustomerPricingDedicatedSection.tsx) | 当前缺少“未维护”和“明确不适用”的区分 |

现行系统已允许“有合法产品配置但无报价”进入待核价；本方案保留此能力，不能改成“必须先定价才能建单”。

## 3. 管理职责与页面

| 页面 | 维护内容 | 不承担的职责 |
|---|---|---|
| 纸张 | 名称、克重、启停状态及既有库存资料；按业务路线维护适用规格 | 不填写产品编码，不直接改已发布价格 |
| 规格 | 名称、尺寸、产品结构、适用业务路线及启停状态 | 不保存具体纸张单价 |
| 空白封单价 | 纸张 × 规格矩阵，新增适用规格，录入与发布单价 | 不作为生产可用性的唯一判据 |
| 专版、彩印计价 | 沿用各自阶梯、加价等规则，并使用统一纸张与规格身份 | 不强行改成空白封的按个单价模型 |
| BOM 维护 | 用业务路线、纸张、规格等条件定位现有目标，继续保留分类级规则 | 不要求用户跳到产品组合页面建档 |

纸张详情和价格表中的“适用规格”是同一份关系的两个入口，必须调用同一个领域服务，不能各维护一份白名单。

### 3.1 纸张与适用规格

- 新增纸张只建立纸张资料，不默认启用全部规格。
- 选择业务路线后，可批量启用适用规格；空白封与专版即使尺寸相同，也不相互自动授权。
- 取消适用关系采用停用，不删除历史记录。再次启用时复用原身份。
- 批量编辑只保存本次实际变动的格子；未勾选且从未维护的格子不能批量推断为“不适用”。
- 纸张停用、缺货和 120g 退役校验沿用现行规则，不能通过新增关系重新开放。

### 3.2 规格独立管理的边界

首期将当前支持的规格整理为独立目录。空白封先保留六种已支持规格；迷你封不能因进入目录而绕过现有纸张限制。

规格具有稳定 ID，名称只用于展示。用于计价和生产的尺寸、结构发生变化时创建新规格，不原地改变已有规格含义；纯展示更名须核对现有字符串匹配与历史展示依赖。

首期不承诺“任意新增尺寸后立即自动报价”。新尺寸需要同时核对计价匹配、物流重量、包装、生产工序及 BOM。未支持的尺寸不可伪装成现有中号或大号；扩展尺寸支持作为后续独立任务。

### 3.3 价格表状态

生产可用性与价格状态分别存储和判断。管理员矩阵建议按以下优先级呈现：

| 条件 | 单元格文案 | 可执行操作 |
|---|---|---|
| 纸张或规格停用 | 已停用 | 查看对应资料；满足现行规则后再启用 |
| 明确标记该搭配不可生产 | 不适用 | 有权管理员可调整适用规格 |
| 尚未建立适用关系，且没有历史冲突 | 待设置 | 设置适用规格 |
| 已允许生产，无生效报价 | 待核价 | 发起调价、补录单价 |
| 已允许生产，有生效报价 | 实际单价 | 发起调价 |
| 已有价格却缺少合法关系，或存在重复匹配 | 待处理 | 展示具体原因和修正入口，不自动启用或选第一条 |

价格草稿继续使用现有变更标记和审阅发布流程，不另创一套发布状态。`0` 是明确零价，留空是缺价，不能相互转换。纸张缺货按现行建单策略显示和阻断，不混同为永久“不适用”。

以上属于拟定文案，实施时按 [文案与确认](./ui-规范.md#文案与确认) 核对。页头不展示产品 ID、生成规则等内部机制；必要后果集中放在实际操作的复核位置。

## 4. 典型流程与生效时点

### 4.1 只增加适用规格

纸张详情 → 选择业务路线 → 勾选方形 → 保存适用规格。

保存成功后，该搭配可进入新的建单选择。没有生效价格时进入现有人工核价流程，不生成默认单价。此操作无需先建立调价草稿。

### 4.2 从价格表增加规格并录价

空白封单价 → 发起调价 → 在“待设置”的格子设置适用规格并录价 → 保存 → 审阅变更 → 发布。

沿用当前“目录即时生效、价格发布生效”的边界：保存时关系与内部产品关联立即生效，单价只写入草稿。保存复核需明确列出新增适用规格以及价格尚未发布这一实际后果；放弃调价不会撤销已保存的适用关系。

该复合保存必须在同一数据库事务内完成关系、内部产品、草稿价格和审计；任一步失败全部回滚。单独维护适用关系则使用独立、明确的保存动作。

### 4.3 销售建单

沿用已有表单顺序选择业务路线、纸张、克重和规格。系统按明确适用关系提供选项，在服务端解析唯一内部产品并重新计价。销售无需选择或填写产品组合名称。

允许生产但缺价格可进入现行人工核价；未维护、明确不适用、重复匹配等不能通过手工输入产品 ID 或伪造前端选项绕过。手工成交价继续遵守原权限、原因与审核规则。

## 5. 建议数据结构

以下名称仅为设计建议，正式 schema 与 SQL 需在实施时审查。

| 数据 | 建议处理 |
|---|---|
| 纸张 | 复用 `Material`，以物料 ID 加明确克重事实识别，不另建重复纸张库 |
| 规格目录 | 新增稳定规格身份，包含显示名、尺寸、结构及受支持路线；保留与现有规范化值的映射 |
| 适用关系 | 以“路线＋纸张物料 ID＋规格 ID”为唯一业务键，状态为允许或明确不适用；没有记录表示待设置 |
| 内部产品关联 | 每条允许关系关联唯一 `Product`；新增或复用由领域服务处理，旧 ID 不变 |
| 价格 | 保留 `CustomerPriceBook` / `CustomerPriceRule` 版本模型，首期继续关联现有产品身份 |

克重若仍来自纸张名称或规格文本，迁移必须解析并校验一致性；不能只靠界面名称去重。若一条纸张物料不能唯一表达一个克重，先记录异常，不生成不确定的适用关系。

同一几何尺寸不一定代表同一种产品结构；规格去重必须同时考虑结构。价格与目录各自只有一个事实来源：关系决定能否用于新单，已发布价目决定自动报价；保留在产品上的纸张、规格字符串仅作为受控兼容字段，不能形成另一个独立编辑入口。

允许关系的新增采用业务键唯一约束、现有价格资料写锁和事务；并发重复请求复用同一产品，失败可重试。新建单时只解析，不临时创建产品或修改目录。

对于兼容关系外的其他产品，保留现有用途，禁止全表一刀切转换。专版多纸张、多规格的旧记录需要单独分析价格/BOM引用，不能直接展开后把原价格和 BOM 复制给所有新组合。

## 6. 服务端与历史保护

- 纸张修改保留 `material:manage`；规格和适用关系首期使用现有 `dict:product:manage`；价格操作保留 `dict:price:manage`。复合操作需要对应权限的交集，既不能因按钮隐藏而放松，也不能让自动维护产品扩大调用者权限。
- 保存和发布重新读取纸张、规格、关系、草稿状态与版本；过期编辑拒绝并给出刷新入口。必要资源归属及新单可用性在领域层复验。
- 金额继续使用 Decimal，单价沿用四位小数及现行合法范围，计算与舍入不变；缺价不取零或其他规格的价格兜底。
- 停用关系只改变新业务准入，不删除旧价格规则、订单、BOM、已保存金额和快照。关系停用后仍可在管理端查看已有价格及引用。
- 重新启用关系若仍有生效价格，应在操作复核中展示将恢复使用的价格；不默默新建价格版本。
- 草稿订单首次提交、打样和销售工作台都需重新验证新业务准入；历史改单与取消结算不能直接套用新单过滤器。
- [纸张退役记录](./audits/2026-09-17-retire-120g-paper.md) 和 [现行决策](../DECISIONS.md) 已记录的“停用物料影响部分历史重算”问题单独保留，不借本次目录改造默默放宽或扩大阻断范围。
- 纸张、规格、关系及价格操作记录变更前后值与操作者。已应用迁移不修改、不删除，只增加前向迁移。

## 7. 分阶段实施

### 阶段一：依赖盘点与迁移预检

产出可重复执行的只读报告：三条路线的产品、纸张、规格、价格、BOM、历史工单引用及重复身份；核对 SQL、seed、维护脚本、动态入口和外部 API 消费方。

报告区分“可唯一映射”“无物料关联”“克重或尺寸不明”“重复产品”“多值规格/纸张”“价格与目录冲突”“其他用途产品”。异常记录禁止自动归并或删除。缺价但允许生产、停用产品、退役纸张分别统计。

阶段完成条件：明确全部消费方、受支持范围和异常处理清单。文档中已找到的路径只是起点，不能替代运行数据预检或作为可删证据。

### 阶段二：建立规格目录和适用关系

新增 schema 和前向迁移；在隔离库验证 fresh DB 和存量回填。仅回填能证明唯一的映射，保留原产品 ID。启用产品是否可迁为允许关系须同时满足有效分类、纸张及路线要求；停用记录不直接推断为物理不可生产。

新旧解析并行比对但仍仅由既有路径返回结果，记录差异；未消除的差异阻止对应范围切换，不静默回退。不要长期保留两套可写配置。

阶段完成条件：受迁移范围的关系解析一致、价格不变、引用计数与快照不变；异常项完成明确处置或保留在尚未切换范围。

### 阶段三：新管理入口与受控切换

交付纸张适用规格、独立规格目录、价格格子新增及统一领域服务；空白封先行验证，再覆盖专版和彩印。对已切换范围，旧编辑入口停止直接修改组合事实，只导航到对应新入口。

同步更新管理员与外销建单、批量建单、销售工作台、打样、报价及提交校验；BOM 选择器使用同一解析服务。内外销、历史改单和取消路径分别验证，不能把新单路径验证视为全覆盖。

阶段完成条件：用户可通过新页面完成原有维护任务，服务端只有一套有效写入口；缺价分支仍可用，所有既有路线均有可用维护入口。

### 阶段四：撤下旧菜单与兼容收尾

三条路线和其他已发现的管理用途都完成替代后，移除“可建单产品组合”日常菜单。旧列表、创建、详情链接按上下文导航到新入口；历史引用仍可查看，无法映射的链接给出恢复入口，不猜测映射、不裸露 404。

撤下旧写接口前再次核对外部消费方，必要时保留经过授权的兼容适配。保留 `Product`、价格关联和历史记录；是否进一步去除底层产品模型，另行评估。

## 8. 发布与回退

采用先扩展、后切换的部署顺序；前向 schema 保持旧读取兼容，切换前完成数据预检与解析对比。正式数据变更需明确目标库、备份、迁移耗时及锁影响，并按项目发布门禁执行。

回退优先关闭新管理写入口、回退读取路径并保留已写数据；不删除新增关系、不逆向删除产品、不回滚已发布的价格。阶段三启用前必须验证旧版本能读取新入口生成的产品和价格，否则不能声称可直接回滚到旧应用。

允许/不适用状态不得只存在新关系中而被旧路径忽略；如旧版本无法遵守新的停用语义，停止受影响的新建业务并向前修复，不能以回退为由重新开放禁用组合。切换期间两套管理入口不能同时自由写入。

## 9. 验收与验证

| 场景 | 必须达到的结果 |
|---|---|
| 红卡 180g 新增方形 | 无需手填产品档案；仅创建一个合法关联 |
| 只启用规格、价格留空 | 销售可选择并进入现有人工核价，无默认金额 |
| 录入零价或四位小数 | 与缺价区分，发布后按原精度计价 |
| 两人同时新增、重复提交 | 无重复产品或关系，结果可安全重试 |
| 关系与草稿同时保存时失败 | 所有本次写入与审计一起回滚 |
| 放弃价格草稿 | 已保存关系保留，生效价格不变 |
| 未维护、不适用、停用、退役、缺货 | 各状态准确，前端和服务端不能相互绕过 |
| 同尺寸不同结构或不同业务路线 | 不错误复用产品、价格或 BOM |
| 重复产品、缺克重、多值旧配置 | 明确报错或进入待处理，不任取第一条 |
| 停用/重新启用关系 | 新单准入符合操作意图；已有价格恢复使用时可复核 |
| 修改目录或发布调价 | 历史工单金额、结算和快照不被回写 |
| 原有三路线和各种建单入口 | 选项、报价、提交均保持完整，不能只验证空白封 |
| 越权、过期草稿、伪造关联 ID | 服务端拒绝，未留下部分写入 |
| 旧链接与 BOM 选择 | 能找到对应业务入口，原引用不丢失 |

实现验证按 [贡献指南](../CONTRIBUTING.md#测试要求) 执行：领域与 Action 定向测试、全量 Vitest、相关真实 E2E、类型与 lint、架构检查，以及 schema 迁移 fresh DB 和前后置检查。写入型验证使用明确指定的独立可丢弃数据库。

界面覆盖六视口、明暗主题、键盘、触控、overflow 与 axe；发布候选补齐构建、覆盖率等完整门禁。同一业务输入对比改造前后报价、物流、BOM 解析和历史记录，不以仅能加载页面作为验收。已有历史重算问题单独记录基线，不能改断言掩盖。
