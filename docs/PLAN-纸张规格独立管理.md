# 纸张、规格独立管理与产品组合自动维护方案

状态：待评审、待实现。日期：2026-09-20。

初稿提交为 `4537aef7`，第一轮修订为 `bfa202f4`；本轮按后者代码核对 N1–N5，并纳入业主 2026-09-20 对改单新增款式的决定，仅交付设计方案。方案整体仍待评审，不能把这一条已拍板决定视为整体获批。未修改页面、价格、数据库或生产配置。开发库数字仅来自审查方只读报告，本次没有重跑 SQL 或访问正式库；实施阶段一必须重新预检目标库。

## 1. 建议与目标

纸张、规格分别管理；管理员在纸张详情或对应计价页面维护路线适用性，不再逐条创建“可建单产品组合”。系统按路线自动维护订单、价格和 BOM 所需的内部产品关联。首期规格目录只读，专版继续复用规格产品，不为每张纸复制产品。

最终日常菜单保留“纸张”“规格”以及各类计价页面，撤下“可建单产品组合”。撤下的前提是现有业务入口和消费方已完成替代，不能先隐藏菜单再补功能。

目标操作示例：为红卡 180g 增加方形封，只需选择该纸张、启用方形规格；需要自动报价时，再填写并发布方形单价。无需填写产品名称、产品编码或另建产品档案。

本方案不要求先删除 `Product` 表。拆分管理职责与替换全部底层模型是两件事，后者不作为本次验收条件。

## 3. 管理职责与页面

| 页面 | 维护内容 | 不承担的职责 |
|---|---|---|
| 纸张 | 新增名称与克重，维护启停及既有库存资料；按路线设置适用性 | 被产品、关系或生效/计划价目引用的身份禁止直接修改，见 §6 |
| 规格 | 只读展示受支持路线、名称、尺寸和结构；首期无新增、改名、改尺寸或全局启停入口 | 不保存具体纸张单价，不承诺任意尺寸自动报价 |
| 空白封单价 | 纸张 × 规格矩阵，新增适用规格，录入与发布单价 | 不作为生产可用性的唯一判据 |
| 专版计价 | 专版纸张准入、规格阶梯与纸张加价各自维护 | 不建立纸张 × 规格单价，也不按纸张复制规格产品 |
| 彩印计价 | 维护纸张与规格适用关系，单价仍在原彩印数量档位及加烫金规则中维护 | 不用空白封单价代替每款阶梯金额 |
| BOM 维护 | 用业务路线、纸张、规格等条件定位现有目标，继续保留分类级规则 | 不要求用户跳到产品组合页面建档 |

纸张详情与对应计价页是同一份关系的不同入口，调用同一领域服务；分路线的粒度见下文，不能各维护一份白名单。

### 3.1 纸张与适用规格

- 空白封、彩印按“路线＋纸张＋规格”维护关系；新增纸张不自动生成这两条路线的全部组合。
- **专版选择 R1 的方案 (a)：纸张级准入，规格复用启用的专版规格产品。** 原有可选集合来自纸张与规格的展开，这种粒度保留现状且避免无意义的纸张级产品复制。专版纸张准入不承载规格单价。
- 专版的缺省值与前两条路线不同：没有显式准入记录时，沿用现有有效 PAPER 物料与有效专版规格的组合逻辑；克重、缺货、退役及身份校验照旧。新增纸张也继续按此逻辑进入专版选项，非基准纸且无唯一加价时转人工，冰白纸仍由管理员核价。
- 专版准入按规范化纸张名与克重判定，再解析唯一物料；多值名称或同身份重复物料标为“待处理”，不开放这些身份的禁用操作，选项与既有报价失败保持原状，不能任取一条物料当权威身份，详见 §5.3。
- **需业主确认：新增纸张是否改为手动启用后才能用于专版。** 已登记在 [HANDOFF](../HANDOFF.md#卡住的问题) 和 [PROGRESS](../PROGRESS.md#待澄清的业务问题)。本方案选择纸张级数据粒度不等于批准修改缺省业务行为；业主确认前不得实施手动启用的默认白名单。当前纸张可能因缺货显示不可选，迁移对比需同时保留选项与禁用状态。
- 关系禁用独立于 `Product.isActive`，不删除记录或价格；只有具备 §7 全部入口覆盖和 §8 发布条件后才开放禁用操作。
- 批量编辑只保存本次实际变动的格子；未勾选且从未维护的格子不能批量推断为“不适用”。
- 纸张停用、缺货和 120g 退役校验沿用现行规则，不能通过新增关系重新开放。

### 3.2 规格独立管理的边界

首期将当前支持的规格整理为只读目录：空白封六规格、专版五个必需规格、彩印按已验证的路线规格映射。目录有稳定 ID，但**当前规范名本身仍是计价键**，不能把它当作任意可改的展示名称。

规格目录分别保存不可变的 `pricingKey`（规范名）与 `displayName`（展示名）。首期两者均无界面写入口，也不开放尺寸、结构或全局启停编辑；既有路线有效性仍沿用现行配置。未来展示名编辑必须与所有计价输入分离后另立任务。

保留并以契约测试锁定五处现有定义：[别名归一](../lib/price/create-order/canonical-facts.ts) 的 `SPECIFICATION_ALIASES`、[款式侧](../lib/order/create-order-quote-facts-adapter.ts) 的 `pricingGroup`、[规则侧](../lib/order/create-order-published-rule-adapter.ts) 的 `pricingGroupForSpecification` 和 `REQUIRED_FULL_SPECIFICATIONS`、[空白封六规格](../lib/price/blank-paper.ts) 的 `BLANK_SPECIFICATIONS`。每个目录计价键必须能通过款式侧分组；专版目录键集合必须恰好等于五个必需规格，且两侧计价组一致。不要要求空白封的迷你封通过仅服务专版的分组函数。

“规格数据驱动化”、新增尺寸、展示名编辑和全局启停是独立后续任务，不进入本方案验收；未知规格不得写入规则导致整本价目投影失败，也不得伪装成已有中号或大号。

### 3.3 价格表状态

以下单元格表**仅适用于空白封**。生产可用性与价格状态分别存储和判断，展示实际业务状态：

| 条件 | 单元格文案 | 可执行操作 |
|---|---|---|
| 纸张或既有产品停用 | 已停用 | 查看对应资料；满足现行保护规则后再处理 |
| 明确标记该搭配不可生产 | 不适用 | 有权管理员可调整适用规格 |
| 尚未建立适用关系，且没有历史冲突 | 待设置 | 设置适用规格 |
| 已允许生产，无生效报价 | 待核价 | 发起调价、补录单价 |
| 已允许生产，有生效报价 | 实际单价 | 发起调价 |
| 无法唯一关联产品/关系、存在身份冲突 | 待处理 | 展示具体原因和修正入口，不自动启用或选第一条 |

关系被明确禁用而价格仍生效是 §6 选定策略允许的状态，显示“不适用”并保留查看价格入口，不误报为资料冲突。

“待设置”只表示不进入标准选项，不代表禁止受理；自定义纸张、改尺寸等既有人工核价路径继续可用。“明确不适用”才是准入拒绝，不能通过留空产品 ID 或填写配置外说明转成人工核价绕过。两者的服务端判定见 §6.1。

专版在纸张列表显示“可选 / 不适用 / 已停用 / 缺货”等准入状态；没有显式关系不显示“待设置”，而是沿用缺省行为。报价是否完整由基准纸、纸张加价、规格阶梯与实际工艺共同决定，缺价显示“待核价”，冰白纸显示“管理员核价”。录价分别进入现有专版阶梯和纸张加价页面，不出现纸张 × 规格单价格。

彩印关系入口显示“待设置 / 可选 / 不适用”，停用和缺货状态仍覆盖准入；报价页继续按数量档位展示实际每款金额或“待核价”，加烫金另按现行规则维护。某个档位有价不等于所有数量都能自动报价，超量等人工核价理由保留。

价格草稿继续使用现有变更标记和审阅发布流程，不另创一套发布状态。`0` 是明确零价，留空是缺价，不能相互转换。纸张缺货按现行建单策略显示和阻断，不混同为永久“不适用”。

以上属于拟定文案，实施时按 [文案与确认](./ui-规范.md#文案与确认) 核对。页头不展示产品 ID、生成规则等内部机制；必要后果集中放在实际操作的复核位置。

## 4. 典型流程与生效时点

### 4.1 空白封、彩印只增加适用规格

纸张详情 → 选择业务路线 → 勾选该路线已支持的规格 → 保存适用规格。

保存成功后，该搭配可进入新的建单选择。没有生效价格时进入现有人工核价流程，不生成默认单价。此操作无需先建立调价草稿。

### 4.2 空白封从价格表增加规格并录价

空白封单价 → 发起调价 → 在“待设置”的格子设置适用规格并录价 → 保存 → 审阅变更 → 发布。

沿用当前“目录即时生效、价格发布生效”的边界：保存时关系与内部产品关联立即生效，单价只写入草稿。保存复核需明确列出新增适用规格以及价格尚未发布这一实际后果；放弃调价不会撤销已保存的适用关系。

该复合保存必须在同一数据库事务内完成关系、内部产品、草稿价格和审计；任一步失败全部回滚。单独维护适用关系则使用独立、明确的保存动作。

专版新增纸张：保存物料 → 按现行缺省策略进入专版纸张选项 → 如需自动加价，发起调价并维护专版纸张加价，基础阶梯仍由规格产品共用；不生成纸张专属规格产品。冰白纸即使补了加价行也不改变管理员核价策略。

彩印新增适用关系：选择纸张及已支持彩印规格 → 保存 → 在彩印阶梯页面发起调价并维护数量档位，另按需维护加烫金价 → 审阅发布。关系保存与价格发布的边界和空白封一致，金额含义保持彩印原规则。

### 4.3 销售建单

沿用已有表单顺序选择业务路线、纸张、克重和规格。按路线关系及专版缺省行为提供选项；空白封和彩印解析具体纸张规格产品，专版解析共用的规格产品并独立校验物料身份。销售无需选择或填写产品组合名称。

允许生产但缺价格可进入现行人工核价；明确不适用按规范化文本拒绝，无论是否提供产品 ID 或配置外说明。空白封/彩印待设置不列入标准选项，但合法自定义纸张、改尺寸等沿用既有人工核价流程。重复身份继续按现有解析规则处理，不任取第一条；专版无显式关系按 §3.1 处理。手工成交价继续遵守原权限、原因与审核规则。

### 4.4 改单：历史重算与新准入分开（N1，业主已拍板 2026-09-20）

原订单中未切换产品/规格的已有款式重算、模板款式本身重算以及取消结算属于历史，不新增关系准入校验。切换目标产品/规格，以及 `operation=ADD` 新增款式均属于新准入；新增款式即使原样复制 `templateItemId`、没有 `targetProductId`，也必须校验。已禁用组合拒绝新增，提示改选其他组合；不因此阻止模板原款式自身的历史重算。

界面可选目标过滤与服务端 `resolveProposedChangeCatalogIdentities` 对目标解析后的校验都要覆盖；但不能把新增款式校验只挂在目录读取上。现有 `needsCatalog` 只判断目标 ID 是否提供，无目标的 ADD 会返回 `catalogIdentity: null`。必须先将模板事实与变更合成为新增款式的最终路线、纸张、克重、规格，再独立调用 §6.1 文本准入判定。

在改单预览、申请保存、管理员审批应用三个入口的事务中复验新增/切换的最终事实，防止申请后关系已禁用仍被审批通过；混合改单逐款标记语义，不把整个订单一律当历史，也不把所有原款式一律当新准入。批准前失败不得留下新增款式、变更金额或部分审计。

## 5. 建议数据结构

以下名称仅为设计建议，正式 schema 与 SQL 需在实施时审查。

| 数据 | 建议处理 |
|---|---|
| 纸张 | 复用 `Material`，以物料 ID 加明确克重事实识别，不另建重复纸张库 |
| 规格目录 | 身份包含路线适用范围、规范计价名、宽高和产品结构；首期每路线单独登记，禁止只按规范名去重；显示名与计价键分字段 |
| 空白封、彩印关系 | 关联唯一物料和路线规格；对外准入判定键为“路线＋规范化纸张名/克重＋规范化规格键”；允许或明确不适用，无记录表示待设置，保留配置外人工流程 |
| 专版纸张准入 | 以“专版路线＋规范化纸张名/克重”约束身份唯一；物料 ID 是消歧后的关联而非绕过文本校验的键；无记录继承现行默认可用规则，多值/重复身份按 §5.3 处理 |
| 专版规格映射 | 规格映射到原 `CUSTOM_FLAT_FOIL` 产品；多张纸共享规格产品，不写纸张专属 `Product.paperType` 或 `paperMaterialId` |
| 内部产品关联 | 空白封、彩印的每条允许关系解析唯一产品；专版先判断纸张准入，再解析规格产品；所有旧 ID 保持不变 |
| 价格 | 保留版本模型与既有 `productId` 关联；真实取价键仍来自 `triggerCondition` 的规范化文本、数量和路线规则，不改为按产品 ID 取价 |

克重若仍来自纸张名称或规格文本，迁移必须解析并校验一致性；不能只靠界面名称去重。若一条纸张物料不能唯一表达一个克重，先记录异常，不生成不确定的适用关系。

### 5.1 文本计价键必须同源生成（审查 §0）

产品字段 `paperType / weight / specification`、规格目录计价键、规则 `triggerCondition.paperTypes / specifications` 必须由同一领域服务从同一份受保护的来源生成。**这些字段是计价事实，不能只当展示或兼容文本。** 现有已发布规则不回写。

N4 核对范围限定为：**迁移范围内的启用产品，以及当前/计划生效价目中与该范围相关的启用规则**。对无 `productId` 的专版基准纸/加价，也按规范化文本识别是否关联该范围。不一致只阻止对应范围迁移/切换，不把停用旧产品、失效历史价目或无关旧写法作为全库日常调价的新增门槛。与本次改造无关的价格保存/发布仍执行原校验，不受这份迁移差异报告阻塞；本次新写入的错误事实仍须由其请求校验拒绝。

测试逐项断言 `canonicalizeCreateOrderPaperFact` 得到的名称与克重相等，`canonicalizeCreateOrderSpecification` 得到的规范名逐字相等，款式侧与规则侧分组一致。规格 ID 或产品 ID 相同不能代替这些断言。

专版是显式例外：规格产品原本不声明纸张，继续保持空字段，不为了“三者相等”伪造纸张字段。纸张事实来自唯一物料，与专版基准纸/加价规则按同一规范化函数对齐；规格则由目录、规格产品和阶梯条件三方对齐。无加价不是身份不一致，仍按现行规则转人工。

### 5.2 分路线规格串生成（R4）

同名可能不同尺寸，同尺寸也可能不同结构。各目录条目保存审核后的 `productSpecificationText`；自动创建产品时原样赋给 `Product.specification`，禁止将规范名与一份跨路线尺寸表拼接。空白封沿用 `BLANK_SPECIFICATIONS.specification` 和 `addBlankPaperDraft` 的赋值方式；已有产品保留原规格文本，由目录保存映射，不批量重写已发布计价事实。

审查方开发库例子：空白封中号 80×115、大号 90×165；彩印中号 80×120、大号 88×165，规范名却分别相同。它们必须是不同路线条目。新建彩印产品的文本模板从已审核彩印目录条目取值；专版复用原规格产品。正式尺寸在阶段一重测，不把开发库例子写成所有环境的固定真值。

测试除了规范化文本一致，还要验证原样复制后的完整规格串、宽高、结构与目录相同；三条路线的标准尺寸款式经现有适配器仍为 `specificationConfiguration=CATALOG`，不能变成 `RESIZED`。

关系写入采用对应路线的业务键唯一约束、现有价格资料写锁和事务；并发重复请求不复制产品，失败可重试。新建单或改单时只解析，不临时创建产品或修改目录。关系决定新准入（含改单切换/新增），已发布价目决定自动报价，两者只有各自一份权威配置。

文本准入键与物料/规格外键必须保持同源。完整目录仍以 §5.2 的路线、规范名、尺寸和结构区分规格记录；明确禁用按 §6.1 的规范化键拦截，不能靠换别名、改实际宽高或省略产品 ID 逃过已禁用的同一组合。若同一路线同规范键映射出多个待独立维护的尺寸/结构身份，先列为待处理，不新增无法被文本判定唯一表达的细粒度禁用。

对于兼容关系外的其他产品，保留现有用途，禁止全表一刀切转换。多纸张、多规格的旧记录需要单独分析价格/BOM 引用，不能直接展开后把原价格和 BOM 复制给所有新组合。

### 5.3 专版多值与重复物料（N3）

采用仓库真实 `catalogPricingFactChoices`、克重解析及规范化函数枚举每条 PAPER 物料的身份，并记录来源物料 ID。某身份命中多条物料，或任一来源物料用一个名称表达多张纸时，该身份进入“待处理”；不能以启用优先、库存优先或数组顺序消歧，也不能禁用整条多值物料连带影响其他纸张。

对这些待处理身份，专版禁用控件与服务端写操作均拒绝，选项继续沿用现状；既有身份不唯一导致的报价失败也保留，不自动隐藏或修复。全部 PAPER 物料参与身份重复核对，启停/缺货另行判断，不以只看启用记录掩盖歧义。待资料整理并证明身份唯一且单值后，才建立准入记录；原有关联和历史金额不自动归并。

判定先读规范化身份上的明确禁用状态，再做唯一物料解析，不能通过换另一条同名物料绕过已有禁用。后续新建或改名物料若破坏受管理身份的唯一性，应在同一写锁下拒绝并提示处理重复资料，不能让禁用随 ID 变化失效。

跨路线副作用必须可见：为空白封/彩印新增或补资料而新建的有效 PAPER 物料，也会按现有专版缺省规则进入专版选项；这是当前 `addBlankPaperDraft` 已有行为。材料回填本身不静默创建缺失物料，零匹配先报待补资料；管理员确需新建时，在相应保存复核说明其专版可用性变化。这一点随“新纸张默认准入”一并供业主决定，未拍板前保持现状。

## 6. 服务端与历史保护

- 纸张修改保留 `material:manage`；规格目录读取和适用关系维护使用现有 `dict:product:manage`；价格操作保留 `dict:price:manage`。复合操作需要对应权限的交集，既不能因按钮隐藏而放松，也不能让自动维护产品扩大调用者权限。
- 保存和发布重新读取纸张、规格、关系、草稿状态与版本；过期编辑拒绝并给出刷新入口。必要资源归属及新准入可用性在领域层复验。
- 金额继续使用 Decimal，单价沿用四位小数及现行合法范围，计算与舍入不变；缺价不取零或其他规格的价格兜底。
- **R2 选择备选方案：关系禁用独立于 `Product.isActive`。** 保留产品当前/计划价格引用保护及草稿产品有效性校验，不绕过 `setProductActive`。禁用关系只改变新准入（含改单切换/新增），不写 `Product.isActive=false`，也不修改生效价；草稿查询继续读取完整产品和规则，不能将禁用关系误映射成停用产品。
- 选择理由：产品身份被历史/BOM/价格共享，专版尤其多纸共用规格产品，禁用一张纸不应停用所有纸的规格；删除专版必需规格阶梯还可能破坏价目投影。代价是 §7 消费方必须完整接入，且 §8 禁止回退到忽略关系的旧版本。本方案不选择“先移除价格再停用产品”。
- 禁用、重新启用关系均记录审计与实际影响。重新启用时若仍有生效价，复核展示该价格；无生效价则待核价，不新建价格版本。关系操作前后规则集 SHA 应不变；随后仍须能保存并发布一次合法调价草稿。
- **准入校验放在入口层，不进入共享报价适配器。** 创建、内外销预览、草稿首次提交、打样提交、工作台，以及改单中的切换目标和全部新增款式均须校验，先于人工核价分支；未改动历史款式及取消结算不加关系准入。
- 改单目录用于选择新目标，确实属于新准入；不再以“改单调用”为理由禁止通用目录过滤。过滤在通用目录函数还是调用方实现可由实现阶段决定，但规则管理/历史读取不得被误滤，且不能用目录过滤代替 §6.1 对无 ID、无目录读取路径的独立文本判定。N1 的模板原样复制尤其不得依赖 `needsCatalog`。
- [纸张退役记录](./audits/2026-09-17-retire-120g-paper.md) 和 [现行决策](../DECISIONS.md) 已记录的“停用物料影响部分历史重算”问题单独保留，不借本次目录改造默默放宽或扩大阻断范围。
- 纸张、规格、关系及价格操作记录变更前后值与操作者。已应用迁移不修改、不删除，只增加前向迁移。

**R5 纸张身份修改保护**：保留现有产品外键保护，并扩展到“任一适用关系（含禁用记录）引用该物料”或“当前/计划生效加工费规则的 `triggerCondition.paperTypes` 引用了其规范化纸张名与克重”。任一命中即拒绝改名、改克重或改分类，改用新增纸张流程；不能只查 `Product.paperMaterialId`。在与调价相同的写锁内读取旧身份、规范化全部候选文本并检查引用；遇到无法解析的潜在引用拒绝修改并列为待处理，不按无引用放行。既有受保护产品也不能通过直接改字符串绕过。

仅新增关系映射不等于可以随手给旧产品补写 `paperMaterialId`：共享适配器会因此新增停用/缺货检查（`create-order-quote-facts-adapter.ts:373–383`）。首期旧产品外键原值保持不变，纸张 ID 保存在新关系中；另行补外键须通过历史重算与报价对比门禁。

### 6.1 文本准入判定与执行顺序（N2）

输入为服务器复核的业务路线、规范化纸张名与克重、规范化规格键，使用已有 canonical 函数与受保护目录映射；产品 ID、物料 ID 只作交叉校验，不作为必须提供才执行准入的条件。专版查纸张级准入，其余两条路线查纸张规格关系。已禁用键优先于后续人工核价、无产品、改尺寸或配置外分支判定。

| 判定结果 | 入口行为 |
|---|---|
| 明确不适用 | 拒绝，提示选择其他纸张或规格；带 ID、无 ID、`manualPricingReason` 配置外说明均不能豁免 |
| 空白封/彩印待设置（无记录） | 不作为标准选项；合法自定义纸张、改尺寸和既有配置外人工核价路径照旧，不因无记录一概拒绝 |
| 专版无显式记录 | 沿用 §3.1 现行缺省规则，继续验证纸张身份、缺货、退役和计价；不是直接保证自动报价 |
| 已允许 | 继续执行既有权限、产品/物料交叉校验及报价逻辑；允许不等于有价 |
| 专版身份多值或重复 | 不开放新的禁用操作，既有选项与身份解析失败按 §5.3 保持，不自行修正成允许 |

缺失、冲突或不合法的纸张/克重/规格继续按现有输入校验处理，不能靠删字段绕过已知禁用。没有产品 ID 的合法自定义输入仍可进入原人工流程，不能为满足新准入强造产品。先执行既有退役校验与本判定，再进入人工核价和自动报价分支；不得在客户端自行把明确禁用改写成待核价。

改单单独按操作语义提取需要校验的最终款式：切换目标取服务端解析后的事实；ADD 合并可信模板与本次修改后必查，不以是否有 `targetProductId`、是否读取目录或是否人工定价为条件。未修改身份的原款式不在此集合中。申请、预览和审批均重读当前关系；关系写入与审批/提交读取沿用现有读写锁和事务，不能沿用浏览器或申请时的过期准入结论。

## 7. 分阶段实施

### 阶段一：依赖盘点与迁移预检

产出可重复执行的只读报告：三条路线的产品、纸张、规格、价格、BOM、历史工单引用及重复身份；核对 SQL、seed、维护脚本、动态入口和外部 API 消费方。

报告区分“可唯一映射”“无物料关联”“克重或尺寸不明”“重复产品”“多值规格/纸张”“价格与目录冲突”“其他用途产品”。按路线统计 `paperMaterialId` 为空的产品数和占比，并区分专版规格产品按设计为空与空白封/彩印待映射；不能把无外键视作极少量异常，也不能全数排除。补充 PAPER 多值名称物料条数、规范化身份重复组数、每组来源物料和受影响路线；专版按 §5.3 分桶，空白封/彩印明确区分唯一可用、唯一但停用/缺货、零条、重复及退役。

正式库重新编写并执行三类只读预检：产品按路线统计总数、启用数、空纸张/空外键和多值字段；PAPER 物料统计启用、缺货、规范化身份重复；加工费规则按组统计产品绑定、停用产品及文本纸张引用，区分固定业务时刻的生效与计划版本。审查附录 SQL 可作起点，但不能只用 `effectiveTo IS NULL` 代替完整生效区间。记录查询时间、基线 SHA、目标环境和实际规则版本。审查方开发库出现“57 个产品全部无纸张外键”等结果，仅说明必须考虑文本回填，不代表正式库也如此。本次没有访问任何数据库。

空白封/彩印文本映射步骤：按现有函数解析纸张名与克重 → 在 PAPER 物料中找规范化身份完全相同的记录 → 恰好一条才建立关系；零条记待补资料，多条重复即拒绝，不优先取启用项或第一条。名称和显式克重冲突、多值文本、尺寸无法唯一解析均停止该项回填。专版规格产品不补纸张字段，纸张准入从有效物料读取。无外键本身不是删除或自动归并依据。

### 阶段二：建立规格目录和适用关系

新增 schema 和前向迁移；在隔离库验证 fresh DB 和存量回填。空白封、彩印按阶段一唯一文本匹配建立关系并保留原产品 ID；不修改旧产品外键及字段。规格按路线、规范名、尺寸和结构映射，不能只按名称去重。停用记录不直接推断为物理不可生产。

专版按 R1(a) 回填：从现有专版规格产品建立规格映射；从 PAPER 目录按规范化纸张身份建立准入记录或保留缺省继承，不从空白 `Product.paperType` 推导纸张。唯一单值才关联物料；多值、重复身份标待处理，保留旧选项且禁用写入口不可用。比较切换时旧目录与新目录展开后的“纸张规范名、克重、规格、产品 ID、可选/禁用状态”集合；全部一致才允许切换。新增纸张继续继承旧默认，含从空白封/彩印管理入口新建的物料，不因未生成关系记录而消失。

新旧解析并行比对但仍仅由既有路径返回结果，记录差异；未消除的差异阻止对应范围切换，不静默回退。不要长期保留两套可写配置。

阶段完成条件：关系与选项解析一致、§9.1 可执行对比门禁通过、规则 SHA 与历史引用/快照不变。按 §5.1 限定的启用产品/启用规则范围核对；异常项明确处置或使受影响范围保持旧路径且不能开放该范围的关系禁用。其他范围和无关日常调价不因这些异常被阻塞，不带未解决差异切换对应范围。

### 阶段三：新管理入口与受控切换

交付纸张适用性、只读规格目录、分路线价格入口及同源领域服务；空白封先行，再覆盖专版和彩印。旧编辑入口停止直接修改已切换范围的组合事实，只导航到对应新入口。纸张身份引用保护必须先于新管理入口上线。

§7 阶段一表内每个消费方都有明确读取语义与回归证据；新准入（含改单切换/新增）、历史重算、规则管理三种用途不能误用同一份过滤结果。BOM 新目标选择与历史读取分别验证。关系禁用功能最后开放，必须等受影响路线所有准入入口（含无 ID、人工核价、无目录读取的 ADD）完成服务端文本校验；仅完成前端过滤不算切换完成。

阶段完成条件：用户可通过新页面完成原有维护任务，服务端只有一套有效写入口；缺价分支仍可用，所有既有路线均有可用维护入口。

### 阶段四：撤下旧菜单与兼容收尾

三条路线和其他已发现的管理用途都完成替代后，移除“可建单产品组合”日常菜单。旧列表、创建、详情链接按上下文导航到新入口；历史引用仍可查看，无法映射的链接给出恢复入口，不猜测映射、不裸露 404。

撤下旧写接口前再次核对外部消费方，必要时保留经过授权的兼容适配。保留 `Product`、价格关联和历史记录；是否进一步去除底层产品模型，另行评估。

## 8. 发布与回退

采用先扩展、后切换的部署顺序；前向 schema 在尚未启用新关系写入与禁用语义时保持旧读取兼容。正式数据变更需明确目标库、备份、迁移耗时及锁影响，并按项目发布门禁执行。

**R2 备选方案的发布限制：开放独立关系禁用后，不可回滚到不识别关系的旧版本，也不能关闭关系校验退回仅看 `Product.isActive` 的读取路径。** 旧版本会重新暴露被禁止的组合，这不是可接受的降级。

在开放禁用前，先部署并验证具备完整关系读取/入口校验的兼容版本，作为之后的最低回退版本。回退演练必须证明：禁用有生效价的关系在回退候选中仍不可用于新建、改单切换目标或新增款式，而历史原款式重算和调价仍可用。没有这样的已验证版本时，出现故障停止受影响的新准入操作并向前修复。

**N5 与候选目录切换流程对齐**：分两次发布。第一次部署支持关系读取和全部新准入校验的兼容版本，禁用写入口仍关闭；第二次才考虑开放禁用。开放禁用的那次发布，切换脚本保留的“上一版本”必须已经是上述能识别关系、兼容当前 schema 且经过演练的版本，发布记录需写明候选 SHA、上一版本 SHA、目录与验证结果。若上一版本仍是原实现，该次发布不得开放禁用开关，不能只留一个未部署过的兼容构建充当回退方案。

保留目录不等于可直接切回：现行 [发布记录](./audits/2026-09-19-production-release-09f1a1ca.md) 已明确旧目录可能仅作证据，[部署指南](./部署指南.md) 要求迁移后不能单独回退旧代码。最低回退版本兼容关系是新增必要条件，不替代 schema/数据兼容和运维恢复要求；涉及不兼容迁移时仍以前向修复为准。

回退可以关闭新增管理写入口，但关系读取和入口校验必须保留；不删除关系、产品、历史数据或回滚已发布价格。切换期间两套管理入口不能同时自由写入。尚未开启关系禁用的扩展阶段可以回退旧应用，须证明新目录写入仍被旧版本正确识别；不能将这一能力套用到切换之后。
