# 空白封纸张与规格价格管理

## 业务范围

管理员在「空白封单价」发起加工费调价后，通过「新增纸张 / 规格」选择已有纸张，或填写新纸张名称、克重，勾选适用规格并录入单价。新建同名同克重纸张时复用唯一现有记录；重复、停用、缺货或身份不完整的资料拒绝保存。

沿用 [加工费计费规则](./加工费计费规则.md) 的六种规格及尺寸：迷你封 50×80、方形 88×88、中号封 80×115、大号封 90×165、西封中号 80×120、西封大号 85×165。此入口不新增尺寸类型。纸张名称最多 60 字，克重为 1–2000 的整数；非负单价保留最多四位小数，零元与留空不同。

## 保存与生效

- 纸张主数据、可建单产品组合、草稿价格和审计在同一事务保存，使用现有价格写锁。提交携带草稿更新时间，过期页面、重复规格或任意一步失败均整体回滚。
- 新产品使用 `paperMaterialId` 关联纸张，完整规格与现有目录一致。唯一匹配的旧组合可以复用并补齐纸张关联，不重写已发布的产品计价事实或历史快照。
- 纸张和产品启用后，销售重新进入建单页即可选取；仍按工艺、规格、克重筛选有效组合。保存草稿不等于发布价格。放弃价格草稿不会删除已保存的目录，缺生效价的组合继续待核价；停用使用原有目录管理入口。
- 单价留空时只创建产品组合，不创建空金额基础规则；数据库的 `CustomerPriceRule_values_valid` 约束保持不变。销售可以选取该组合，报价进入待核价，不用零元或默认价格兜底。
- 有价格的格子在现有价格矩阵修改；为缺价格子补价或增加其他规格，再使用「新增纸张 / 规格」选择同一纸张。已有价格记录拒绝从新增入口覆盖。
- 「审阅变更 → 发布」继续执行完整规则校验、差异与高风险检查。自动报价只读当前已发布版本；旧工单保存的收费和价格快照不会因发布自动改变。
- 价格矩阵由规则与有效产品组合共同生成：有组合无报价显示「— 转人工」，不存在组合显示「不适用」。纸张不再依赖固定九行列表，列识别不再依赖产品编码后缀。

## 权限与资料保护

新页面与 Server Action 均要求 `dict:price:manage`、`material:manage`、`dict:product:manage`。客户端提交不信任纸张名称、ID、价格或草稿状态，服务端重新读取校验。

已用于建单产品的纸张不能直接改名称、克重或分类，以免纸张主数据与产品、报价身份脱节；使用新增纸张配置新组合。是否启用、缺货状态等仍由原有目录流程管理。

本次不修改 schema、已应用迁移、价格发布协议或历史订单金额；不把内部编码放到新增表单。

### 改造前后真实入口对比

`scripts/maintenance/compare-paper-specs.ts` 提供采集和比较两种模式。采集调用所选源码版本的真实建单目录和 `calculateCreateOrderQuoteFromCatalogInTx`，保留完整目录/禁选状态、规范化输入、报价分项及金额、人工原因、加工费展示。连接串必须显式传入；事务是 `REPEATABLE READ READ ONLY`，不会写目标库。金额保持字符串；已有输出文件拒绝覆盖。

准备一个本地 JSON 数组（不提交业务数据）：每项为 `{ "id": "唯一用例名", "coverage": "standard", "facts": { ... } }`。`facts` 字段严格按 `scripts/lib/paper-spec-comparison.ts` 的 schema，包括 items、packagingGroups、isSfCollect、shipments；产品、纸张及工艺必须是目标数据中的真实 ID/事实。至少四例，coverage 必须覆盖 `standard`、`missing-price`、`zero-price`、`four-decimal`，且 items 合计覆盖三条计价路线。零价和四位小数必须真实命中空白封报价行，标准例的规格必须判为 CATALOG；缺价例必须产生 NOT_FOUND 人工原因，否则采集失败。

在已独立可用的改造前源码目录、当前源码目录分别启动新进程；不得临时复制仓库、伪造历史基线，或用同一套当前代码冒充前后版本。启动前将 `TSX_TSCONFIG_PATH` 指向本次源码目录，确保 `@/` 路径别名也从该版本加载。工具拒绝 lib/generated/prisma 有未提交修改的采集源。以下占位路径/连接串需替换为明确授权的本地目标：

```bash
TSX_TSCONFIG_PATH=/absolute/before/tsconfig.json node --conditions=react-server --import tsx /absolute/current/scripts/maintenance/compare-paper-specs.ts --mode capture --source-root /absolute/before --database-url 'postgresql://USER:PASSWORD@HOST/DB' --at '2026-09-20T00:00:00.000Z' --cases /absolute/cases.json --out /absolute/before.json
TSX_TSCONFIG_PATH=/absolute/current/tsconfig.json node --conditions=react-server --import tsx /absolute/current/scripts/maintenance/compare-paper-specs.ts --mode capture --source-root /absolute/current --database-url 'postgresql://USER:PASSWORD@HOST/DB' --at '2026-09-20T00:00:00.000Z' --cases /absolute/cases.json --out /absolute/after.json
node --conditions=react-server --import tsx scripts/maintenance/compare-paper-specs.ts --mode compare --before /absolute/before.json --after /absolute/after.json
```

两次采集必须使用相同数据、固定报价时刻与用例；产品/分类/物料/工艺/价目版本及规则的摘要必须一致。比较只忽略源码版本与采集时间等 provenance，其余差异输出字段名并返回非零退出码；数据变动不能被当成代码回归对比通过。输出包含业务目录及价格，请留在受控本地路径，勿提交仓库。操作产生的数据变化由 E2E 另验，不能混入同数据基线。

批次 5 的离线工具测试与用例收集不构成真实数据库验收：只有实际前后采集一致及隔离库 E2E 通过，才能关闭 S10。
