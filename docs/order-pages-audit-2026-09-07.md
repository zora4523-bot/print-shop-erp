# 工单页面与功能层审查（2026-09-07）

范围：管理端、销售/客服、师傅端的工单创建、列表、抽屉、详情、编辑、变更申请、审批核价、发货、打印/PDF、导出及其 Action/领域/查询契约。此记录描述当前代码与开发环境验证，不代表生产历史数据全部完备。

## 已确认并修复

| 问题 | 原因与修复 | 主要证据 |
|---|---|---|
| 包装说明混在基本资料，易被当成装袋配置 | 保留历史字段，统一为选填“包装补充说明”；创建和编辑与分袋事实放在一起，管理/销售/师傅展示口径一致 | `EditOrderForm`、`OrderForm`、`OrderSavedPackaging`；真实创建/编辑测试检查文字持久化且包装、分货和金额不变 |
| 销售详情缺少包装组、每袋组成与实际袋数 | 扩充销售专用 select/DTO，增加包装明细；不传内部规则、工资和成本 | `sales-detail-query` 显式映射及权限/字段泄漏测试，销售详情六视口明暗门禁 |
| 外部工单可在编辑时清空名称 | 表单必填与领域层非空校验同时补齐，依据工单结算类型判断 | `updateOrderFields` 空值/空白/正常名称/历史局部更新测试；浏览器必填测试 |
| 客户关联与客户简称/收货信息关系不明确 | 编辑时保存原资料，提供明确的采用动作；主地址采用后重置省份确认，不覆盖其他配送票 | 浏览器验证简称、姓名、电话、地址显示与提交事实一致 |
| 销售与客服修改入口遗漏待工厂确认、已驳回 | 详情页复用共享修改状态集合；待审批锁定与编辑页、设计领域守卫对齐 | 详情真实渲染测试、共享状态测试及 Action/领域权限测试 |
| 完整包装仍被打印提示“包装要求未填” | 根据真实分袋事实判断；说明为空且包装完整时显示“见分袋明细”；历史缺失资料继续提示 | 打印 HTML 边界测试与既有打印像素/PDF门禁，未修改截图基线 |
| 发货领域查询反向引用 UI 模块 | 将纯可用性规则和 DTO 移到 `lib/order/`，保留 UI 兼容导出 | 全量类型检查及发货条件/Action/领域回归 |

## 其余检查与保留边界

| 页面/功能 | 检查结论 |
|---|---|
| 列表、筛选、抽屉、批量操作 | 列表采用精简 DTO；地址和可编辑费用由按版本匹配的抽屉查询加载；本次不改变已调整的列表布局及批量逻辑 |
| 基本资料保存、配送更正 | 有权限/所有权、状态白名单、待审批锁定及 `expectedEditVersion` 防覆盖；逐票归属、已发货锁定和主地址同步继续在事务内执行 |
| 款式修改、审批计价 | 基础保存不写款式/袋数/费用；变更仍走独立申请、版本校验、报价预览和事务审批；已有包装组无法表达的新增款式继续拒绝，不能猜测包装 |
| 费用、顺丰到付、发货、结算 | 保留专用金额命令、Decimal 计算、价格版本与状态校验；文案修改不重写已确认/已结算快照 |
| 设计文件、师傅工序及报工 | 设计文件修改沿用草稿和待审批守卫；师傅权限及工序事实不因资料展示修改而放宽 |
| 历史兼容与导出 | 不删 `packageRequirement`、SQL、Prisma 字段或已应用迁移；CSV 和纸质栏名保留，兼容外部消费者 |
| 页面中的 E2E 空工单 | Dashboard 测试夹具只建工单头，缺款式/配送并非创建流程丢数据；继续显式显示缺失，不自动补造业务数据 |
