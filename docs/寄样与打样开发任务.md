# 寄样与打样工单开发任务

## 任务状态与已确认口径

本计划已实施。当前实现与验证范围见下方「实施记录」；用户于计划提交后授权开始开发。
调查基线：2611e098；分支 codex/memory-after-pr19；开始时工作区及暂存区干净。

用户已确认：

- 销售工作台当前工艺选择区域增加「寄样品」「打样」入口，外部销售可使用。
- 寄样品应收 = 快递费 + 包装费；包装取最新配置，默认最小规格。
- 打样由管理员直接填写整单总价，该金额包含整单应收，不再另加包装费、快递费或普通加工费。
- 管理工单列表展示「打样」胶囊标签；沿用现有 UI、权限、金额及审计规范。

规划默认：寄样品发送已有实物，免生产加工；打样保留真实生产工艺和生产任务。首版每单只允许一种用途，不混普通生产和样品用途。寄样品数量必须真实记录，不能伪造数量 1 来获取最小包装档。若现场履约方式不同，在实施对应流程前补齐业务口径。

## 数据与计费设计

### 1. 工单用途

建议新增 Order.purpose 枚举：STANDARD、SAMPLE_SHIPMENT、PROOF，旧数据默认 STANDARD。
保留 kind 的 NORMAL / REWORK 语义，避免混用返工、用途和工艺。新增工单用途与标签映射集中维护。

寄样不需要虚构 PARTIAL/FULL/PRINT 工艺；输入用用途判别联合区分寄样清单与生产款式。尽量复用 OrderItem、OrderShipment、OrderShipmentLine 保存名称、真实数量与分票关系，允许寄样款式不填生产参数。实施时检查所有必填枚举、数据库约束与消费方；现有 MANUAL_QUOTE 仍表示人工计价，不能借它把寄样误标成待加工核价。按用途明确免加工计价与免生产事实，必要的 schema 扩展写入新增迁移。

打样保留实际工艺/材料/数量供生产使用，但对客价格由整单人工核价决定，不运行普通自动加工费作为应收依据。

### 2. 寄样计费

- 新报价按报价时有效且已发布的运费及包装规则计算，建单事务复核报价版本。最新不包含草稿规则。
- 包装默认最小有效规格/档，不等于最低价格。现有数据是数量档，服务端按档位范围确定默认值；界面显示真实规则名称及价格。
- 不以虚假数量、零重量或硬编码金额触发默认。重量不足以估算时显示待核价；复用实际重量确认，不能默认运费为零。
- 可选择更大包装时，仅接受服务端发布的规则标识，服务端校验适用性和金额；保存选中规则、计价策略、数量与价格快照。
- 普通加工费、制版费、入袋/装盒加工费不自动计入寄样。若确需额外加工，应走明确业务变更，不隐式收费。
- 保留顺丰到付语义：到付运费不计入本单应收，包装费仍按规则计入。
- 多地址首版沿用当前整单包装计入主地址的口径；界面与明细必须一致，不擅自改为逐票最低档。若要求逐票独立包装，应单列计费变更。
- 已保存或已核定订单不随规则发布自动涨价；明确重新报价才创建新版本。

### 3. 打样整单人工核价

建议新增明确计价模式 Order.pricingMode：ITEMIZED / MANUAL_TOTAL；旧数据 ITEMIZED，PROOF 服务端强制 MANUAL_TOTAL。用途与模式由服务端校验组合，外部销售不能自由指定计价模式。

- 外部销售建单不填金额，整单显示「待核价」，不能显示 0 元或自动确认。
- 管理员核价表单新增单一输入「整单总价」，以字符串传金额，Decimal 运算、两位小数、上限与非负校验沿用现有规范。
- 复用 confirmedFee、settledFee、pricingStatus、priceRevision、OrderPricingRevision 和审计记录；不再新增平行的 sampleTotal 金额来源。
- 扩展核价命令为 ITEMIZED / MANUAL_TOTAL 判别联合；人工总价分支拒绝混传款式价格及额外收费，复核界面展示原金额、新金额、差额。
- 报价完整性必须覆盖整单，核价前不能以「不含人工项的小计」替代打样总价。若允许明确 0 元，必须经过管理员确认并记录原因；空值永远不等于 0。
- SAMPLE_FEE 只在实施明确统一费用账本表示方式后复用；不得在 totalAmount 上再加一个同额 SAMPLE_FEE，也不得将附加费用保存接口视为整单核价完成。
- 审计所有金额消费方：列表排序 effectiveCustomerFee、订单详情、打印、导出、外部销售账单、结算、销售台账与取消退款；统一读取现有有效应收解析逻辑并验证所有 fallback。
- totalAmount 与费用明细的既有含义必须保持一致。实施前沿当前汇总函数确定人工总价在既有账本中的唯一表示，补契约测试；不允许 confirmedFee 正确但账单仍按分项重算。
- 实际运费/包装可作为履约事实记录，但不能自动改变已确认总价。改价必须重新走管理员价格版本和审计流程，已结算工单遵守既有锁定/调整规则。

## UI 与流程

在原选择区域提供五个同样式入口：局部烫金、专版烫金、彩印、寄样品、打样。区域标题建议「工单类型」；前三项映射普通用途及对应工艺，打样后在下方选择真实工艺。数据层仍分开保存用途和工艺。

- 寄样：显示样品名称/数量、收件信息、包装选择、快递计费所需事实；报价卡展示快递费、包装费、合计。
- 打样：显示真实款式与打样要求；外部销售看到待核价，管理员在既有核价位置输入整单总价；不显示普通加工费加价比例。
- 类型切换时清除不适用的计费输入、报价令牌和缓存，不静默丢失已填写的公共收件信息；草稿恢复及工作台转建单保持用途一致。
- 管理列表工单识别区增加「打样」Badge；类型标签复用 Badge，生产状态继续用现有状态组件。建议寄样同样显示「寄样品」，详情和销售列表保持同一命名。
- 服务端列表查询显式返回 purpose，添加用途筛选时同步 URL 参数校验、分页、数量统计和索引评估。
- 复用现有表单、卡片、金额 formatter、错误反馈和核价复核层；遵守 [UI 文案与确认](./ui-规范.md#7-文案与确认)，不新建通用组件副本或重复确认弹窗。

## 必测验收场景

1. 外部销售分别建普通、寄样、打样单；本人可查看，他人订单不可越权访问。伪造 confirmedFee、价格模式、规则金额、角色或核价请求均被服务端拒绝。
2. 寄样最新已发布最小包装档 + 正确省份快递费；更大档、规则缺失/停用、规则发布竞争、缺地址/重量、到付、多地址、实际重量变动。
3. 寄样收货清单真实数量完整，无普通加工/制版/装盒费用，无生产任务/工资，仍能合法发货、完成、取消。
4. 打样销售提交后待核价；管理员输入 88.00，列表/详情/打印/导出/账单应收均为 88.00；填写或核定包装运费后仍为 88.00。
5. 打样空值、负数、超限、多余小数、显式零金额、重复提交、过期订单版本/价格版本、结算后改价、管理员并发修改。
6. 打样生产工艺、设计资料、下发/报工/发货能正常运行；核价未完成的阻断与已完成后的放行均经过真实状态机。
7. 普通自动报价、原人工分项核价、已有 SAMPLE_FEE 附加费用、返工和免收费单回归；不重复计费、不改变历史快照和台账。
8. 五入口键盘操作、焦点、44px 触控、六视口、明暗主题、overflow、axe；管理列表移动端胶囊不遮挡工单号/状态。
9. 真实浏览器提交覆盖：工作台 → 建单 → 管理员核价 → 发货/结算 → 列表及账单；写入测试只用独立可丢弃数据库。
