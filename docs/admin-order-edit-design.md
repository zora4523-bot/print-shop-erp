# 管理端编辑工单

参考用户提供的《编辑工单-管理端.html》，沿用 UI-SYSTEM 的语义色、控件与对话框。

## 页面与交互

- 正文最大 880px，固定编辑工具栏；款式、订单资料、收货、包装补充与费用按顺序展示。
- 常用款式字段直接填写；原值、修改数量、还原、新增款式的移除、保存前差异确认及离开提示围绕同一草稿。
- 生产参数、分货与混装明细保留在展开区。工单备注仍对可查看工单的销售可见，不冒充内部备注。
- 管理员关联的是外部销售账号；未更换时不提交该字段，保留停用账号的历史归属。
- 金额只显示已保存快照与服务端预览。修改后出现待核物流费时，在保存确认中逐票填写金额及依据，重新核价后随本次修改一起保存；输入变化会使旧预览失效。入袋费与款式加工费分列；缺少生产明细时显示未计价。版费默认 0，管理员可在制版明细中维护额外版费；其他费用与待核报价使用原有核价入口。
- 人工费用、物流核价、设计附件单独保存。有未保存的资料或款式修改时禁用这些写入入口，避免刷新覆盖草稿。

## 保存边界

`previewAdminOrderEditAction` / `saveAdminOrderEditAction` 仅允许 ADMIN，销售与客服保留原修改申请流程。

预览在回滚事务中校验资料、建立临时申请并调用真实报价。临时申请、日志及通知不持久化。保存重新取得工单锁，校验 editVersion、revision、workOrderVersion、priceRevision 与报价 token，然后在同一事务中保存资料、创建并批准款式/交期修改。失败全部回滚。原始报价、历史价格版本、账单与生产记录继续使用既有领域规则。重算后的款式金额与报价状态同步更新，报价快照保留数据库要求的 version=1 兼容外壳及纯引擎 schemaVersion=2 分项。仅资料修改不增加业务版本；款式/交期修改沿用现有审批的版本推进。

已有包装明细允许修改每包数量 `pack`（1～9,999,999 整数）。其唯一包装组的 `unitsPerBag` 同步投影到与创建工单相同的计价引擎；袋数和入袋费取整单报价结果。批准后同步 OrderItem、包装组明细和金额。进入生产后此入口禁止直接改分袋组成。

## 与演示稿的业务差异

演示稿中的静态价表、模拟上传、演示状态按钮及“审批通过后待落实”的二次应用不进入项目。真实审批已在事务中应用工单。

已有工艺/纸张替换、删除历史款式、给缺失全部原始记录的历史工单补造款式、含包装组工单新增款式，仍缺少项目领域层支持。本页明确显示限制并保留原始事实，不提供能点击却不落库的按钮。无包装组且有有效模板的工单可沿用模板新增款式；已有生产记录的原款式在本页锁定，生产变更使用原修改申请审批流程。

## 验证

领域测试覆盖事务共享、预览回滚、权限、过期版本、报价变更、日期与资料单独保存、审批失败回滚和包装数量投影。浏览器测试覆盖六视口、明暗主题、44px 控件、overflow、axe、差异确认、错误保留与放弃提示。真实 PostgreSQL E2E 覆盖创建到编辑、包装重算、过期页拒绝、历史金额保留与外部销售归属。
