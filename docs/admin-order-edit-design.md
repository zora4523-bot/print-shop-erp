# 管理端编辑工单

参考用户提供的《编辑工单-管理端.html》，沿用 UI-SYSTEM 的语义色、控件与对话框。

## 页面与交互

- 正文最大 880px，编辑工具栏跟随后台顶栏的实际高度吸顶；款式、订单资料、收货、包装补充与费用按顺序展示。订单资料、配送、包装补充使用同一个信息分组。
- 常用款式字段直接填写；原值、修改数量、还原、新增款式的移除、保存前差异确认及离开提示围绕同一草稿。
- 设计图和 CDR 入口直接显示，生产参数在“更多生产信息”弹窗中查看；分货与混装明细保留在展开区。工单备注仍对可查看工单的销售可见，不冒充内部备注。
- 正反面烫金使用与创建页相同的物料颜色目录，保留已选历史颜色，每面最多 3 色。纯彩印不开放烫金修改；彩印加烫金保留颜色选择。历史人工计价款式仅修改名称，不使用自动计价字段或作为新增模板。
- 管理员关联的是外部销售账号；未更换时不提交该字段，保留停用账号的历史归属。
- 金额只显示已保存快照与服务端预览。修改后出现待核物流费时，在保存确认中逐票填写金额及依据，重新核价后随本次修改一起保存；输入变化会使旧预览失效。入袋费与款式加工费分列；缺少生产明细时显示未计价。版费默认 0，管理员可在制版明细中维护额外版费；其他费用与待核报价使用原有核价入口。
- 保存前以底部 Sheet 展示差异与服务器重算金额，桌面最大宽 620px，移动端内容可滚动；失败保留草稿，保存中禁止重复提交与关闭，关闭后焦点返回保存按钮。
- 人工费用、物流核价、设计附件单独保存。主表单与独立费用表单互锁，费用草稿也计入离开提醒；各费用入口提供还原操作。上传与删除设计文件互锁，期间禁止关闭文件管理或操作工单；结果不确定时提示刷新核对，不误报成功。
- 返回、侧栏链接与刷新保护未保存输入；支持 Navigation API 的浏览器同时拦截同文档后退/前进，确认后继续原历史跳转，不插入重复历史项。旧浏览器保留链接和整页离开提醒，同文档历史跳转不在此兼容保证内。

## 保存边界

`previewAdminOrderEditAction` / `saveAdminOrderEditAction` 仅允许 ADMIN，销售保留原修改申请流程。

预览在回滚事务中校验资料、建立临时申请并调用真实报价。临时申请、日志及通知不持久化。保存重新取得工单锁，校验 editVersion、revision、workOrderVersion、priceRevision 与报价 token，然后在同一事务中保存资料、创建并批准款式/交期修改。失败全部回滚。原始报价、历史价格版本、账单与生产记录继续使用既有领域规则。重算后的款式金额与报价状态同步更新，报价快照保留数据库要求的 version=1 兼容外壳及纯引擎 schemaVersion=2 分项。仅资料修改不增加业务版本；款式/交期修改沿用现有审批的版本推进。

已有包装明细允许修改每包数量 `pack`（1～9,999,999 整数）。其唯一包装组的 `unitsPerBag` 同步投影到与创建工单相同的计价引擎；袋数和入袋费取整单报价结果。批准后同步 OrderItem、包装组明细和金额。进入生产后此入口禁止直接改分袋组成。

资料增量省略的字段（包括显式 `undefined`）保持原值，避免仅修改名称时丢失急单、交期或包装说明；主动清空与 `false` 仍正常保存。交期校验有效日历日期。费用和版费的独立写入同时刷新编辑页，避免页面继续使用旧快照。

## 与演示稿的业务差异

演示稿中的静态价表、模拟上传、演示状态按钮及“审批通过后待落实”的二次应用不进入项目。真实审批已在事务中应用工单。

已有工艺/纸张替换、删除历史款式、给缺失全部原始记录的历史工单补造款式、含包装组工单新增款式，仍缺少项目领域层支持。本页明确显示限制并保留原始事实，不提供能点击却不落库的按钮。仅无包装组且有有效模板的草稿工单可沿用模板新增款式；服务端同时拒绝非草稿的 ADD。已提交的新款通过新建完整工单录入，以便上传设计图及生产文件。已有生产记录的原款式在本页锁定，生产变更使用原修改申请审批流程。

遵守项目 44px 控件和现有后台壳，不以压缩点击区域换取逐像素一致。1440×1000 实测单款卡片从 439px 缩至 327px，HTML 对应卡片为 260px；393×852 下从 837px 缩至 697px，HTML 为 608px。参考稿和实际订单的款数、状态及文本不同，这些几何对照不能作为像素差异百分比。
