## 页面与判定口径

- 基准：`/orders/new`，见 [新建页](../app/(admin)/orders/new/page.tsx#L19) → [OrderForm](../components/business/order/OrderForm.tsx#L3328)。取字段最全的内部建单分支，并标注仅内部可录入的字段；业务员外部建单不以内部专属字段作为基准。
- 派生：`/orders/[id]/edit`，见 [编辑页](../app/(admin)/orders/[id]/edit/page.tsx#L64)。覆盖管理员 `AdminOrderEditor`、客服 `EditOrderForm + OrderChangeRequestForm`、业务员 `SalesOrderEditor + SalesOrderDetailView`。
- 编辑页装配的修改申请、文件管理、费用管理和配送组件，以及明确返回详情页使用的专用入口，均计入对应能力。展示历史值不等于具备编辑入口。
- 以同角色、未被待审批或终态限制的可编辑阶段对照。只展示“缺失”和“锁定但代码里找不到依据”；有明确原因的状态、权限、生产、目录兼容性限制不列为问题。
- “缺失”表示基准存在可操作入口，派生页及其配套提交结构没有等价入口；schema 未收字段本身不构成锁定的业务理由。只读历史展示与主动禁用的表单控件区别处理。

## 基准完整清单（核查范围，不是问题清单）

以下按 [createOrderSchema](../lib/auth/schemas.ts#L1925)、[orderItemBaseSchema](../lib/auth/schemas.ts#L1170)、[配送字段](../lib/auth/schemas.ts#L1642)、[额外地址](../lib/auth/schemas.ts#L1850)、[包装组](../lib/auth/schemas.ts#L1876) 逐字段盘点。自动派生字段也列入范围，但不凭其缺少独立输入框报缺失。

| 分组 | 全部字段或操作 | 基准入口与数据口径 |
| --- | --- | --- |
| 工单 | `customName`、`customerPartyId`、`customerRef`、`promisedDate`、`isUrgent`、`packageRequirement`、`remark`、`isSfCollect` | 工单名、包装说明、备注、到付为共用；客户、交期、急单见内部 `orderExtras`（OrderForm 3341–3429）。 |
| 主地址 | `receiverName`、`receiverPhone`、`receiverAddress`、`expressCode`、`destinationProvince` | 收货信息共用；快递代码内部可填；省份随地址识别。 |
| 主地址兼容收费字段 | `quotedWeightKg`、`shippingFee`、`packingMaterialFee`、`customerChargeOverrideReason` | schema 兼容字段，不等于当前表单允许人工填价；外部提交明确移除，见下文提交边界。 |
| 款式身份 | `fig`、`name`、`productId`、`pricingRoute`、`productStructure`、`specification` | 路线、规格选择派生目录产品及结构；`fig` 自动递增；内部可单独改款式名。 |
| 款式纸张尺寸 | `paperType`、`paperWeightGsm`、`actualWidthMm`、`actualHeightMm` | 纸张、克重、规格选择及自定义尺寸开关；实际宽高不是任意数字输入框。 |
| 款式生产信息 | `quantity`、`pack`、`crafts`、`frontFoilColors`、`backFoilColors`、`foilColors`、`foilTechnique`、`hasLocalFoil`、`lamination`、`printColors`、`isDoubleSided`、`isDoubleColor` | 数量、每袋数、正反面烫金、烫金方式、彩印烫金模式、覆膜；附加工艺仅内部；汇总颜色、单双面/色及彩印颜色按结构化选择派生。 |
| 款式补充信息 | `artworkVersion`、`plateGroupId`、`pricingGroup`、`manualQuoteReason`、`remark` | 内部建单可填，见 OrderForm 3430–3505。 |
| 款式兼容金额 | `unitPrice`、`fixedFee`、`suggestedSubtotal`、`priceOverrideReason` | schema 兼容字段，当前结构化建单不提供这些字段的直接金额输入框。 |
| 包装组 | `name`、`mode`、`actualBagCount`、`itemUnitsPerBag[]` | 单款装/混装及各款每袋数；组名默认空，组数和袋数随组成、数量派生。 |
| 额外地址 | `receiverName`、`receiverPhone`、`receiverAddress`、`expressCode`、`destinationProvince`、`quotedWeightKg`、`shippingFee`、`packingMaterialFee`、`customerChargeOverrideReason`、`itemQuantities[]` | 增加地址后填写联系人与各款分配量；金额兼容字段同主地址，不另算人工录价入口。 |
| 文件 | 待上传文件集合（图片、CDR）；关联款式、文件名、类型、大小和上传结果 | 经 `pendingDesigns` 与上传调用提交，不在 `items` schema 内；需计入上传、移除待上传文件，不能只看 create payload。 |
| 提交辅助 | `clientSubmissionId`、`nextItemFig`；报价 token、提交意图 | 幂等、编号与报价控制，不作为用户可改业务字段。 |
| 款式操作 | 增、删、复制、逐款修改数量；多款一次提交 | [add/remove/duplicate](../components/business/order/OrderForm.tsx#L1694)；无专门批量填值、批量删除或拖动/上下移排序入口。自动编号不是排序操作。 |
| 包装操作 | 单款装与混装切换、各款每袋数调整；随款式增删维护组成 | [包装回调](../components/business/order/OrderForm.tsx#L2155)。不把 schema 允许多个组误算为有任意增删组的 UI。 |
| 配送操作 | 增、删额外地址、修改既有地址各款分配量；主地址承接余量 | [多地址区域](../components/business/order/OrderForm.tsx#L3588)。无独立地址排序入口。 |
| 保存操作 | 本地草稿恢复/放弃、保存服务端草稿、提交建单、提交前查看报价 | 创建阶段动作，不要求编辑页再次“创建同一工单”；编辑保存及预览按派生页语义核对。 |

提交边界还核对了 [persistOrder](../components/business/order/OrderForm.tsx#L1515) 与 [外部 payload 清理](../lib/order/external-create-order-payload.ts#L7)，未将服务端拥有的费用或旧兼容字段当成缺失表单入口。

本轮未单列“锁定但代码里找不到依据”的项目：检查到的主动禁用入口有阶段、待审批、目录兼容性、生产记录或缺少唯一包装明细等代码依据。特别是工艺、纸张替换与已有款式删除，在 [AdminOrderEditor](../components/business/order/AdminOrderEditor.tsx#L1055)明确说明改变生产基础、通过新建工单处理；因此没有把这些受限能力混入缺失项。相同理由覆盖附加工艺、覆膜和烫金方式替换，不因其基准有输入控件就重复报告。
