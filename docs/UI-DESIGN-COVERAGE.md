# UI 设计覆盖与验证边界

本表回答两个不同问题：设计包对一个页面族提供了多少证据，以及当前实现经过了什么验证。它不把“共享组件已统一”写成“85 页均已逐像素还原”。整改任务、严重度和成本另见 [`UI-REMEDIATION-BACKLOG.md`](./UI-REMEDIATION-BACKLOG.md)，提交 `41abe65` 后的证据化对抗复审见 [`UI-UX-ADVERSARIAL-REVIEW-2026-08-24.md`](./UI-UX-ADVERSARIAL-REVIEW-2026-08-24.md)。

## 判定口径

- **A · 直接对照**：有当前选定版本的高保真或交互稿，并对主要区块、状态和窄屏行为做过实现核对。
- **B · 契约对照**：有线框或明确交互契约，已按结构与状态实现；不能声称像素一致。
- **C · 系统收口**：设计包只有页面族模式或推断，当前只验证共享组件、响应式和可访问性。
- **受保护**：已有生产视觉基线，未获单独授权不改。

设计冲突以 [`UI-SYSTEM.md`](../UI-SYSTEM.md) 的证据优先级为准。收费工作台采用“批次五”的现有 shadcn 皮肤，不采用早期 Industry 皮肤。

## 页面族覆盖

| 页面族 | 设计包页数 | 证据等级 | 当前实现与验证 | 尚不能声称 / 后续边界 |
|---|---:|---|---|---|
| Dashboard | 1 | A | 处理队列优先、跨视口几何/axe 候选截图 | 管理端尚无设计稿像素 diff 基线；分区错误隔离仍可细化 |
| 工单（含变更审批） | 5 | A/B | 列表卡片降级、批量选择与更多菜单、新建三段式/本地草稿/缺口清单、详情常驻动作/时间线、审批字段 diff | 批量排产已有 Action/schema，仍缺选择到兼容师傅/排产页的 UI 交接；批量导出/打印仍需各自契约，不能用假按钮代替 |
| 排产 + 师傅端 | 8 | A/B/C | 待排产可派/阻断、候选师傅卡、报工首屏与吸底操作；六视口明暗、touch、axe | worker 的我的工单/详情/工资缺原始实屏，属于契约收口，不是像素还原 |
| 价格与报价 | 9 | A/C | 收费工作台、数量阶梯和发布中心按最终稿；定价 fixture 有响应式/axe 门禁 | 销售报价、物流工作台和部分 fixture 缺实屏证据 |
| 账单与薪资 | 13 | A/C | 计件工资主屏、状态语义和首批结构化反馈已收口 | 除计件工资外，多数页面在设计包中是推断级；需逐页截图与状态 fixture |
| 主数据字典 | 21 | B/C | 共用列表/表单原语已存在；产品“被引用/停用影响”作为首个真实领域闭环 | 七类三页的稿是通用骨架且原图未逐页打开；工艺、账号、分类、往来单位、BOM、物料仍需真实引用查询与 L3 审计，不能复制假计数 |
| 采购 / 盘点 / 仓库 | 5 | C | 盘点已有并发冲突与部分成功契约，首批反馈层已迁移 | 设计包明确缺复杂作业实屏；仓库作业台和盘点信息架构需独立交互稿 |
| 外协 / 考勤 / 车间物料 | 7 | C | 状态语义、已有业务动作与跨视口门禁继续保留 | 只有模式契约；不能声称逐页视觉对齐 |
| 通知 / 系统设置 | 5 | B/C | 投递状态与后台任务分列；UNKNOWN 已送达/重发/忽略及审计闭环；原生弹窗已移除 | 通知配置与系统设置缺完整实屏；模板 L3 和其他设置页仍需逐项迁移 |
| CDR 汇总下载 | 1 | A | 禁用原因、环境提示、长任务回执、过期同条件重生 | 需继续保留真实 OSS/mock 两类环境验证 |
| 后台任务 / Pigsty | 2 | C | 状态语义与只读运维信息保留 | 只有契约；业务异常与纯技术指标的长期信息架构仍可继续拆分 |
| 认证 / 404 / showcase | 3 | B/C | 根错误恢复、既有登录/404、组件 showcase | 没有当前高保真实屏；登录限流语义不得为了视觉调整而改变 |
| 打印 | 1 | 受保护 | 8 个 Playwright 像素截图基线；固定 localhost origin 时通过 | 不代表 Web 全站视觉一致；任何打印变化须单独立案并由业主确认基线 |

设计包分组页数合计为 85；“85”描述范围，不描述证据深度。页面新增、拆分或路由别名不应在没有重新清点时直接改写这个数字。

## 视觉证据

| 门禁 | 性质 | 可证明 | 不能证明 |
|---|---|---|---|
| `tests/visual/order-print.spec.ts` | 像素截图基线 | 固定环境下打印布局没有非预期像素变化 | 管理端、师傅端或设计稿一致性 |
| `tests/visual/admin-responsive.spec.ts` | 六视口 × 明暗的几何、touch、axe 与候选截图 | 已列管理路由无定义内的裁切、溢出和严重无障碍问题 | 与 `.dc.html` 自动像素匹配 |
| `tests/visual/worker-responsive.spec.ts` | 六视口 × 明暗的几何、touch、axe 与候选截图 | 已列师傅路由满足当前响应式门禁 | 所有业务状态或实屏稿均已覆盖 |
| `/dev/showcase` | 人工组件检查 | 共享 token、状态、L2/L3 弹窗可目视检查 | 自动视觉回归 |

未经人工确认，不更新打印截图；管理端/师傅端若要建立像素基线，先固定 fixture、字体、浏览器版本、主题和 viewport，再由业主确认第一版 expected 截图。

2026-08-24 实际验收结果：管理端 36/36、师傅端 12/12、打印像素基线 8/8 通过；应用内浏览器另行检查 393×852 和 1280×800 的 `/dev/showcase`，无页面级横向溢出、无控制台错误，L2/L3 确认层的焦点回归和理由门禁正常。管理端/师傅端的结果仍是响应式与可访问性门禁，不应改写为 85 页的自动像素对照。

## 本轮已闭合与仍开放

已闭合的明确缺口：工单列表批量条/行菜单、变更审批逐字段差异、CDR 同条件重生、通知 transport/job 拆分与 UNKNOWN 人工决策，以及根路由错误恢复。

仍开放的高成本缺口：主数据各域真实引用影响、全部旧写表单结构化反馈、长任务统一回执、复杂页完整分区错误隔离，以及管理端/师傅端真正的设计稿像素基线。开放项的完成状态只能由代码、测试和视觉证据共同更新。
