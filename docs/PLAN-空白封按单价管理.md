# 空白封按单价管理，移除独立建单组合

状态：**方案，待评审、未实现**。代码核对基线：`16c5fc85`，2026-09-20。本次只改文档，未查询数据库、未删除数据、未调整价格。

## 1. 目标与已确认口径

业主已确认空白封没有免费供货业务，希望直接维护「空白封现货单价」，移除「可建单产品组合」及其重复配置。按本轮对话，将目标解释为：**当前生效的已发布单价大于 0，才允许该纸张、克重、规格用于新的空白封业务；0 或空白表示未启用。**

使用流程只保留：进入空白封单价表 → 填写或修改格子 → 保存草稿并发布。无需先创建组合、启用组合，再返回录价。

| 红卡 180g | 中号封 | 大号封 | 方形 |
|---|---:|---:|---|
| 示例单价 | 0.135 | 0.15 | 未启用 |

中号封 1,000 个的空白封费用 = `Decimal(0.135) × 1000 = 135.00` 元。机烫、制版、包装、物流仍各自按现有规则计算；这不是把整单费用简化成一个乘法。

本方案替代[上一阶段方案](./PLAN-纸张规格独立管理.md)中「产品承载空白封适用关系」「无价格也可启用、转人工」「保留空白封组合管理入口」的后续建设方向。上一阶段已完成的实现和测试是历史事实，不据此宣称本方案已经实现。

## 2. 范围与删除边界

**真正移除空白封的第二套配置来源**：新空白封不创建 Product，不读取 Product.isActive 判定能否建单，也不在后台偷偷自动生成组合。价格、可选规格和新单准入共同从生效价格规则推导；不再新建「适用关系表」或单独的启用开关。

| 对象 | 处理 |
|---|---|
| 「可建单产品组合」独立菜单、空白封组合增改/启停入口、纸张页勾选启用规格 | 移除；纸张页只管理基础资料并链接单价表 |
| 新空白封的产品记录、规则的 Product 外键依赖 | 停止产生；新订单明细 `productId=null`，保存完整业务事实与价格快照 |
| 空白封旧产品中已证明无引用、无运行时用途的记录 | 生成明确清单后清理；不批量按类别直接 DELETE |
| 有订单、历史价格、BOM、阶梯、审计或未确认外部引用的旧记录 | 作为只读历史关联保留，不参与新单销售配置；不改原 ID，不级联删除 |
| 专版、彩印等其他路线的产品资料与计价 | 保留业务能力；从独立组合菜单迁到「产品结构」对应路线的资料区，不套用空白封的正价准入 |
| 现行操作说明中的旧组合维护步骤 | 实现切换后删除或改写，统一指向单价表 |
| 已应用迁移、历史决策、审查与验收证据 | 保留并标明适用时期；不伪造历史，也不因关键词命中就删除 |

「移除组合功能」不等于删除整个 Product 表：该表仍承载其他路线及历史关联。分类、BOM、纸张主数据也不是重复的空白封销售启用状态，不能随菜单删除。

本次不扩大为专版/彩印计价重构、120g 数据清理、整单免费结算/售后/寄样政策调整；空白封规则的 0 不再代表免费供货。其他费用中的合法零额（例如顺丰到付、未包装、已批准费用处理）不受此规则影响。

## 4. 单价表：一个入口、一种可售判定

### 4.1 页面行为

- 行来自唯一可识别的纸张基础资料；列复用 `BLANK_SPECIFICATIONS` 六种规格。不从 Product 决定某个格子能否填写。
- 每个正常纸张的标准规格格子都可录价。取消「不适用」和「缺价转人工」的空白封销售状态，空白/0 显示「未启用」。配置损坏显示错误及修复入口，不能伪装成未启用。
- 新增纸张可以从同一入口完成，或选择已有纸张；保存基础资料不使其自动成为可售空白封。
- 清空原有正价格子会在复核中显示「发布后停止用于新单」。新增空格留空不生成记录；取消编辑不改变草稿。必须区分「字段未提交」和「明确清空」。
- 草稿仍使用现有保存、差异审阅、发布流程及版本检查；不另造启用审批。当前价、草稿价和预约生效时间明确区分。
- 修改价格继续要求 `dict:price:manage`；同一入口新建纸张额外要求 `material:manage`。解除空白封 `dict:product:manage` 的无关前置，不降低已有价格/物料权限；Action 与领域层均校验，BOM 继续沿用其管理权限。
- 纸张停用、缺货、120g 退役等现有保护保留；正价只是销售配置条件，不能覆盖这些独立资料限制。保留有价但资料异常的行供管理员诊断。

### 4.2 存储约定

复用 CustomerPriceRule 的 `STOCK_BASE / BASE / PER_PIECE`，不增加新价格表。

1. 新规则 `productId=null`；规范化纸张名、克重、标准规格由一处事实函数生成 `triggerCondition`，同源生成矩阵键、下拉选项和报价输入。不能把单独拼接的中文文本当第二套键。
2. 新编辑协议：正数保存为正价；现有格子清空或填 0 都保存 `amount=0`；空白新格不创建行。不向非空要求的 BASE 金额写 null。
3. 正常空白封草稿行保留统一有效结构，不提供额外 `isActive` 开关；销售状态从唯一生效规则的金额推导。读取旧 `isActive=false` 的规则时仍判未启用；克隆草稿时可规范化为 0，但必须在差异审阅中明示，原版本不修改。
4. 克隆空白封规则为新草稿时去除 Product 绑定及旧 `productCodes` 条件；仅在文本身份完整且等价时转换，歧义拒绝。不清空已发布规则的外键或改写其文本。
5. 金额沿用 Decimal、四位单价与原有舍入。负数、超精度、非法数字拒绝；重复键即使价格相同也拒绝，不取第一条。
6. 发布前校验收费类别、路线、规格、纸张身份和键唯一性。收费类别从既有收费配置解析，不能依靠第一条启用 Product；没有有效收费类别时要求补资料，不默建收费语义。
7. **正价格可以为零个。** 全部停售时仍可读价目及其他路线；不能因空白封无可售项让专版/彩印报价整体失败。保留结构完整的 0 值行不等于存在可售产品；若没有任何空白封行，投影也须表示空集合。重复/损坏规则仍报错，不能一律吞错。

新增迁移需核对 CHECK、区间排斥、发布触发器、只读版本保护等完整约束链：仅允许结构合法的 STOCK_BASE 无产品，按规范化键保护同版本唯一；保留非空白 BASE、彩印 null 金额哨兵和已发布不可变规则。应用写锁下的唯一性校验与数据库约束共同防并发，不能仅因 null 绕过旧索引就认为安全。

## 5. 新单目录、报价与正式提交

### 5.1 统一数据来源

空白封候选 = **当前时间生效的唯一已发布规则中，单价 > 0 且纸张可用的标准规格**。草稿、尚未生效版本、历史版本不进入候选。

同一读取事务、同一 `now`、同一价目快照产生选项和报价。首次正式提交及草稿/驳回重提再读取当前生效版本；填写后刚停售时，明确提示重新选择，不能沿用缓存。已受理订单的幂等复用（REUSE）返回原已确认结果，不因之后停售而拒绝，也不重新报价或重复写入。变价继续沿用原报价复核协议。

- 空白封选项使用纸张身份、规格键和价目上下文；客户端键仅用于选择，服务端重新解析。不得伪造一个看似 Product ID 的字符串塞进旧字段。
- 新空白封明细保存 `productId=null`、路线、纸张、克重、完整规格、尺寸、产品结构、工艺及既有价格快照。不是只存一个单价或规则 ID。
- 事实适配器为空白封建立独立的标准事实分支；其他路线保留既有 Product 解析。兼容旧请求的 Product ID 时，转换为同源文本后仍做新准入，不能信任旧 ID 或启用状态。
- 用户自由文本、配置外说明、手填金额、伪造产品 ID 都不能绕过空白封缺价/0 的新业务拦截。合法的专版、彩印、非标准报价能力按各自路线保留，不自动改路线来绕过。

### 5.2 必须覆盖的入口

| 入口 | 要求 |
|---|---|
| 管理员、客服、外销的创建与报价预览 | 共用空白封准入，前端和服务端同源；批量/多款逐款检查 |
| 内销旧草稿首次提交、外销提交、驳回后重提 | 未正式受理的业务仍按当前正价准入；不得复用过期允许结果 |
| 改单新增款式、增加规格、复制模板款式 | 无论是否切换目标，独立检查新增款式的文本事实；申请、预览、审批都不能绕过 |
| 现有款式切换纸张、克重、规格或路线 | 对变成的新空白封身份重新准入；只改数量与历史核算区别处理 |
| 复制/重做为新工单 | 当前规则准入，不继承历史豁免；不能靠带原 productId 通过 |
| 工作台、询价预览、打样的选纸与提交 | 涉及空白封时统一目录/准入；寄样、售后等原有结算政策不在此处删除 |
| 管理员完整编辑 | 以服务端读到的原款式比对新增/身份变更，不能让客户端自报「历史款」 |

主要消费方：[建单选项](../lib/order/create-order-options.ts)、[目录](../lib/order/order-item-catalog.ts)、[配置解析](../lib/order/order-item-configuration.ts)、[报价服务](../lib/order/create-order-quote-service.ts)、[建单](../lib/order.ts)、[外销提交](../lib/order/submit-external-order.ts)、[改单目录](../lib/order/change-request-catalog-query.ts)、[改单](../lib/order/change-request.ts)、[管理员编辑](../lib/order/admin-edit.ts)、[打样](../lib/order/sample-order.ts)、[工作台目录](../lib/workbench/catalog.ts)、[工作台报价](../lib/workbench/quote.ts)。还须沿这些入口检查表单、预览、序列化、缓存失效和查询/导出，不只替换一个目录函数。

## 6. 历史订单与停售：实施前要定清的规则

已经确认的边界：原历史款式不能因为新增款式准入而被当成新款拒绝；原样复制模板属于新增，必须检查当前正价。已确认金额、既有价格快照、审计及历史真实 0 值原样保留。

**当前代码并不是所有重算都沿用旧价。** 改单整单重算、取消已产量结算读当前价；因此不能只修改「0=停售」然后宣称历史单不受影响。

本方案建议以下策略，**尚需业主确认，未将其登记为已拍板**：

| 操作 | 建议计价/准入 |
|---|---|
| 历史展示、账单、已结算记录 | 原快照与已确认金额，不因发布而变化 |
| 原款式不换纸张/规格，按现行流程确需重算，当前空白封价仍为正 | 沿用现有重算取价政策，本次不全局改为锁原价 |
| 原款式不换身份，当前空白封价为 0、缺失或已停用 | 不收取「停售 0 元价」；只对空白封材料项使用该款式最近一次已确认且可验证的快照单价，按新数量计算，记录来源版本和原因；其他费项沿用原规则 |
| 原快照没有可独立确认的材料单价，或只有管理员整款总额 | 不从总价除数量猜单价；需有真实可执行的人工补核价/确认路径。取消流程目前遇空金额会报错，必须补齐再开放切换，不得只写「转人工」了事 |
| 新增/复制款式或切换身份 | 一律当前正价准入，不借模板历史价销售 |

历史上下文须由领域层依据已受理订单和明细 ID 确定，并受状态与所有权限制，不能接受客户端 `historical=true`。按上述建议，空白封历史同身份核算不因旧 Product 当前启停而拒绝；物料当前停用/缺货与核算的关系须随本项明确，不能顺带放宽专版/彩印。

这承接原有「历史重算是否忽略当前资料启停」待确认项。评审期间可实施独立基础改造，但**停售切换及历史重算分支在确认前不能上线**。不是把未定政策藏在共享适配器里默认选一边。

## 7. BOM、生产与其他路线：先替代依赖，再撤入口

### 7.1 BOM 的最小替代

空白封计价不需要 Product，但目前按产品估算用料是真实功能。只改为 `productId=null` 会让新单丢用料，不能接受。

- 在现有 BillOfMaterial 增加「空白封纸张 + 标准规格键」目标，复用现有版本、启用、明细和数量，不新增组合主表。纸张 ID 关联 Material；规格来自同一只读目录。
- 前向迁移增加两个可空目标字段、纸张外键与索引；把现有「产品/分类二选一」CHECK 扩成「产品/分类/空白封身份三选一」。空白封目标按纸张、规格、版本唯一，且每身份只能有一个启用版本。参见[现有 BOM 约束](../prisma/migrations/20260628013000_bom_material_usage/migration.sql)。
- 新空白封明细按纸张、规格直接查 BOM；BOM 表单的空白封目标选项来自纸张和标准规格，不要求已有 Product。BOM 不决定可销售性。
- 对已有有效空白封产品专属 BOM，预检证明唯一对应后复制为新身份目标，保留用量、基数和版本信息，记录来源与审计；原 BOM 和 Product 关联保留给旧订单。重复或冲突不能取最近一条覆盖。
- 分类回退也要迁移：在既有 Setting 机制登记一个仅供生产用料使用的 `blank_stock_bom_category_node_id`，保存有效的空白封默认分类 ID，由 BOM 服务直接读取，不运行时反查 Product，不参与价格或准入判断。预检只有一个既有分类来源时可作确定性迁移；多分类的现存身份先把实际生效用料结果转换为身份专属 BOM，未来新身份的默认分类须有明确选定结果，不能凭第一条产品猜。新身份专属 BOM 优先于默认分类 BOM；确无既有分类用料的环境可保持配置为空并显示未配置。Setting 指向的分类有引用保护，失效不能静默降为无用料。
- 迁移后的旧空白封产品目标 BOM 变为只读历史，BOM 表单、Action 和领域层都拒绝再为这些旧产品目标新建、改明细或启停；非空白目标维持原能力。旧订单仍按原产品专属/分类顺序读取原 BOM；新身份 BOM 的修改/停用不改变旧产品专属 BOM。现有共享分类 BOM 仍按原职责管理，不复制出第二套分类启停。迁移前后用料结果逐项比较。缺 BOM 继续显示缺配置，不产生零用量的假成功。
- 纸张身份保护扩展到新目标及文本规则：有价目/BOM/历史事实引用时不能通过改名、改克重或改分类破坏身份。保留现有重复纸张保护，不只查 Product 外键。

这里新增的是既有用料功能的目标字段，不是新的销售组合状态。若要求整表物理删除 Product，专版/彩印与所有历史关系还要另行重构，本方案不以此作为简化空白封的前提。

### 7.2 其他功能的去向

- 工单生产、打印、发货、外协、工资、应收等继续消费完整 OrderItem 事实和已有快照。对 `productId=null` 的新空白封执行真实流程验收，不以 TypeScript 可空推定兼容。
- 物流保持既有「结构、纸张克重、数量」算法；未知单重继续待核，不用规格面积自行发明重量公式。
- 专版/彩印的必要资料管理嵌入现有[产品结构页面](../components/business/rules/catalog/ProductCategoryCatalogPages.tsx)的对应路线区，保留权限、原允许字段、启停引用检查。其他非空白类别先清点实际入口与消费，不未经核实收窄为两类后删除能力。

- 旧 `/owner/rules/stock-skus`、`/new` 引导至单价表；旧详情按真实类别分流：空白封去对应纸张单价位置，其他路线去新资料区。旧书签、别名路由、鉴权和回执一起处理；历史详情通过订单读取，不重建一个「隐藏的空白封组合编辑页」。

## 10. 验收标准与尚待确认

### 10.1 可执行门禁

1. **无 Product 的完整业务**：新纸张只有正价规则，无对应 Product，发布后内部/外部可选、自动报价、创建、提交；新明细 `productId=null`，标准尺寸为 CATALOG，不转人工、不偷偷建产品。红卡例材料项为 135.00，其余费项逐项一致。
2. **0/缺价不绕过**：空白、0、无规则、停用规则不允许新业务；伪造 Product ID、配置外说明、管理员手填、旧页面、模板原样复制、重做新单均覆盖；已受理订单的幂等复用除外，必须返回原结果。
3. **草稿与生效时间**：保存/放弃草稿不改变销售选项；预约时间前后、撤销计划、并发发布、草稿版本冲突、提交期间停售或变价均按同一价目版本处理。补充「提交成功→停售→重放已完成请求」仍返回原结果且无重复写入，与旧草稿首次提交被拒分开验收。
4. **矩阵与唯一性**：无产品的空格可编辑；新格空白不写规则，已有格清空为停售；同纸不同规格/同名不同克重可用，别名同键/重复纸张/并发写同格拒绝；全部停售不阻断其他路线。
5. **历史真实链路**：既有正价与真实 0 值快照不改；改数量、改单整单重算、取消已产量结算、退款金额、缺快照人工核价可完成且无停售归零。模板历史原款不被新增准入误拦；不能用 mock 整个报价服务代替此验收。
6. **BOM 与下游**：原产品 BOM、分类回退、新身份 BOM 的用料数量前后一致；无产品新单真实生产/打印/发货/物流/外协/工资/账单流程覆盖，资料缺失明确报因。
7. **其他路线与权限**：专版/彩印前后报价和缺价人工政策保持；所有权、角色越权、直接 POST 旧 Action、120g、纸张停用缺货、文本身份保护不回退。
8. **数据库与删除**：fresh DB 完整迁移链；升级已有数据；新 SQL 约束、并发唯一、失败回滚；清理有订单/价格/BOM/阶梯引用时拒绝，绝不级联删业务记录；审计及旧链接完整。
9. **前后对比**：扩展[真实采集工具](../scripts/maintenance/compare-paper-specs.ts)，固定数据、时间和版本。正价案例所有费用逐项相等；预期差异仅为 0/缺价准入、无产品身份结构、已批准历史停售策略。不能继续机械要求旧 Product 选项数量相等；差异白名单逐例断言，不泛化忽略整个字段。
10. **UI**：价格表及纸张页六视口、明暗、键盘、触控、overflow、axe；旧书签和跳转；按[文案规范](./ui-规范.md)使用「未启用」、现有确认与回执，不暴露表名/FK等技术细节。
