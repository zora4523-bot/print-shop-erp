# 价格版本页布局调整

## 范围与依据

基线 `990ff4da93bfab79f545d0a900582922291699cc`。按用户确认的“版本选择 → 草稿摘要 → 变更明细 → 发布 → 历史”顺序重排；设计证据为 B 级交互契约，对照 `docs/ux-redesign/批次五 价格与报价 交互稿.dc.html` 与 `UI-SYSTEM.md`，文案以 `docs/ui-规范.md` 的“文案与确认”为准。

## 展示与操作

- 页面标题统一为“价格版本”，去除重复生效说明。加工费与物流费通过用途导航切换，URL 保留草稿选择；`purpose=logistics` 可直接查看物流版本历史。缺口工作区仍保留原有双用途核查。
- 草稿摘要显示当前版到草稿版、原因、更新时间及返回编辑。修改按收费项目分组，数量档位仍可定位到对应编辑项；单价显示 2–4 位小数，避免把 `0.325` 显示为 `0.33`。
- 1440px 起采用差异明细与 360px 发布栏，较窄视口上下排列；移动端使用分组明细卡片。价格右对齐，表格横向滚动限制在自身容器内。
- 无差异时不渲染发布表单，只显示一条中性结果。仅去重服务端明确返回的“没有价格或规则变化”诊断，其他真实校验错误及处理入口仍保留。服务器继续阻止零差异发布。
- 有差异时保留单层确认，主按钮沿用品牌样式，高风险区域使用警告色，真实失败使用错误色。发布影响只在确认区展示，预约时间和补充说明继续按需展开。
- 版本历史在审阅草稿时默认折叠，展开后按用途、价目系列和时间展示紧凑列表；计划版改期、取消及放弃草稿的原有确认流程继续使用。

本次不修改 Server Action、定价、事务、权限、版本锁或数据库迁移。发布仍提交原有草稿更新时间、高风险确认、生效时间与说明，并保留提交中锁定和冲突刷新恢复。
