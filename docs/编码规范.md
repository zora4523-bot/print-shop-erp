# 编码规范

本文规定 print-shop-erp 的代码分层、命名、格式化、计费边界、测试和真值文档治理。系统边界与提交流程分别见 [`ARCHITECTURE.md`](../ARCHITECTURE.md) 和 [`CONTRIBUTING.md`](../CONTRIBUTING.md)。

## 1. 基本原则

- 页面负责组合，Action 负责编排，领域服务守护业务不变量，纯函数负责计算。
- 权限、状态、金额和数据完整性必须在服务端成立；UI 的隐藏、禁用和确认框不能代替服务端约束。
- 同一概念只使用一套字段名、变量名和界面文案。
- 金额、薪资、库存、状态和历史快照采用 fail closed：输入或依据不足时明确失败或转人工，不猜测结果。
- 代码、数据库和既有测试只能证明当前行为，不能推翻已确认业务真值。
- 一个提交只表达一个目的；行为无关重构、缺陷修复、迁移和功能扩展不得混在一起。
- 工作区可能存在他人改动。开始和提交前检查 `git status --short`，只修改、暂存任务范围内文件。

### 2.2 冲突优先级

1. 范围更窄的已确认领域真值优先于通用规格。
2. 同一文档内明确标注“现行”“取代”或“已废弃”的新条款优先。
3. 已确认文档优先于代码、数据库当前实现和既有测试。
4. Schema 与迁移是当前存储事实；即使违反业务真值，也只能通过经审查的前向迁移修正。
5. 外部 API 已发布签名不得因内部整理而直接改变。
6. 同级真值冲突、规则缺失或文档疑似笔误时，停止实现并报告，等待人工确认。

## 3. 目录与依赖方向

| 目录 | 职责 | 约束 |
|---|---|---|
| `app/` | 页面、布局、Route Handlers、授权取数后的组合 | 不承载计费、状态机、薪资或库存算法 |
| `actions/` | Server Actions、权限、Zod 解析、领域调用、缓存失效和跳转 | 不直接拼接关键状态或财务写入 |
| `lib/<domain>/` | 领域规则、查询、事务、状态机、纯计算和基础设施适配 | 不依赖 `app/` 或 React 页面 |
| `components/business/<domain>/` | 领域组合组件 | 不复制服务端业务规则 |
| `components/ui-business/` | 页面状态、反馈和业务语义外观 | 不定义领域规则；从 barrel 引用 |
| `components/ui/` | 无业务语义的原子控件 | 保持主题、键盘和可访问性契约 |
| `hooks/` | 可复用客户端交互状态 | 不隐藏授权或服务端规则 |
| `prisma/` | Schema、前向 migration、seed | 不回写已应用 migration |
| `tests/e2e/` | 跨页面业务流程 | 使用专用开发库和可清理 fixture |
| `tests/visual/` | 响应式、axe、overflow、触控和打印门禁 | 未确认时不更新截图基线 |
| `scripts/` | worker、检查和受控维护脚本 | 不复制领域算法 |
| `generated/` | 生成产物 | 禁止手工修改 |

```text
app
├── components/business
│   └── components/ui-business
│       └── components/ui
└── actions
    └── lib/<domain>/ 服务与事务
        └── lib/<domain>/ 纯函数
```

下层不得反向依赖上层。Server-only 模块不得进入客户端 bundle。跨目录使用 `@/` 根别名；不要新建无领域归属的万能 `utils.ts`。

## 4. 命名约定

| 对象 | 约定 | 示例 |
|---|---|---|
| React 组件文件 | `PascalCase.tsx` | `OrderForm.tsx` |
| 领域文件 | `kebab-case.ts` | `external-sales-quote.ts` |
| 单元测试 | `.test.ts(x)` | `quote.test.ts` |
| E2E / 视觉测试 | `.spec.ts` | `order-create.spec.ts` |
| 变量、函数、字段 | `camelCase` | `quotedFee` |
| 类型、组件、类 | `PascalCase` | `QuoteResult` |
| 模块常量 | `SCREAMING_SNAKE_CASE` | `MAX_ORDER_ITEMS_PER_ORDER` |
| 布尔值 | `is`、`has`、`can`、`should` 前缀 | `canEdit` |
| 标识符 | `Id` 后缀 | `orderId` |
| 时间戳 | `At` 后缀 | `confirmedAt` |

领域词汇：

- 状态、对外词和驳回原因逐字取自 `工单变更与版本规则.md`。
- 工艺使用 `craft`；颜色事实使用 `frontColors[]`、`backColors[]`。禁止新增“色数”“面数”字段替代数组。
- 包装领域统一使用 `pack` / `packaging` 词根，界面使用“包装数量”或更具体的真值词汇；禁止“放数”。
- 金额三态目标字段为 `confirmedFee`、`quotedFee` 与两者均无时的“待工厂核价”；当前 dirty schema 草案虽出现字段，查询/API/UI 尚未采用该统一契约，迁移前不得靠重命名伪装完成。
- 内部枚举、规则 code、JSON key 和公式变量必须经集中映射转换为业务文案。
- 数据库字段、历史快照和对外 API 的重命名属于契约或迁移变更，不是普通命名整理。

## 5. 统一格式化

- 格式化函数放在 `lib/format/` 或明确领域目录。
- 禁止页面内重复 `Intl.NumberFormat`、`toLocaleString`、日期切片和地址拆分。
- 金额千分位、小数位、币种符号和“估 / 待工厂核价”由统一组件或 helper 产出。
- 上海用户显示日期使用 `formatDateShanghai` / `formatDateTimeShanghai`；表单和 URL 日历值使用 `formatDateInputShanghai`。
- 毫米尺寸由结构化数值统一生成 `宽 × 高 mm`。
- 地址解析只保留一个权威实现；调用方不得复制正则或行政区拆分逻辑。
- design token 不在业务页面新增魔法值；有 A 级证据或材料外观例外时登记依据。

## 6. Server Action 与领域服务

Server Action 按以下顺序执行：

1. 权限或 session 检查；
2. Zod 解析不可信输入；
3. 资源范围、状态、金额和并发不变量检查；
4. 调用 `lib/<domain>/` 服务或事务；
5. 失效必要缓存并按契约跳转；
6. 返回结构化结果。

字段错误必须定位到具体字段或款式。预期业务失败使用可区分结果，不吞异常，不向客户端暴露堆栈、连接串、密钥或内部 payload。

状态变化由领域状态机或事务守护。金额、薪资、生产和价目规则保存不可变快照；规则更新不得重算或覆盖历史。

## 7. 计费引擎纯函数边界

### 7.1 分层

| 层 | 职责 |
|---|---|
| 取数与持久化层 | 在事务内读取价目、版本和订单事实，调用引擎，保存结果、证据和快照 |
| 纯计算层 | 接收完整事实与规则快照，计算命中规则、逐项金额、舍入、人工核价原因和输出快照 |

纯计算层可以使用普通对象、只读数组、显式时间参数和 `decimal.js`，并返回可序列化的判别联合结果。

纯计算层禁止：

- 导入 `db`、Prisma runtime client 或调用事务；
- 访问文件、网络、OSS、Webhook、环境变量或全局配置；
- 调用 `fetch`、`process.env`、`Date.now()`、无参数 `new Date()`、`Math.random()`；
- 调用 Server Action、缓存失效、跳转、React 或日志副作用；
- 在计算过程中查询缺失规则；
- 修改传入对象或依赖全局可变状态。

当前时间由编排层显式传入。纯函数优先使用领域 DTO；Prisma 类型如确有必要只能 `import type`。

### 7.2 禁止兜底与 fail closed

计费引擎禁止：

- 规则未命中时回退到默认价、产品基础价、相邻数量档或历史金额；
- 插值、猜价或从冲突规则中自行选择一条；
- 把缺失费率当 `0`；
- 沿用旧报价冒充当前报价；
- 捕获配置错误后继续输出金额。

真值文档若把基础价明确列为可命中的正式规则，按该规则命中不属于 fallback；未命中后再拿基础价补结果仍是禁止的兜底。

以下情况返回结构化人工核价结果，该款不出金额、不参与合计：

- 订单事实合法完整，但报价证据不完整；
- 未精确命中价目或多条规则冲突；
- 命中人工核价触发点；
- 费用仍在真值文档“待定”清单中。

非法或自相矛盾的订单事实返回校验错误；合法但无法报价的事实转人工核价，两者不得混淆。

结果超出 Decimal 或数据库数值边界时返回结构化计算错误并拒绝写入，不得转人工金额绕过数值安全边界。

### 7.3 金额与快照

- 最终财务计算使用 Decimal，不用 JavaScript 浮点数。
- 舍入位置和精度由真值文档明确。
- 报价快照至少包含输入事实、价目版本、命中规则、逐项金额、舍入、总额、价格状态、人工核价原因和计算时间。
- 浏览器报价只是预览；服务端写入时用同一纯函数和事务内规则快照重算。
- 对客加工费、员工工资、供应商应付和内部销售业绩属于不同账本，禁止互相借用价格规则。

## 8. Fixture 与测试要求

任何计费引擎改动必须附带 fixture，放在：

```text
lib/price/__tests__/fixtures/
lib/<domain>/__tests__/fixtures/
```

每个 fixture 至少包含可读名称与真值条款、完整输入事实、价目版本与规则、预期命中规则、逐项金额/舍入/合计、价格状态、校验或人工核价原因，以及快照关键证据。

计费测试至少覆盖：

1. `加工费计费规则.md` 的全部黄金算例；
2. 每个数量边界及前后各一个值；
3. 正反面颜色组合和每面上限；
4. 空价、待定价、自定义事实和人工核价触发点；
5. 无匹配、多规则冲突和缺失输入；
6. Decimal 精度、分项舍入、总额对平和最大值；
7. 规则版本更新不改写历史快照；
8. 浏览器预览与服务端使用同一纯函数；
9. 不同财务账本之间不串价。

计费引擎改动至少运行目标 fixture、全量 Vitest、lint、typecheck 和受影响的 E2E。新增或修改算钱纯函数时，必须将目标文件显式加入 `vitest.config.ts` 的 100% statements、branches、functions、lines 门禁。

通用纪律：

- 行为无关重构不得修改既有测试来取得通过。
- 不通过删除断言、放宽 axe、降低覆盖率或更新截图掩盖失败。
- 测试失败先区分基线失败、环境故障和本次回归。
- fixture 不含生产账号、密码、密钥或真实客户数据。
- Playwright 只能连接专用开发数据库。
- 全量基线必须由被记录的 checkout 在独立端口启动受控服务；不得复用来源、代码版本或生成物不明的已有开发服务器。
- 基线归档须记录 commit、工作树补丁/未跟踪测试清单、migration 与 schema 指纹、Node/pnpm/browser 版本及 `playwright test --list`；只有这些指纹一致的运行才能比较失败集合。
- 依赖或锁文件变更须先在干净 checkout 通过 `pnpm install --frozen-lockfile`，不能用已有 `node_modules` 代替可复现性验证。

常用门禁：

```bash
pnpm lint
pnpm typecheck
pnpm test --run
pnpm test --run --coverage
pnpm test:e2e
pnpm build
git diff --check
```

## 9. Next.js 16 要求

本项目使用当前安装的 Next.js 16，不能套用旧版经验。

修改 App Router 页面/布局、Server/Client Component 边界、Server Actions、Route Handlers、缓存与失效、异步请求 API、metadata、error 或 loading 边界前，必须完整阅读 `node_modules/next/dist/docs/` 中当前版本的对应指南。

发生文档与记忆冲突时，以本地安装版本文档和类型定义为准；不得为绕过类型或弃用提示复制旧版写法。

## 10. 重复、死代码与嵌套

- 先全仓检索静态引用、动态 import、字符串路由、barrel 和外部入口，再判定“无引用”。
- 对可能被外部或动态调用的导出，只登记人工清单，不猜删。
- 重复实现只有在输入、输出、错误和时区等契约等价时才合并。
- 深层条件优先早返回、具名函数或穷尽映射；禁止三元套三元和模板字符串内嵌复杂逻辑。
- 只透传 props 的组件和只包一层的 DOM wrapper，确认无样式、语义、ref、事件或测试契约后才拍平。
- 深层 Prisma `include/select` 先评估权限、事务快照和查询计划；架构/性能建议不与行为修复混改。
