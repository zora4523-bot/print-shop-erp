## 0. 部署架构与前置准备

```
        用户浏览器 / 师傅微信
              │ HTTPS
              ▼
   ┌──────────────────────┐
   │  Nginx (443)          │  反向代理 + TLS
   └──────────┬───────────┘
              │ http://127.0.0.1:3000
              ▼
   ┌──────────────────────┐        ┌─────────────────┐
   │  Next.js (PM2 守护)    │───────▶│ PostgreSQL       │
   │  next start           │        │ (Pigsty 实例)     │
   └──────────┬───────────┘        └─────────────────┘
              │                     ┌─────────────────┐
              ├────────────────────▶│ 阿里云 OSS       │ 设计图/CDR
              │                     └─────────────────┘
              └────────────────────▶ 企业微信 webhook (推送)
```

**上线前你需要准备好这些**（缺一不可，先备齐再开始）：

| 项 | 说明 | 从哪来 |
|---|---|---|
| 一台阿里云 ECS | 建议 2核4G 起，Ubuntu 22.04 / 24.04 | 阿里云控制台 |
| 一个域名 + SSL 证书 | 师傅微信扫码报工需要**公网 HTTPS**域名 | 阿里云域名 + 免费证书 |
| PostgreSQL 16 实例 | 独立 Pigsty 实例（CLAUDE.md 规定） | 已有 / 按 Pigsty 文档部署 |
| 阿里云 OSS bucket + RAM 凭证 | 已在之前配好（bucket `hongbaowebdb`、子账号 `webhongbao`） | 阿里云 OSS/RAM 控制台 |
| 企业微信群机器人 webhook | 上线后老板在系统里填（见 §10） | 企业微信群设置 |

## 1. 服务器基础环境

SSH 登录服务器，装 Node 24 / pnpm / PM2 / Nginx / Git。

```bash
# ── Node.js 24 (项目要求 >=24) ──
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt-get install -y nodejs git nginx

# ── pnpm 10.33.1（锁定版本，与 package.json packageManager 一致）──
sudo npm install -g pnpm@10.33.1

# ── PM2（进程守护）──
sudo npm install -g pm2

# 验证版本
node -v      # 应 >= v24
pnpm -v      # 应 10.33.1
```

## 2. 数据库准备（Pigsty PostgreSQL）

前提：已有一个独立的 Pigsty PostgreSQL 16 实例。做两件事：

**(1) 建库 + 建应用账号**（在 PG 里执行）：

```sql
CREATE DATABASE print_shop_erp;
CREATE USER erp_app WITH PASSWORD '换成强密码';
GRANT ALL PRIVILEGES ON DATABASE print_shop_erp TO erp_app;
-- Prisma 迁移需要建表/扩展权限，MVP 阶段给够即可
```

**(2) 安装扩展**（重要）：迁移文件里用到 `pg_trgm`、`citext`（Postgres 标准 contrib，任何 PG 都有，`migrate deploy` 会自动 `CREATE EXTENSION`）。但 `pg_pinyin`（拼音搜索）、`pg_bigm`、`pg_ivm`（库存看板增量）、`pg_partman` 等**需要 Pigsty 侧预加载**，迁移里对它们做了「装不上就降级」的条件处理——**不装也能上线**，只是拼音搜索等增强功能退化。

> 生产扩展安装照 **`docs/pigsty-production-activation-runbook.md`** 执行。可以先不装，上线后再补。装完在 `/owner/pigsty` 页看红绿灯就绪状态。

## 3. 拉代码、装依赖、构建

```bash
sudo mkdir -p /var/www && cd /var/www
sudo git clone <你的仓库地址> print-shop-erp
sudo chown -R $USER:$USER /var/www/print-shop-erp
cd /var/www/print-shop-erp

# 切到要上线的分支（当前功能分支，或合并到 main 后用 main）
git checkout main    # 或当前分支名

# ⚠️ 装完整依赖（不要用 --prod）：
#    - Next.js 构建需要 devDependencies（typescript 等）
#    - db:seed 用 tsx（devDependency），--prod 会导致 seed 失败
CI=true pnpm install

# 生成 Prisma Client + 构建生产包
pnpm exec prisma generate
pnpm build           # next build，成功输出 "✓ Compiled successfully"
```

## 4. 环境变量 `.env`

在项目根建 `.env`（Next.js 启动时自动读取）。**这是最容易出错的一步**，逐条对照：

```bash
cp .env.example .env
nano .env   # 或 vim
```

| 变量 | 填什么 | 漏填/填错的后果 |
|---|---|---|
| `DATABASE_URL` | `postgresql://erp_app:密码@PG主机:5432/print_shop_erp` | 应用起不来 |
| `AUTH_SECRET` | **生成新的强随机值**（勿沿用 dev） | 会话签名不安全 |
| `AUTH_TRUST_HOST` | `"true"`（Nginx 反代必填） | 登录跳转失败 |
| `CRON_SECRET` | 生成一个随机串 | 7 个定时任务全 503 |
| `APP_PUBLIC_URL` | `https://你的域名`（**无尾斜线**） | **师傅扫码/外协短链变死链** |
| `NOTIFICATION_MOCK_MODE` | **留空**（生产自动真发） | 填 `"true"` → 推送静默 mock，一条不发 |
| `CDR_BUNDLE_MOCK_MODE` | 留空 | 填 `"true"` → CDR 下载返回占位链接 |
| `SEED_ADMIN_USERNAME` | 老板账号，如 `admin` | 见 seed.ts 顶注释 |
| `SEED_ADMIN_PASSWORD` | 老板初始密码（强密码） | 留空则 seed 打印一次随机密码 |
| `OSS_ACCESS_KEY_ID` 等 5 个 | 子账号 `webhongbao` 的凭证 | 留空 → 设计图上传按钮禁用 |
| `SENTRY_DSN` | Sentry 项目 DSN（选填但强烈建议） | 留空 → 无错误监控 |

生成随机密钥：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

> **切勿**把 dev 机的 `AUTH_SECRET` 抄到生产。`.env` 权限设严：`chmod 600 .env`。

## 5. 数据库迁移 + 首次 seed

```bash
# 建表（生产安全命令，不会重置数据）
pnpm exec prisma migrate deploy

# 首次 seed —— ⚠️ 必做，否则没有老板账号、工艺/薪资/推送规则，登不进系统
pnpm db:seed
```

seed 会创建：老板 OWNER 账号、12 条工艺字典、12 条薪资规则、11 条推送事件规则（默认未启用）、系统配置。**seed 不写任何测试数据**，生产库干净。

seed 只在**首次部署**跑。之后更新代码只跑 `migrate deploy`。

## 6. 阿里云 OSS —— 配 CORS（关键，代码改不了）

设计图和 CDR 走**浏览器直传 OSS**（文件不经过服务器）。浏览器跨域 PUT 前会发 CORS 预检，**bucket 不配 CORS 规则就会被浏览器拦死**，签名正常也传不上去。

在**阿里云 OSS 控制台 → bucket `hongbaowebdb` → 数据安全 → 跨域设置 → 创建规则**：

| 字段 | 值 |
|---|---|
| 来源 Origin | `https://你的域名`（split-origin 部署则内网 staff 域也加一行） |
| 允许 Methods | `PUT`, `GET`, `HEAD` |
| 允许 Headers | `*` |
| 暴露 Headers | `ETag` |
| 缓存时间 | `600` |

> RAM 凭证（角色 `erp-oss-upload`、子账号 `webhongbao` 对象读写策略）之前已配好，这里只补 CORS 这一步。

## 8. 用 PM2 启动应用

```bash
# 日志目录
sudo mkdir -p /var/log/print-shop-erp && sudo chown $USER /var/log/print-shop-erp

# 复制并按需改配置（cwd / 端口 / 日志路径）
cp deploy/ecosystem.config.cjs .    # 已在仓库，改 cwd 为 /var/www/print-shop-erp

pm2 start deploy/ecosystem.config.cjs

pm2 startup         # 按提示执行输出的命令，实现开机自启

pm2 status
pm2 logs print-shop-erp
```

此时应用在 `127.0.0.1:3000` 跑起来了（还没对外，下一步 Nginx）。

## 9. Nginx 反向代理 + HTTPS

```bash
# 复制示例配置，改域名和证书路径
sudo cp deploy/nginx.conf.example /etc/nginx/conf.d/print-shop-erp.conf
sudo nano /etc/nginx/conf.d/print-shop-erp.conf   # 改 server_name / ssl 证书路径

sudo nginx -t                # 测试配置
sudo systemctl reload nginx
```

配置里**三个关键点**（示例文件已含，务必保留）：
1. `X-Forwarded-Proto $scheme` —— 否则二维码/短链退化成 localhost 死链、登录 cookie Secure 失效
2. `X-Forwarded-Host $host` —— 二维码/短链域名跟随它
3. `proxy_read_timeout 300s` —— CDR 打包等长任务不被截断

访问 `https://你的域名` 应看到登录页。

## 10. 定时任务（7 个 cron）

系统有 7 个需要每天/每月自动跑的任务。用系统 crontab 逐个打，请求头带 `CRON_SECRET`。

```bash
crontab -e
```

粘贴（把 `$CRON_SECRET` 换成你 `.env` 里的真实值、`erp.example.com` 换成域名）：

```cron
# 师傅日薪结算（每日 00:30）
30 0 * * *   curl -fsS -X POST https://erp.example.com/api/cron/daily-salary       -H "Authorization: Bearer 你的CRON_SECRET"
# 客服周期结算扫描（每日 01:00）
0  1 * * *   curl -fsS -X POST https://erp.example.com/api/cron/cs-settle          -H "Authorization: Bearer 你的CRON_SECRET"
# 客服周期 7 天预警（每日 08:00）
0  8 * * *   curl -fsS -X POST https://erp.example.com/api/cron/cs-period-ending   -H "Authorization: Bearer 你的CRON_SECRET"
# 外协超期推送（每日 08:10）
10 8 * * *   curl -fsS -X POST https://erp.example.com/api/cron/outsource-overdue  -H "Authorization: Bearer 你的CRON_SECRET"
# 承诺交期逾期推送（每日 08:20）
20 8 * * *   curl -fsS -X POST https://erp.example.com/api/cron/order-overdue      -H "Authorization: Bearer 你的CRON_SECRET"
# 时薪工月结（每月 1 号 00:00）
0  0 1 * *   curl -fsS -X POST https://erp.example.com/api/cron/hourly-payroll     -H "Authorization: Bearer 你的CRON_SECRET"
# 销售应收账单生成（每月 1 号 00:40）
40 0 1 * *   curl -fsS -X POST https://erp.example.com/api/cron/generate-bills     -H "Authorization: Bearer 你的CRON_SECRET"
```

> 稳定运行 2-3 周后，可按 `docs/pigsty-production-activation-runbook.md` 把这些切到 Pigsty 的 `pg_cron`（数据库侧调度，少维护一处）。MVP 期先用系统 crontab，出问题好排查。

## 11. 企业微信推送配置（老板在系统里操作）

代码已实现，但**出厂 11 条推送规则默认全是「未启用 + 未绑群」**，老板需要在后台配一次：

1. 企业微信里目标群 → 群设置 → **群机器人 → 添加**，复制它的 webhook URL（形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx`）
2. 系统里用老板账号登录 → **推送配置**（`/owner/notifications`）→ **新建渠道**，粘贴 webhook URL
3. 在事件规则列表里，把要推的事件（如「急单」「师傅日薪」「交期逾期」）**绑定到这个群 + 启用**
4. 点渠道的**测试按钮**，确认企业微信群真收到消息

## 13. 上线 smoke 验证（逐条打勾）

对着走一遍，全绿才算上线成功：

```bash
# 服务器上跑自动化自检（迁移状态 / mock-mode / Puppeteer / 路由）
DEPLOY_SMOKE_BASE_URL=https://erp.example.com pnpm deploy:smoke
```

再手动验证（自动化覆盖不到的）：

- [ ] 浏览器打开 `https://域名`，用老板账号登录成功
- [ ] 建一张工单 → 提交 → 车间主管排产 → **手机微信扫打印单上的任务二维码**，能打开报工页（先登录后回跳）
- [ ] 建单时上传一张设计图，**缩略图正常显示**（验证 OSS CORS 配对了）
- [ ] 详情页点「下载 PDF」，能生成打印 PDF（验证 Puppeteer）
- [ ] 推送配置页点「测试」，企业微信群**真收到消息**（验证 NOTIFICATION_MOCK_MODE 没误设 true）
- [ ] 手动触发一次 `curl -X POST .../api/cron/daily-salary -H "Authorization: Bearer ..."`，返回 200

## 14. 日常运维

**更新部署**（拉新代码上线）：

```bash
cd /var/www/print-shop-erp
git pull
CI=true pnpm install
pnpm exec prisma migrate deploy    # 有新迁移才需要
pnpm build
pm2 reload print-shop-erp          # 平滑重启，不中断
```

**查日志**：`pm2 logs print-shop-erp` / 错误日志 `/var/log/print-shop-erp/error.log`

**紧急踢掉所有会话**（如密钥泄漏、员工离职要立即失效）：换 `.env` 里的 `AUTH_SECRET` → `pm2 reload`。所有人需重新登录。（注意：老板给师傅改密码**不会**立即踢掉其已登录会话，最长 30 天；要即时失效只能换 secret。）

**回滚**：`git checkout <上一个正常的 commit>` → `pnpm install && pnpm build && pm2 reload`。数据库迁移一般不回滚（向前兼容），确需回滚数据结构要谨慎。

## 15. 故障速查

| 现象 | 大概率原因 |
|---|---|
| 登录后又跳回登录页 | `AUTH_TRUST_HOST` 没设 `"true"`，或 Nginx 没转发 `X-Forwarded-Proto` |
| 师傅微信扫码打不开 / 是 localhost 链接 | `APP_PUBLIC_URL` 没配，或 Nginx 漏 `X-Forwarded-Proto` |
| 设计图上传转圈后报错 | OSS bucket **CORS 没配**（§6） |
| 点上传按钮是灰的 | 5 个 `OSS_*` 环境变量没配全 |
| 下载 PDF 报错 | Puppeteer Chrome 没装（§7）或缺系统库 |
| 后台推送日志显示成功但群里没消息 | `NOTIFICATION_MOCK_MODE` 误设 `"true"`，或事件规则没绑群/没启用 |
| 定时任务没跑 | crontab 没配（§10），或 `CRON_SECRET` 不一致导致 401 |
| 每个 cron 返回 503 | `.env` 的 `CRON_SECRET` 留空了 |
| 应用起不来 | `DATABASE_URL` 连不上，看 `pm2 logs` |

---

**最后**：首次上线建议选业务清淡的时段（如周日），上线后盯一两天 `pm2 logs` 和 Sentry。有问题随时按 §14 回滚。
